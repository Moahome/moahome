# 계정별 원장

상태: 2026-11-07 통장·미수·선수금·손익 원천별 조회·기간 누계·원본 상세·다운로드 1차 구현. [공통 API](../../docs/api/accountLedgerApi.md)의 현재 지원 범위와 미구현 범위를 따릅니다. 이번 화면 구성을 전체 원장 요건이나 새 사용자 확정 정책으로 기록하지 않습니다.

## 화면과 조회 상태

조회 조건은 기간 → 계정과목 → 동 → 조회 버튼 순서입니다. 조회 조건의 흰색 카드·테두리·안쪽 여백은 유지하고 PC 카드 폭은 입력과 조회 버튼에 맞춰 오른쪽 빈 공간을 줄입니다. PC 기간 선택은 최대 280px로 제한하고 화면을 채우도록 늘리지 않습니다. 본문 폭이 좁으면 두 열로, 모바일에서는 기간부터 한 열로 배치하고 조회 버튼은 한 줄 전체 너비를 사용합니다.

기준 경로는 `/manage/[propertyId]/accounting/ledger`, 화면 슬라이스는 `screens/accounting/ledger`입니다. 공통 ListHeader·Dropdown·MonthRangePicker·SummaryCard·ListCard·DataTable·ListToolbar·Pagination을 사용합니다. 표·도구 줄·페이지 이동은 흰색 ListCard 안에 배치하고 빈 결과는 공통 StateMessage의 no-results 그림으로 표시합니다. 계정은 코드순, 동은 숫자를 인식하는 이름순이며 현재 사용하지 않는 동도 과거 주소·원천 식별에서는 유지합니다.

기간·계정·동은 조회 버튼으로 적용하고 `startMonth/endMonth/account/building`에 보존합니다. 페이지와 표시 개수는 `page/size`로 보존하며 기본 10개, 10/20/50개입니다. 기간 선택창에서 조회한 기간도 같은 주소에 적용합니다. 손익계산서의 개별 과목 링크는 현재 적용된 기간·동·계정 ID를 원장으로 전달합니다.

표는 계정과목·적요·동·귀속 월·일자·반영액·과목별 기간 누계 순서입니다. 적요는 한 줄로 표시하고 길면 말줄임하며 거래일·부담처 등의 설명줄을 반복하지 않습니다. 자세한 원본 정보는 행 선택으로 기존 상세에서 확인합니다. 401 조회는 날짜 열을 부과일로 표시하고 저장된 부과일(매월 1일)을 사용합니다. 입출금 과목은 거래일, 전체 혼합 조회는 일자이며 귀속 월은 별도 표시합니다. 실제 거래일과 기존 명시적 비용 귀속 월을 서로 덮어쓰지 않습니다. 서버에서 계산한 누계를 그대로 사용하며 최신순 표시·페이지 이동으로 다시 계산하지 않습니다.

요약은 전체·손익 조회에서 수익 반영액·비용 반영액·반영 건수이며 자산·부채 과목을 선택하면 증가 반영액·감소 반영액·반영 건수입니다. 페이지 안의 행만 더하지 않습니다. 요약 카드의 왼쪽 아이콘은 수익·증가 위쪽 화살표, 비용·감소 아래쪽 화살표, 건수 문서로 구분합니다. 모바일 첫 행은 금액 카드 2열, 다음 행의 건수 카드는 전체 너비를 사용합니다. 시작 미설정, 시작 전, 정상 빈 목록, 조회 중과 오류를 분리하며 실패한 자료·이전 조건의 결과를 정상 표로 남기지 않습니다. 지원하지 않는 과목·시작 전·설정 전에는 다운로드를 비활성화합니다.

확인 필요 목록은 전체 과목 기준임을 표시하고 기존 손익 확인 목록으로 연결합니다. 미확인 원천 금액을 반영액에 포함하지 않습니다. 반영 내역·누계는 기초/기말 잔액과 구분합니다.

## 원본 상세와 다운로드

다운로드·미리보기에는 원본 정보 열을 넣지 않습니다. 계정별 내역과 회계 확인 필요 목록 모두 적요·금액·필요한 조회 정보만 출력합니다.

일반관리비는 월·계정별 부과 합계를 한 행으로 표시합니다. 부과 행은 BillingPeriodDetail을 통해 원장 sourceIds에 포함된 항목만 기존 BillingDetail에 전달하며 동·호수의 숫자 오름차순(102동 201호부터)으로 표시합니다. 세대 미납·수납 상세로 보내지 않습니다. 지출·기타 입금은 기존 BankingExpensePage·PaymentDetail을 재사용합니다. PC는 중앙 모달 하나, 모바일은 기존 독립 상세 경로이며 공통 헤더의 실제 뒤로가기로 원장 조건·페이지에 복귀합니다. PC 상세를 닫으면 원장을 다시 조회해 원본 변경을 반영합니다.

공통 ReportDownload로 Excel·PDF·PNG와 실제 파일 미리보기를 제공합니다. 모바일 경로는 `/accounting/ledger/download`이며 새로고침·직접 접근은 공통 자료 재선택 안내를 표시합니다. 열기 시점의 전체 조회 자료를 보관하므로 현재 페이지·표시 개수가 출력 범위를 제한하지 않습니다.

Excel은 계정별 원장과 필요 시 전체 과목의 회계 확인 필요 시트입니다. PDF는 A4 세로이며 사용자 시안의 기간·범위 정보 바, 중앙 요약 카드 3개, 한 줄 거래 표·집계 안내·페이지 번호로 구성합니다. 같은 열·조회 조건·확인 목록을 출력하며 원본 정보 설명줄은 넣지 않습니다. PNG는 같은 PDF를 사용합니다. 기간 누계를 장부 잔액으로 표시하지 않으며 미확인 금액은 별도 목록에 보존합니다.

## 검증

`npm run lint`, `npm run typecheck`, 프로덕션 빌드와 `npm run test:api`를 수행합니다. 변경 흐름은 `npm run test:e2e -- accountLedgerFlow.spec.ts incomeStatementFlow.spec.ts monthlySettlementFlow.spec.ts`로 확인합니다. API의 대상·과목·동·기간·금액·누계·합계·원본 연결 검증, PC/360px, 코드순 고정·날짜 방향·다중 과목·계좌·페이지별 누계, 원본 상세 복귀·주소 복원, 전체 Excel/PDF·다운로드 재선택을 검증합니다. 브라우저 모의 API 검증과 실제 서버·DB 적용은 구분합니다.

부과 상세는 공통 표시를 entities/billing으로 옮겨 부과 화면과 원장에서 재사용합니다. 모바일은 `/accounting/ledger/billing?item=...`에서 같은 원장을 조회해 합계 행을 찾고 새로고침·직접 접근을 지원하며 공통 헤더로 실제 이전 조건에 복귀합니다. 원장과 새 부과 조회의 원본 ID·합계가 다르면 미납 화면이나 다른 금액으로 대체하지 않고 재확인 상태를 표시합니다.


정렬 선택은 공통 ListToolbar의 actions로 표시 개수 옆에 배치합니다. 계정 코드 오름차순은 항상 고정하며 선택지는 최신순(기본)·오래된순만 제공합니다. 같은 과목 안에서만 서버 계산 순서의 방향을 바꾸며 같은 날의 순서와 행별 누계를 보존합니다. `sort=oldest`를 주소에 보존하고 기본 최신순은 생략합니다. 다운로드에도 같은 정렬을 적용합니다.

100·200 원천 연결과 현재 자료 기준의 제약은 공통 API를 따릅니다. 102·201은 날짜 열을 반영일로 구분합니다. 감소액·음수 기간 누계는 Danger 공통 토큰으로 표시하고 Excel·PDF에도 부호를 유지합니다. 통장·이체는 해당 통장·날짜의 기존 거래 목록, 외부 부담은 기존 잔고·정산, 초기 선수금은 기존 인계 정정으로 연결합니다. 미수의 청구는 기존 세대 수납·미납 상세, 회수·수납은 기존 입금 상세를 사용합니다.

목록 조회 중·실패·잘못된 선택지에서 내부 계정/동 UUID를 선택 상자의 문구로 표시하지 않습니다. 공통 Dropdown은 선택 항목이 없으면 placeholder를 표시하며 ID와 선택 조건은 유지해 재조회 후 원래 코드·명칭을 복원합니다. 기본 계정 정의는 Server DefaultAccount를 사용하고 Client에서 UUID→기본 코드 목록을 추측해 복제하지 않습니다.

### 202·계정 다중 선택·101 후속 구현

공통 Dropdown의 multiple 모드로 계정 체크 상태를 유지하며 전체 계정과목은 선택 해제입니다. 조회를 눌러 적용하고 반복 `account` URL에 선택 목록을 보존합니다. 조회 실패 시 내부 ID를 표시하지 않습니다. 101 단독 조회에서는 ListToolbar의 최신순 왼쪽에 전체 계좌 선택을 둡니다. 계정 선택 범위를 바꾸면 계좌 조건을 해제합니다.

101은 기존 누계 셀에 합산 잔액(기초 포함)을 표시하고 계좌 필터가 있으면 해당 계좌만 계산합니다. 별도 통장별 요약 표·설명 문단·통장 열·은행 거래 잔액 열은 표시하지 않습니다. 기존 요약 카드의 도움말은 제목 왼쪽 InfoTooltip이며 모바일 금액 2열·건수 전체 너비를 유지합니다.

미지급 등록은 기존 수동 지출 등록의 지급 상태에서 미지급을 선택합니다. 원장 헤더의 미지급 등록 버튼은 사용자 요청으로 제거했습니다. PAYABLE 원본은 PC 중앙 모달·모바일 독립 상세에서 같은 PayableManager로 조회·지급 연결·연결 해제·등록 취소를 처리합니다. 권한·금액·연결 기준은 [공통 계약](../../docs/api/payableApi.md)을 참조합니다. 저장 중 중복 제출·닫기를 막고 응답 유실 재시도는 같은 요청 ID를 사용합니다.

미지급 독립 등록·상세 페이지는 사용자 요청에 따라 제목과 입력·상세 내용을 흰색 공통 ListCard 안에 배치하고 ListHeader를 사용합니다. PC 입력은 두 열, 모바일은 한 열이며 기존 지출 폼 안의 미지급 입력과 PC 상세 모달은 각 화면의 흰색 카드·모달을 그대로 사용합니다.

다운로드 헤더에는 계산 설명 문구를 표시하지 않습니다. 선택 계정 요약은 코드순 첫 과목과 나머지 개수(예: `801 일반관리비 외 2개`)로 표시하며 Excel 설명과 PDF·PNG 범위 바에서 같은 문구를 사용합니다. 실제 선택 과목과 원장 행은 모두 유지합니다.
