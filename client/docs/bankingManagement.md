# 통장 관리 화면

상태: 2026-10-17 **구현**. 정책·집계 범위·API는 [공통 계약](../../docs/bankingManagement.md), 수납 계산은 [기존 수납 화면](paymentManagement.md)을 참조합니다.

2026-10-23의 은행별 업로드 지원 제어·실제 거래 기간 표시를 구현했습니다. 별도 중복 대사·수동 지출 취소·은행 연결 화면은 미구현이며 새 UI는 정책 확정 후 검토합니다.

## 파일 검토와 선택 처리

- 미리보기는 저장하지 않으며 파일 교체·검증 실패 시 기존 선택과 입력을 보존합니다. 성공한 새 파일만 초안을 교체합니다.
- 전체·입금·출금 FilterTabs와 검색, 기본 10개·10/20/50개 표시 선택과 공통 Pagination을 사용합니다. 통장 거래·업로드 미리보기·지출 내역에 모두 적용하며 표시 개수 변경은 첫 페이지로 이동하고 파일 선택·초안은 보존합니다. 조회 조건과 페이지에 무관하게 파일 전체 선택·초안을 거래 ID로 유지합니다. 헤더 체크는 현재 페이지에만 적용합니다.
- 행 클릭 또는 Enter·Space로 거래 설정 모달을 엽니다. 설정 모달을 닫아도 초안은 보존하며, 닫기 X·Escape·포커스 복귀는 공통 ClientModal에서 처리합니다. 지출 설정이 유효할 때 설정 완료를 사용할 수 있습니다.
- 입금은 자동 매칭, 세대 직접 지정, 기타 용도를 고릅니다. 기타 용도는 항목·선택 메모를 입력하고 명단 일치 자동 수납보다 우선합니다.
- 출금은 지출명, 실제 부담 동, 외부·공통 부담처, 균등/비율/직접 금액, 메모, 규칙 저장 여부를 입력합니다. 부담액 합계와 남은 금액을 표시합니다. 직접 금액으로 전환하면 직전 계산값을 가져와 나머지를 조정할 수 있습니다.
- 선택 전체 중 출금 입력이 잘못되면 해당 출금이 보이는 페이지·필터로 이동해 설정 모달을 열고 처리하지 않습니다. 저장 중 중복 요청·파일 교체를 막고 실패하면 파일·선택·입력을 보존합니다. 업로드 오류와 성공은 공통 Toast를 사용합니다.

## 저장된 내역과 수납 연결

출금의 지출명은 은행 원본 내용으로 자동 입력하고 필요할 때만 변경합니다. 원본 내용은 상세에서 확인합니다. 목록은 입금자·지출명을 방향별로 구분하고 중복된 내용 열을 두지 않습니다. 별도 비용 항목을 입력하지 않습니다. API의 `category` 필드는 지출명 값을 전달하는 기존 호환 키로 유지합니다. 저장한 내용별 설정이 있으면 해당 지출명·나누는 방법을 제안합니다.

거래 행의 입금 상세는 기존 PaymentEditor를 PC 모달·모바일 페이지에서 재사용해 확정·보류·해제·취소·수동 수납 연결을 유지합니다. 출금 상세는 원본과 배분을 조회하며 미분류 출금만 확정할 수 있습니다. 지출 내역은 확정 지출을 월·검색·부담 동으로 조회합니다. 표는 거래일시·지출명·지출액으로 구성하며 입금·출금 전액·매칭·배분 열을 두지 않습니다. 전체 동에서는 관리 동의 부담액을 거래별로 합친 지출액 한 열을, 특정 동에서는 그 동 부담액을 같은 열에 표시합니다. 요약도 합계 한 카드로 표시합니다. 합계는 표시한 동의 부담액을 더하며 외부 부담액을 제외합니다. 관리 동의 부담이 없는 외부 전용 거래는 지출 내역에서 제외합니다. 통장 거래의 출금 필터에는 입금 열·입금 요약을, 입금 필터에는 출금 열·출금 요약을 표시하지 않습니다.

월별 수납은 기존 청구·수납·선입금 계산과 엑셀 다운로드를 재사용합니다. 서버 변경 성공 후 통장 조회·관련 수납·부과 쿼리를 갱신합니다. 실제 은행 잔액과 동별 부담액은 별도 지표입니다.

모바일 상세는 로딩·오류·대상 없음에서도 공통 헤더의 `<`로 같은 관리대상의 목록에 복귀합니다. 본문 목록 버튼을 두지 않습니다. PC 상세는 모달 닫기로 원래 목록·필터·페이지·스크롤을 유지합니다. 신규 화면 그룹 `banking`은 ESLint와 구조 테스트의 SCREEN_GROUPS에 반영합니다.

## 공통 디자인과 시안 반영

요약은 기존 SummaryCard의 compact 표현을 사용합니다. 큰 장식 아이콘은 기존 왼쪽 배치를 유지하고, 설명용 도움말 아이콘(ⓘ)은 제목 글씨 바로 왼쪽에 둡니다(`ⓘ 입금 합계`). 통장 거래는 입금 합계·출금 합계·입출금 차액·확인 필요·최근 은행 확인 잔액을, 지출 내역은 동별 실제 부담액을 표시합니다. 요약 카드의 집계 기준·차액 계산식·확인 건수·최근 확인 시각은 제목 글씨 왼쪽의 공통 InfoTooltip으로 표시하고 카드 아래 상시 설명은 두지 않습니다. PC는 호버·포커스, 모바일은 터치로 도움말을 열며 Escape·바깥 터치로 닫습니다. 전체 통장에서는 최근 은행 확인 잔액 카드를 숨기고 전체 내역은 4개, 입금·출금·취소 내역은 3개 카드가 같은 너비로 본문 전체를 채웁니다. 특정 통장을 선택했을 때만 잔액 카드를 표시하며 전체 내역은 5개, 입금·출금·취소 내역은 4개로 배치합니다. 본문 폭 540px 이하에서는 요약 카드를 한 열로 배치해 금액을 중간에서 나누지 않습니다. 필터·검색·표·Pagination은 기존 관리 목록처럼 하나의 카드 안에 배치하며 PC는 월·검색·상태 또는 동을 한 줄에, 좁은 화면은 한 열로 배치합니다. 숫자와 긴 이름은 컨테이너 밖으로 넘치지 않도록 줄바꿈하고, 표의 가로 스크롤만 해당 영역에 제한합니다.

제공한 5개 이미지는 카드·아이콘·필터·파일 정보·상세 입력 구획의 시각 참고입니다. 현재 공통 색상과 내용·지출명 명칭을 적용합니다. 참고 이미지에 있는 별도 메뉴·컬럼 매핑·업로드 이력·계좌 관리·새 회계 정책을 구현 상태로 기록하지 않습니다.

지출 설정 모달 본문은 Card 배경을 사용합니다. 긴 입력은 본문 내부만 스크롤하고 헤더 닫기와 오른쪽 하단 설정 완료는 유지합니다. 목록 Pagination은 공통 상단 여백 24px과 하단 24px을 맞춰 버튼이 카드 테두리에 붙지 않게 합니다.

통장 거래·업로드 미리보기의 전체 필터는 입금자와 지출명 열을 나누고 해당 방향의 값만 표시합니다. 입금 필터는 입금자, 출금 필터는 지출명만 표시합니다. 2026-10-18 후속 사용자 요청으로 모든 방향의 연결 열은 `처리 내용`으로 통일하고 처리 종류와 연결 대상을 두 줄로 구분합니다. 세대 입금은 `세대 수납`과 동·호수, 기타 입금은 항목명을 붙이지 않고 `기타 입금`만 표시합니다. 배분된 기타 입금은 그 아래 `N개 동 배분`을 표시합니다. 미리보기는 `세대 수납 예정`·`N개 동 배분 예정`으로 저장 전임을 구분하고, 세대 직접 지정·기타 입금 초안도 즉시 반영합니다. 미확정 세대 후보는 `세대 확인 필요`, 미분류 입금은 `입금 분류 필요`로 표시합니다. 기타 입금이라는 이유만으로 외부 부담금 회수나 회수 완료를 표시하지 않습니다.

출금의 처리 내용은 `지출`과 지정한 부담 동의 고유 개수로 표시합니다. 외부로 등록한 101동도 포함하므로 101·102·103동은 `3동 부담`으로 표시합니다. 공동 입금의 배분 동 이름은 목록에 나열하지 않고, 입금 항목명과 구체적인 동 이름·금액·비율은 기존 상세에서 확인합니다. 이 표시 변경은 세대 수납·기타 입금·외부 회수의 저장 분류와 집계 기준을 변경하지 않습니다.

지출 내역 헤더의 엑셀 다운로드는 현재 월·동·검색 조건 전체를 XLSX로 저장하며 페이지와 10/20/50개 표시 선택은 파일 범위를 줄이지 않습니다. 거래일시·지출명·지출액과 합계 행을 내보내고, 표시한 동의 합산액을 화면과 동일하게 사용합니다. 문서 구성과 금액·문자열 셀은 [공통 엑셀 서식](excelReports.md)을 따릅니다. 지출 합계 아이콘은 사용자 요청에 따라 옅은 노란 배경과 Warning 아이콘을 사용하며 지출 처리 상태를 뜻하지 않습니다.

표는 전체·입금·출금·지출 내역에서 헤더와 본문을 모두 가운데 정렬합니다. 마지막 행과 페이지네이션의 경계는 행 테두리 1px만 사용하고 중복 선을 두지 않습니다. 동 선택·초안·확정 상세는 이름의 숫자 오름차순으로 표시하며 API 원본과 저장 이력의 배열은 수정하지 않습니다.

지출 상세는 시안 2번의 아이콘·카드 구성을 사용합니다. 상단에 지출명과 확정 상태를, 아래 세 카드에 출금액·거래 후 잔액·거래일시를 한 번씩 표시합니다. 원본 내용은 지출명과 다를 때만 보조 문구로 표시하며 시안의 가상 분류·설명은 생성하지 않습니다. 하단은 동별 금액·비율과 저장한 메모를 표시합니다. 모바일 카드는 흰색 Card 배경을 사용하고 출금액 카드에만 옅은 Primary 강조를 적용해 회색·색상 배경이 중첩되지 않게 합니다. PC 중앙 모달과 모바일 독립 상세 경로는 같은 내용을 사용합니다.

## 동별 잔고·정산

2026-10-18 후속 요청으로 동별 잔고의 조회 조건은 제목 아래, 요약 카드 위의 흰색 카드로 묶습니다. `조회 조건` 제목과 기존 월·통장 입력을 표시하며 선택 즉시 반영합니다. PC에서는 월·통장 입력을 1:2 비율로 늘려 카드의 가로폭을 채우고 모바일에서는 한 줄씩 배치합니다. 통장 거래·지출 내역의 기존 필터는 테이블 위 위치와 검색창 오른쪽의 통장 선택을 유지합니다. 요약 카드의 도움말은 배경 없는 14px 정보 아이콘으로 표시해 제목 줄 높이와 금액 정렬을 유지합니다.

2026-10-18 사용자 요청으로 모바일 조회 월은 본문 가로 전체 너비를 사용합니다. 그래프·기준 잔고 확인/수정·잔고 차이 내역·외부 부담금 정산·입금 귀속 동 확인은 모바일에서 모달 대신 독립 페이지로 엽니다. `panel`은 `chart`, `opening`, `difference`, `settlement`, `assignment`이며 조회 월은 `month`, 조회 통장은 `account`, 정산·귀속 대상 ID는 `target` 쿼리로 전달합니다. 그래프는 목록의 동 검색·상태 필터도 전달합니다. PC는 기존 모달을 유지하고 같은 조회·입력·저장 내용을 재사용합니다. 모바일은 직접 진입·새로고침을 지원하고 로딩·오류·대상 없음에서도 공통 헤더의 `<`로 조회 월·조회 통장을 유지한 목록에 복귀합니다. 저장 성공 시에도 해당 월·통장 목록으로 돌아갑니다. 본문 목록·닫기 버튼은 추가하지 않습니다.

새 초기 설정에서 인계·확정한 각 통장별 잔액은 새 은행 거래가 없을 때 장부 기준일 마감 금액으로 표시합니다. 기준일 이후 잔고 미제공·순서 미확인 거래를 이전 잔액으로 숨기지 않으며 기준일 이전 월에 이 잔액을 소급 표시하지 않습니다.

상단은 은행 확인 잔고·동별 잔고 합계·잔고 비교 차이·관리 동 수 네 카드로 고정합니다. 은행 잔고는 원본 기준일시를 표시하며 실시간 잔고라고 하지 않습니다. 미설정 또는 거래 순서가 불명확한 값은 0원으로 표시하지 않습니다.

2026-10-18 후속 사용자 지정으로 동별 잔고 합계 아이콘은 Warning, 잔고 비교 차이 아이콘은 Success 색상을 사용합니다. 잔고 비교 차이가 음수이면 아이콘 색상과 별개로 금액과 원 단위를 Danger로 표시합니다. 모바일에서는 상단 작업 버튼과 요약 카드를 각각 1열로 배치합니다.

후속 사용자 요청으로 통장 잔액·동별 잔고 합계·잔고 비교 차이 카드의 제목 옆에 도움말을 제공합니다. 은행 확인값은 마지막 확인 시점의 기록, 계산 잔액은 시작 잔고와 등록 입출금의 계산값으로 구분해 설명합니다. 동별 합계는 선택 통장 또는 전체 조회 범위를 명시하고 미배분 입금은 포함하지 않음을 안내합니다. 자료가 없을 때는 `은행 확인 자료 없음`과 `잔액이 0원이라는 뜻은 아닙니다.`를 사용합니다. 기존 통장별 잔액 목록과 공통 InfoTooltip을 재사용해 PC 호버·포커스, 모바일 터치로 버튼 아래에 열고 Escape·바깥 터치·포커스 이탈로 닫습니다. 도움말은 body 포털에서 화면 좌표로 표시해 카드의 스크롤·잘라내기 경계에 가려지지 않게 하며 화면 가로 폭 안으로 제한합니다.

중앙은 동 이름·기초 잔고·월 입금·월 지출·월말 잔고와 행 클릭으로 구성합니다. 동 검색, 이름·잔고 정렬, 미설정·부족 상태 필터, 10/20/50개 표시와 선택 동 합계를 제공합니다. 헤더의 `다운로드`는 아래 동별 입출금 명세를 Excel·PDF·이미지로 제공합니다. 동 추가는 기존 동 관리에서 처리합니다. 비활성 동은 보관 상태를 표시하고 잔고 이력을 유지합니다.

시작 잔고 설정은 PC 공통 ClientModal·모바일 독립 페이지에서 기준일 마감 보유금을 현재 미설정 동마다 입력합니다. 동은 이름순의 검색 가능한 드롭다운으로 선택하며, 선택을 바꿔도 동별 입력 초안을 유지합니다. 입력 완료 동 수를 표시하고 미입력 동이 있으면 해당 동을 선택해 안내합니다. 입력 폼은 동 수에 따라 늘리지 않으며 확인 버튼은 상세 하단에 유지합니다. 저장 후에는 `기준 잔고 확인`에서 조회하고 `기준 잔고 수정`을 눌러 편집합니다. 편집에서는 날짜 선택과 등록된 동별 마감 잔고 수정을 허용하며 `변경 저장`으로 함께 정정합니다. 취소하면 이전 값을 복원합니다. 기준일을 바꾸면 해당 날짜의 마감 잔고를 확인하도록 안내하고 이전 값은 서버 이력에 보관합니다. 세대 미납·선납 인계와 구분하며 입력 실패는 현재 상세와 입력을 유지합니다.

원장은 PC 중앙 모달, 모바일 독립 상세와 공통 헤더 뒤로가기를 사용합니다. 원장 영역은 흰 Card 배경·Border 테두리로 바깥 Background와 구분하고 월말 잔고 카드는 옅은 Primary로 강조합니다. 음수 잔고는 Danger를 우선하며 거래 날짜는 한 줄, 시간은 그 아래에 표시합니다. 전체·입금·출금 필터와 입금자·지출명 검색은 표시만 제한하며 입금 필터는 입금자·입금, 출금 필터는 지출명·출금 열만 표시합니다. 출금액은 음수로 표시하고 누적 잔고는 전체 거래 순서로 계산합니다. 행 선택 시 기존 입금 처리·지출 상세를 PC 모달 또는 모바일 경로로 열고 모바일은 원래 동·조회 월의 원장으로 돌아갑니다. 입금 처리 후 잔고 조회를 무효화합니다. 상세는 월 기초·입금·지출·말 잔고와 해당 동의 실제 이동·누적 잔고를 표시합니다. 기준일 이전 월도 역산하며 상단에서 기준일과 계산 방향을 안내합니다. 기준 잔고 확인 버튼은 저장 후에도 유지하고 저장 당시 동별 금액을 검색해 확인합니다. 큰 금액은 줄바꿈하고 표 가로 스크롤은 표 내부로 제한합니다.

동별 목록은 확인·화살표 열 없이 행을 눌러 상세를 엽니다. 하단 두 카드는 같은 줄에서 높이를 맞춥니다. 하단은 조회 동의 월 입금·출금 비중을 보여주며 가운데 월 입출금 차액(입금 합계 − 출금 합계)과 음수 출금액을 표시하는 원형 그래프(클릭 시 동 검색·선택과 동별 금액 표가 있는 PC 모달·모바일 페이지), 잔고 차이 확인, 외부 부담금 목록입니다. 고정 1/2·1/4 열이나 음수 잔고를 숨기는 비율 도넛은 만들지 않습니다. 외부 부담금 행을 누르면 회수 이력과 검색 가능한 선택 입력으로 실제 확정 기타 입금 잔여액을 확인해 부분 연결할 수 있습니다. 실패 재시도는 입력과 요청 ID를 유지하고 저장 중 중복 처리를 차단합니다. PC 모달은 저장 중 닫기도 제한합니다.

기존 HOUSEHOLD 확정 은행 수납은 연결 세대의 동을 자동 기록해 원장·합계에 반영합니다. 귀속 동이 남아 있지 않고 세대 연결·동 정보도 없는 예외만 확인 목록에 표시합니다. 연결 세대 동 필터(전체·등록 동·세대 미확인)와 입금자·연결 세대 검색을 제공합니다. 이미 기록한 귀속 동은 세대 이동 뒤에도 그대로 사용합니다. 미분류 은행 거래·미귀속 기타 입금·외부 대납금을 차이 확인 상세(PC 모달·모바일 페이지)에서 구분합니다. 잔고 차이 확인 카드는 별도 하단 버튼 없이 카드 전체를 클릭해 상세를 열며 키보드 Enter·Space도 지원합니다. 차액을 특정 동에 배분하거나 대사 완료로 자동 표시하지 않습니다. 계산·취소 반영·API는 [공통 계약](../../docs/bankingManagement.md#동별-잔고외부-회수-api)을 참조합니다.

통장 화면은 공통 Pretendard 글꼴을 사용하고 모달 제목·본문·금액의 굵기를 구분합니다. 차액·원장의 음수 잔고는 Danger 토큰으로 표시합니다.

외부 부담금 상세 하단의 `정산에서 제외`는 입금 선택 없이 실행할 수 있으며 하단 오른쪽에 정렬합니다. 입금 연결 버튼이 함께 표시되면 두 버튼을 12px 간격으로 오른쪽에 모읍니다. 외부 부담금 목록은 거래일 최신순으로 정렬한 뒤 페이지를 나누며 검색·정산 대상 필터에도 같은 순서를 유지합니다. 기본 목록은 정산 대상만 표시하며 `정산에서 제외` 필터로 제외 내역을 열고 `정산 대상으로 복원`할 수 있습니다. 제외된 내역은 입금 연결 폼을 숨기고 원본·회수 기록을 보존한다는 안내를 표시합니다. 제외·복원 실패는 상세와 입력·요청 UUID를 유지하고 저장 중 다른 처리를 차단합니다. PC 모달은 저장 중 닫기도 제한합니다. 미회수 합계에서만 제외하며 은행−동별 잔고 차이는 변경하지 않습니다.

## 통장 선택 삭제와 공동 입금 배분

통장 거래 목록의 `편집`을 누르면 체크박스와 `선택 삭제`를 표시합니다. 행 클릭도 선택을 토글하며 상세를 열지 않습니다. 현재 페이지 전체 선택을 지원하고 월·검색·방향·상태·페이지 변경 시 선택을 해제합니다. 확인 모달에는 거래일·내용·방향·금액과 연결 수납·잔고 반영 취소를 설명합니다. 실패 시 선택과 확인창을 유지하고 성공하면 통장·수납·청구·잔고를 다시 조회합니다. 삭제 버튼은 행·상세에 중복 추가하지 않습니다.

업로드 입금 용도의 `동별 입금 · 직접 배분`에서 기존 출금 배분 편집기를 재사용합니다. 입력은 입금 항목·나누는 방법·배분 동·금액 또는 비율·메모로 표시하며 외부 부담처·지출 설정 자동 기억은 표시하지 않습니다. 저장된 확정 기타 입금 상세에도 `동별 입금 배분`을 제공하고 확정 후에는 동별 몫을 조회합니다. PC 상세 모달·모바일 상세 경로·동별 원장에서 연 상세가 같은 배분 블록을 사용합니다. PaymentDetail은 화면에서 전달하는 보충 영역 슬롯만 제공하며 다른 widget 내부를 참조하지 않습니다.


## 수동 입금 진입·취소 내역 복구 (2026-10-18)

사용자 요청으로 통장 거래 헤더에 `수동 입금 등록`을 복구했습니다. 수동 입금 폼·요청 UUID·수납 API를 재사용하며 후속 용도별 입력은 아래 기준을 적용합니다. PC는 공통 ClientModal, 모바일은 `/banking/manual`의 독립 페이지이며 공통 헤더의 `<`로 복귀합니다. 저장 후 같은 입금의 처리 상세를 열고 조회 월·검색·처리 상태를 초기화합니다. 조회 월은 주소에도 반영해 다른 월에서 등록한 뒤 새로고침해도 입력한 입금월을 유지합니다.

은행 원본에 연결되지 않은 수동 입금도 거래 목록에서 표시하며 `등록 방식`은 `수동 입금 / 엑셀`로 구분합니다. 엑셀 원본을 기존 수동 수납에 연결하면 미연결 수동 행을 제거하고 원본 행 하나만 표시합니다. 후속 사용자 요청에 따라 입금 합계·입출금 차액에는 취소되지 않은 수동 입금도 포함합니다. 취소 이력 행은 합계에서 제외하고 은행에 연결된 수동 입금은 원본만 한 번 집계합니다. 후속 수동 지출은 출금 합계에 반영합니다. 은행 확인 잔액에는 수동 입출금을 반영하지 않습니다. 이는 기존 현금 집계 정책을 유지하는 화면 조합입니다.

`전체 / 입금 / 출금 / 취소 내역` 탭에서 취소 이력을 별도로 조회합니다. 취소 건을 `확인 필요`로 표시하지 않으며 취소 상태·사유·기존 세대를 보존합니다. 수동 입금은 미확정·보류·확정·취소 상태 모두 목록 편집에서 선택 삭제할 수 있습니다. 확정 건도 체크박스를 활성화하고 서버가 수납·충당 취소와 삭제를 함께 처리합니다. 은행에 연결된 취소 이력은 은행 원본 삭제와 구분합니다. 은행 거래와 수동 내역의 혼합 선택은 한 요청으로 처리하고 실패하면 선택·확인창을 유지합니다. 헤더의 수동 등록·엑셀 버튼은 12px 간격으로 배치합니다.

중복 확인의 실제 기준과 제한은 [기존 수납 계약](../../docs/paymentApi.md#은행-파일추천중복)을 따릅니다. 같은 세대라는 이유만으로 별도의 실제 입금을 자동 삭제·병합하지 않습니다.

삭제 확인 모달은 2026-10-18 사용자 제공 시안을 따릅니다. 제목은 `거래를 삭제할까요?`, 거래별 연한 회색 요약 박스에는 입금자·입출금·금액과 실제 거래 날짜·시간을 표시합니다. 시간 없는 수동 입금에 시간을 만들어 표시하지 않습니다. 안내는 `연결된 수납은 취소되며, 처리 이력은 보관됩니다.`로 간결하게 표시하고 오른쪽 아래에 외곽선 취소·연한 빨강 배경과 빨간 글자의 삭제 버튼을 12px 간격으로 둡니다. 같은 날 후속 사용자 요청의 전체 버튼 색상 완화 기준을 적용합니다. 여러 건은 같은 요약 박스를 반복하며 모달 내부 스크롤을 허용합니다.

기준 잔고 버튼은 후속 사용자 선택 2안에 따라 아래 상시 설명을 제거하고 버튼 안쪽 왼편에 정보 아이콘을 표시합니다. 후속 요청으로 이 버튼은 아이콘·글자 영역 모두 호버 배경 변화를 없애고 하나의 연한 배경을 유지합니다. 버튼 영역에 마우스를 올리거나 키보드 포커스를 두면 설명을 표시하며 모바일은 정보 아이콘을 터치해 엽니다. 본문 버튼은 기존 기준 잔고 확인·설정 동작을 유지하며 도움말 터치로 상세 페이지를 열지 않습니다. 도움말은 바깥 터치·Escape·포커스 이탈로 닫습니다. 등록 전에는 `기준일의 동별 보유금을 등록합니다.`, 등록 후에는 `등록한 동별 기준 잔고를 확인·수정합니다.`와 `은행 실시간 잔액 조회는 아닙니다.`를 표시합니다. 도움말 본문은 사용자 제공 B안의 파란 정보 아이콘·세로 구분선과 제목·설명 배치를 사용하며, 후속 요청으로 배경은 흰 Card로 표시합니다. PC·모바일 모두 버튼 왼쪽 끝에 맞춰 열고 화면 오른쪽에 남은 공간 안에서 폭을 줄여 표시합니다. 연한 버튼 색상은 [Client 공통 디자인 규칙](../AGENTS.md#4-ui--design)을 유지합니다.


## 다중 통장 화면 (2026-10-18)

[다중 통장 계약](../../docs/bankingManagement.md#다중-통장내부-이체-api-2026-10-18)을 사용합니다. 설정의 관리계좌에서 목록·통장 추가·수정·기본 지정·삭제를 제공합니다. 수정은 공통 Button의 text·success 색상, 삭제는 text·danger 색상을 사용하며 배경과 테두리 없이 글씨만 표시합니다. 삭제 확인·취소·실패 안내는 기존 공통 UnitDeleteConfirmation 모달을 재사용합니다. 삭제 성공한 CLOSED 통장은 설정 목록에서 숨기고 다시 열어도 표시하지 않습니다. 기본 계좌에는 삭제 행동을 표시하지 않습니다. 삭제는 기존 사용 종료 API를 사용하여 신규 입력을 막고 과거 내역을 보존합니다. 계좌 관리는 PC에서 기존 모달, 모바일에서 `/manage/{propertyId}/settings/accounts` 독립 페이지를 사용합니다. 페이지 제목 아래 계좌 목록·안내·추가·수정 본문은 공통 ListCard의 흰 Card 배경·Border 테두리·내부 여백으로 감싸 바깥 Background와 구분합니다. 모바일의 추가·수정도 같은 페이지 안에서 처리하며 삭제 확인은 기존 공통 모달을 유지합니다. 직접 접근·새로고침·로딩·오류에서도 공통 헤더의 `<`는 같은 관리대상의 `/settings`로 돌아갑니다. 본문에 닫기·목록 복귀 버튼을 두지 않습니다. 모달을 닫거나 페이지에서 이탈하면 원문 캐시는 폐기합니다.

통장 거래·지출 내역에는 전체/특정 통장 선택을 제공하고 전체 목록에 실제 통장을 표시합니다. 업로드는 사용 중인 통장을 선택하고 통장 변경 시 파일 미리보기·선택·분류 초안을 함께 초기화합니다. 수동 입금도 실제 입금 통장을 선택합니다. 월별 세대 수납은 전체 통장을 합산합니다. 거래 화면은 전체 통장의 서로 다른 잔액을 하나의 누적 잔액처럼 표시하지 않고 특정 통장을 선택했을 때 마지막 원본의 잔액과 시각을 확인합니다.

업로드 거래 설정의 `관리 통장 간 이체`는 수납·지출 편집을 대신해 원본만 저장합니다. 저장 거래 상세에서 다른 통장의 같은 금액·반대 방향 이체 대기를 직접 선택해 연결하거나 기존 연결을 해제합니다. PC는 공통 모달, 모바일은 기존 `/banking/transactions/{id}` 독립 상세와 공통 헤더 뒤로가기를 사용합니다. 실패 시 입력과 요청 ID를 유지합니다.

동별 잔고는 선택 통장 안의 보유금이며 전체 조회는 통장별 계산 결과를 합산합니다. 은행 카드 아래에는 조회 범위의 통장별 잔액·확인 시점을 표시합니다. 확인값과 계산값이 모두 없는 통장이 있으면 전체 합계는 `은행 확인 자료 없음`으로 표시합니다. 추가 통장 잔액과 동별 보유금을 자동으로 같게 만들지 않습니다. 외부 회수 후보는 기존 같은 통장 제한에 맞게 필터링합니다.

2026-10-18 사용자 제공 추천안에 따라 `통장별 확인 잔액`은 제목 옆 정보 버튼·구분선과 은행 로고·마스킹 계좌명·짧은 확인 시각·Primary 색상 잔액으로 표시합니다. 제목 옆에는 배경 없는 14px 정보 아이콘을 6px 간격으로 붙입니다. 상시 설명은 정보 버튼의 도움말로 옮기고 호버·키보드 포커스·터치로 열며 Escape·바깥 터치·포커스 이탈로 닫습니다. 후속 사용자 요청으로 도움말은 항상 아이콘 아래에 열고, 기준 잔고 확인 도움말과 같은 흰 배경·파란 정보 아이콘·세로 구분선·제목을 사용합니다. 문구는 `확인값 또는 계산 잔액입니다.`와 `실시간 조회가 아닙니다.`로 줄입니다. 구현상 확인 시각의 원문은 time 요소에 유지하고 화면은 `10.15 14:12 확인`으로 줄이며, 날짜만 제공되면 시간을 만들지 않습니다. 미확인 잔액은 `은행 확인 자료 없음`으로 표시하고 사용 종료 표시를 유지합니다. 좁은 화면은 잔액을 계좌 정보 아래에 배치하며 도움말은 화면 폭 안에서 표시합니다.

통장 거래의 `최근 은행 확인 잔액` 카드 제목 옆에도 같은 도움말을 제공합니다. 전체 통장은 통장 선택 안내, 선택 통장은 은행 파일의 마지막 거래 후 잔액과 수동 입금·실시간 조회 미반영을 도움말에서 설명합니다. 2026-10-23 후속 요청으로 실제 확인 시각도 도움말 안에 표시하고 카드 아래에는 설명을 반복하지 않습니다. 잔액 자료가 없으면 `은행 확인 자료 없음`, 같은 날 거래 순서를 구분할 수 없으면 `거래 순서 미확인`으로 표시합니다.

## 잘못 등록된 외부 부담금 거래 삭제 (2026-10-18)

후속 사용자 요청으로 외부 부담금 상세 푸터에 `거래 삭제`를 제공합니다. 같은 상세 안에서 원본 거래일·전체 출금액·외부 부담액과 연결된 모든 동별 지출의 제거 범위를 확인한 뒤 기존 선택 삭제 API를 호출합니다. PC는 모달, 모바일은 기존 독립 상세 경로 안에서 확인하며 목록에 삭제 버튼을 중복 추가하지 않습니다. 실패하면 확인 내용과 오류를 유지합니다. 저장 중 중복 실행을 막고 PC 모달은 닫기도 막습니다. 성공하면 관련 통장·수납·잔고·관리비 조회를 갱신하고 기존 월·통장 범위로 복귀합니다. 실제 거래를 유지하는 `정산에서 제외` 동작은 그대로 둡니다.

## 수동 입금 용도와 동별 직접 입금 (2026-10-18)

수동 폼은 먼저 `세대 관리비 직접 지정 / 외부 분담금·수리비 등 기타 입금 / 동별 입금 · 직접 배분` 중 용도를 선택합니다. 처음 열면 용도 미선택이며 세대를 표시하지 않습니다. 특정 세대에서 진입한 기존 흐름은 세대 용도를 미리 선택합니다. 자동 매칭은 업로드에만 제공합니다. 세대 용도에서만 세대 검색·대표 주민 읽기 전용 입력을 표시합니다. 다른 용도는 세대 없이 입금자·입금 항목·선택 메모를 입력합니다.

동별 입금은 entities/banking의 AllocationEditor와 원 단위 계산을 업로드·출금·수동에서 공유합니다. 선택한 한 동에 전액 또는 여러 동에 균등·비율·금액으로 나눕니다. 2동 100만 원·3동 50만 원처럼 서로 다른 몫을 지정할 수 있습니다. 원 미만 나머지·합계 불일치는 등록을 막고 직접 금액 조정을 안내합니다. 동 수·이름·ID는 현재 원장의 buildings로 구성합니다. 저장 후 상세와 새로고침한 목록에 기타 항목 또는 동별 입금·배분 동 개수를 표시하며 수동 출처를 유지합니다. 저장 실패는 폼·금액·배분·요청 UUID를 유지합니다. PC 모달은 입력 본문만 스크롤하고 제목·닫기·등록 동작을 계속 표시합니다.

거래 설정 모달의 이체 선택·설명은 본문 좌우 여백과 맞추며 설명은 체크박스 글자 위치에 맞춰 들여 씁니다. PC는 24px, 모바일은 16px 좌우 여백과 일정한 줄 간격을 사용합니다. 배경·공통 푸터 색상은 이 변경 범위에 포함하지 않습니다. 저장·잔고 반영 기준은 [수동 API](../../docs/paymentApi.md#수동-등록확정취소)를 참조합니다.


### 통장 선택과 기존 잔고 보존 (2026-10-18 후속)

기존 `기준 잔고 확인` 화면 안에서 통장 선택 → 동 선택 → 해당 통장 안의 동별 기준 잔고를 표시합니다. 이미 확정한 값은 읽기 상태로 표시하고 `기준 잔고 수정`으로 정정합니다. 통장 소속만 미정인 기존 금액은 서버의 legacyOpening 날짜·금액을 초안에 표시하고 확인 안내 후 `확정`을 받습니다. 저장 실패·통장 전환 시 금액과 재시도 UUID를 유지합니다. 통장별/동별 탭이나 별도 기초 잔액 등록 버튼은 두지 않습니다. 운영 중 확인 기록의 진입점은 아래 2026-10-24 후속 구현에서 별도로 다룹니다.

조회 월·조회 통장은 공통 MonthPicker·Dropdown을 재사용하고 입력 높이는 50px로 맞춥니다. 후속 사용자 요청으로 위쪽 `조회 월`·`조회 통장` 글씨는 숨기고 접근 가능한 이름은 유지합니다. 통장 거래·지출 내역에서는 통장 선택을 검색창 바로 오른쪽의 같은 필터 줄에 두며, 잔고 화면의 조회 통장 위치는 유지합니다. `선택 통장 거래 보기` 버튼은 표시하지 않습니다. 선택 통장은 서버 조회와 동별 목록·원장·정산·엑셀 출력 전체에 적용하고 URL의 account로 새로고침·모바일 복귀를 유지합니다.

통장 선택·확인 잔액 목록은 서버가 반환한 최초 등록 순서를 유지하며 이름·기본 지정으로 다시 정렬하지 않습니다. 월별 수납은 후속 철회 요청에 따라 통장 조회·통장별 추가 열·통장별 상세·엑셀을 제공하지 않고 기존 전체 수납 합산을 유지합니다.

PC 모달은 제목·하단 행동을 고정하고 본문만 스크롤합니다. 모바일은 같은 섹션을 독립 페이지에 배치합니다. 후속 사용자 정정으로 입력·드롭다운·날짜 선택 배경은 모두 흰 Card로 유지합니다. 본문·입력 글자 `#1E293B`, placeholder `#94A3B8`, 선택칩 테두리 `#93C5FD`는 공통 토큰을 사용합니다. 동 선택칩과 부담처 추가 버튼은 높이 50px·글자 16px·안쪽 여백 10px/18px로 맞춥니다. 모바일의 부담처 추가 버튼은 동 선택칩 다음 줄에서 가로 전체 너비를 사용합니다. 배분 행은 삭제 버튼의 40px 자리를 모든 행에 확보해 동별 행과 외부 부담처 행의 입력·결과 열을 맞춥니다. 금액·비율 입력 폭은 PC 120px, 모바일 72px로 같게 하고 숫자는 오른쪽 정렬합니다. 수동 지출·수동 입금의 제출 버튼 이름은 `등록`으로 통일하며 기존 공통 Button의 연한 Primary 배경·Primary 글자 규칙을 사용합니다. 진한 채움 변형은 사용하지 않습니다.

## 사용 종료 통장 표시 구현 (2026-10-23 후속)

표시 정책과 응답은 [공통 계약](../../docs/bankingManagement.md#사용-종료-통장-조회-계약-2026-10-23-후속)을 따릅니다. 거래·지출은 조회 월로 accounts를 걸러 목록과 필터에 같은 집합을 사용합니다. 숨겨진 통장 선택은 전체로 복원하고 URL의 account를 제거합니다. 월 변경은 선택·페이지를 초기화하며 이전 URL 월을 다시 덮어쓰지 않습니다. 잔고 화면은 서버의 accounts와 accountId를 그대로 따라 미정산 예외를 유지합니다. 기간 메타데이터가 없는 이전 응답은 과거 통장을 임의로 숨기지 않습니다. 신규 등록·업로드는 기존 ACTIVE 제한을 유지합니다.


수동 지출의 등록 버튼은 통장·출금일·양수 금액·지출명·부담처·배분 합계가 모두 유효할 때만 활성화합니다. 초과 배분, 미배분 금액, 비율 합계 오류와 원 미만 잔액이 있으면 비활성화하며 제출 시에도 같은 계산으로 검증합니다. 배분 합계는 정상일 때 Success, 미완료는 Warning, 출금액 초과는 Danger로 표시합니다. 초과한 잔액은 음수 `남은 금액` 대신 양수 `초과 금액`으로 표시하며 실제 차액 계산은 유지합니다.


## 은행 잔액 직접 확인 화면 (2026-10-24)

상태: **구현**. 업무 판단은 [도메인 규칙](../../docs/domainRules.md#운영-중-은행-잔액-직접-확인-2026-10-24), 요청·응답은 [공통 API](../../docs/bankingManagement.md#은행-잔액-직접-확인-api-2026-10-24)를 따릅니다.

후속 사용자 시안에 따라 통장별 잔액 행은 은행 로고·계좌 식별·확인시점과 출처·금액·`⋮` 메뉴로 구성합니다. 후속 사용자 요청으로 상세 화살표는 제거하고 행 클릭으로 통장 상세를 엽니다. 은행명·별칭·마스킹 번호·실제 확인 방법은 실제 자료만 표시하며 날짜를 양쪽에 중복 표시하지 않습니다. 금액은 기존 Primary 토큰을 사용합니다. 후속 사용자 요청으로 통장 행 호버 시 배경색을 채우지 않고 흰 Card 배경을 유지하며 키보드 포커스 표시는 보존합니다. `⋮` 버튼은 흰 Card 배경이며 메뉴에 `은행 잔액 직접 확인`·`확인 이력 보기`를 둡니다. 종료 통장은 이력만 제공합니다. 열린 메뉴는 다음 행의 버튼보다 앞에 표시하고 포인터·키보드·바깥 클릭·Escape 및 180ms 열림/닫힘 전환과 reduced-motion을 지원합니다. 행의 기존 통장 상세 열기와 메뉴는 중첩 버튼 없이 분리합니다.

PC 입력·이력은 공통 ClientModal로 뷰포트 가로·세로 중앙에 표시합니다. 공통 스타일이 fixed·inset 0·margin auto를 보장하고 본문만 내부 스크롤하며 저장 중 busy와 닫기 비활성화를 적용합니다. 모바일은 `/banking/balances/details/check`·`/banking/balances/details/checks` 독립 페이지로 열고 공통 헤더 뒤로가기로 조회 월·통장 조건을 유지해 복귀합니다. target은 확인할 통장 ID이며 실제 조회 범위 밖의 통장은 대상 없음으로 표시합니다.

입력은 대상 통장, 실제 잔액, 공통 CalendarPicker의 확인 날짜, 한국시간의 확인 시각(초), 확인 방법, 선택 메모입니다. 날짜·시각은 실제 확인시점으로 입력하고 과거 조회 월말로 자동 변환하지 않습니다. 안내는 `직접 확인한 잔액은 입출금 거래나 동별 보유금을 변경하지 않고 확인 이력으로 저장됩니다.`입니다. 실패하면 본문·요청 UUID를 유지하며 같은 본문 재시도는 중복 생성하지 않습니다.

확인 이력은 실제 확인시점·방법·금액·기록 관리자 표시명·시스템 기록시점·메모·취소 여부와 사유를 표시합니다. 후속 사용자 시안에 따라 PC는 넓은 중앙 모달에서 금액·확인 기준시각·기록자·시스템 기록시각·상태를 나란히 표시하고 모바일은 같은 항목을 세로로 배치합니다. 상단 가운데에 기본 5개·5/10/20/50개 표시 선택을, 오른쪽에 상태·정렬 필터를 두며 하단에는 공통 Pagination을 표시합니다. 취소한 기록은 사유·취소 처리자·시각을 옅은 Danger 영역에 표시합니다. 유효 기록의 메뉴에서 취소 입력을 열고 취소 사유 입력·취소 요청을 제공합니다. 취소 실패는 사유·요청 UUID를 유지하며 취소한 원문도 조회할 수 있습니다. 성공 뒤 잔고·해당 통장 이력을 갱신합니다.

통장별 실제 확인값과 계산값을 구분하고 순서 불명확을 계산값으로 가리지 않습니다. 전체가 계산값이면 `통장 계산 잔액 합계`, 혼합이면 `통장 잔액 합계`와 계산값 포함 안내를 표시합니다. 실제 확인값과 동별 월말 계산시점이 다르면 차액에 `비교 시점 다름`을 안내합니다. 도움말은 제목 왼쪽의 공통 InfoTooltip로 제공하며 아이콘 아래 배치·포커스·터치·Escape 등 기존 공통 동작을 재사용합니다.


425px를 포함한 모바일 잔고 목록의 표시 개수 선택은 마지막 행의 전체 너비를 사용합니다. 동 검색은 첫 행, 잔고 정렬·상태는 두 열을 유지하며 표시 개수를 반쪽 너비로 남기지 않습니다.


## 동별 입출금 명세 다운로드

2026-10-24 사용자 요청으로 월별 정산의 기존 동별 입출금·잔액 명세를 이 화면의 다운로드로 옮겼습니다. 종전 요약/동별 시트 Excel을 교체하며 [월별 정산 종합보고서](monthlySettlement.md#excelpdf-자료-범위)와 역할을 구분합니다. 공통 `shared/ui/report-download` 모달에서 Excel·PDF·이미지(PNG)를 미리보고 저장합니다. 실제 PDF·PNG의 페이지 이동 버튼은 미리보기 아래에 둡니다.

다운로드를 열 때 기존 통장 Workspace의 기간·사용 이력 메타데이터와 선택 월의 전체 통장 잔고를 확인합니다. 모달의 `조회 동 / 조회 계좌`는 전체 또는 개별 대상을 함께 선택하며 형식 전환에도 유지합니다. 목록에서 한 동 또는 통장을 선택했다면 모달의 초기 선택으로 사용합니다. 이후 범위는 모달에 명시한 동·계좌를 따르며 목록의 검색·상태·표시 개수·페이지로 줄이지 않습니다. 여러 동 체크박스는 목록의 선택 합계에 사용하며 다운로드는 모달의 전체/개별 동 선택을 따릅니다. 실패한 조회나 이전 관리대상·월의 자료로 파일을 생성하지 않습니다.

자료는 기존 확정 현금 원장 `balances.entries`입니다. 선택 월의 동별 실제 입금과 배분 부담 지출만 사용하고, 통장 원본 출금액을 동마다 반복하거나 미분류 금액을 임의 배분하지 않습니다. 동 이름은 숫자 오름차순, 각 동의 거래는 **월초→월말 거래일시 오름차순**, 같은 시각은 ID 순서입니다. 금액이 모두 0인 행은 제외합니다. 동의 이름을 확인할 수 없는 귀속 이력은 `동 확인 필요`로 보존합니다.

동마다 기초 잔액·입금·지출·월말 잔액과 소계를 표시하며 거래별 잔액은 기초부터 입금을 더하고 지출을 빼서 누적합니다. 개별 계좌는 `buildings.accountBalances`의 해당 계좌 잔액만 사용합니다. 필드가 없는 기존 응답에서는 기존 `GET banking/balances?month&accountId`로 확인한 뒤 파일을 만들며 전체 범위로 복원된 응답을 개별 계좌 자료로 사용하지 않습니다. 확인 실패는 재시도하고 미확인 잔액은 `설정 필요`로 유지합니다. 거래 없는 동은 `내역 없음`으로 표시합니다.

계좌 선택지는 기존 `getAccountsForMonth`와 `banking.accounts`의 `availableFrom / closedOn / hasHistory`를 사용합니다. 시작 월 이전·실제 입출금 없이 종료한 계좌를 제외하고 실제 사용한 종료 계좌는 종료 월까지 제공합니다. 수납·원장에 과거 계좌 ID가 있다는 이유로 선택지를 복원하지 않습니다. 통장 잔고 화면의 종료 후 잔액 보존 정책과 거래 명세의 계좌 선택 정책은 [도메인 규칙](../../docs/domainRules.md#사용-종료-통장-표시-2026-10-23-후속-확정)을 따릅니다.

Excel은 사용자 첨부의 진한 제목 띠·네 잔액 요약·동별 요약·명세·소계 서식을 **동별 입출금 내역 한 시트**에 적용합니다. 표시 열은 동·거래일시·통장·구분·입금자/지출명·입금액·지출액·잔액입니다. 예시의 별도 요약/동별/전체 시트나 거래·금액은 복사하지 않습니다. 정확한 정수와 문자열 보호는 [공통 엑셀 서식](excelReports.md)을 재사용합니다.

PDF는 기존 첨부 A4 세로 디자인을 유지합니다. 동마다 새 페이지를 시작하고 해당 동의 첫 페이지에만 큰 제목·조회 범위·건수·조회시각·기간 상태와 기초/입금/지출/월말 잔액 카드 4개를 둡니다. 다음 페이지는 거래표와 열 제목을 이어 표시합니다. 거래일시·구분·입금자/지출명·입금액·지출액·잔액의 6열, 입금 파랑·지출 빨강·교차 행 배경·동별 소계·전체 합계를 사용하며 모든 거래 행을 보존합니다. 한국어 글꼴과 PDF·PNG 변환·리소스 해제는 공통 모듈을 재사용하고 외부 변환 서비스로 자료를 보내지 않습니다.

파일명은 `모아홈_동별입출금내역_YYYY-MM.xlsx/pdf`이며 개별 동·계좌는 선택 표시명을 덧붙입니다. PNG 한 장은 `.png`, 여러 장은 번호를 붙인 PNG 전부를 ZIP으로 저장합니다. ISO 원문 대신 한국시간 조회시각을 표시하고 지난 월은 `9월 마감`, 현재 월은 `집계 중`, 미래는 `집계 예정`으로 표시합니다. `마감 미확정 자료` 문구를 다시 넣지 않습니다. 기간 표시는 원장 잠금·정정 이력과 구분합니다.

동·계좌 변경 시 이전 PDF/PNG를 즉시 제거하고 새 자료가 준비될 때까지 저장을 막습니다. 변환 취소·실패 재시도·포커스 복원·모바일 중앙 정렬을 유지합니다. `balanceReport.spec.ts`, `balanceReportFlow.spec.ts`와 기존 `bankingFlow.spec.ts`의 잔고 흐름으로 범위·잔액·순서·파일·오류를 확인합니다.
