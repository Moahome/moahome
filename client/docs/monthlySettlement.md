# 월별 정산 화면

작성일: 2026-10-24. **상태: 조회·점검·Excel·PDF·이미지(PNG) 및 사용자 선택 2번 시안의 화면 배치 적용.**

월별 정산은 한 달의 입출금·수납·지출·동별 자금과 확인할 항목을 모아 보는 관리자 화면입니다. 기존 통장 업무의 결과를 조회합니다. 다운로드는 관리대상 전체의 월별 정산 종합보고서를 Excel·PDF·이미지(PNG)로 제공합니다. 동별 입출금·잔액 명세는 [동별 잔고·정산](bankingManagement.md#동별-입출금-명세-다운로드)으로 옮겼습니다. 회계와 실제 마감 확정·잠금은 후속입니다.

업무 범위와 집계 기준은 [도메인 규칙](../../docs/domainRules.md#월별-정산-조회-구현), 요청·응답·오류는 [월별 정산 API](../../docs/monthlySettlementApi.md), 저장 설계의 적용 범위는 [ERD](../../docs/erd.md#12-월마감--통장대사)를 따릅니다.

## 메뉴와 진입 경로

후속 사용자 요청에 따라 `정산 / 마감`은 관리비 부과처럼 드롭다운 없는 단일 링크입니다. 별도 월별 정산 하위 메뉴·통장 대사·보고서 메뉴를 두지 않으며 회계 그룹은 숨깁니다. 기존 통장 관리의 동별 잔고·정산은 유지합니다. 전체 메뉴는 [관리 레이아웃](managementLayout.md#메뉴별-목적지)을 참조합니다.

브라우저 탭 제목은 `월별 정산 | 모아홈`입니다. 페이지 metadata에서 제목을 지정하고 루트의 공통 제목 템플릿을 재사용합니다.

경로는 `/manage/[propertyId]/closing/monthly`이며 선택 월을 `month=YYYY-MM`으로 유지합니다. 생략하면 서버 한국시간의 현재 월을 선택하고 잘못된 월은 다시 선택하도록 안내합니다. 직접 진입·새로고침과 월 선택 변경을 지원합니다. 상세 탭은 `tab=accounts|buildings|collections|external`로 유지하며 기본은 `collections`(수납과 미납)입니다.

## 화면 구성

사용자가 선택한 2번 시안을 기준으로 기존 공통 `ListHeader`, 월 선택, 요약 카드, 도움말, DataTable과 다운로드 버튼을 조합했습니다. 제목 오른쪽에는 월 선택과 다운로드 버튼, 그 아래에는 한국시간 조회시각과 새로고침을 둡니다. 후속 요청에 따라 월 선택 양옆의 이전·다음 월 버튼은 제거했습니다.

요약 카드 8개는 PC에서 4열 두 줄로, 월말 점검 6개는 그 아래 한 줄로 배치합니다. 점검 건수를 표시하되 0건이라는 이유만으로 마감 완료나 대사 확정으로 표현하지 않습니다. 전월 대비 증감률은 현재 응답에 없으므로 임의로 표시하지 않습니다.

하단은 통장별 잔액·동별 자금·수납과 미납·외부 부담금의 네 탭으로 구성합니다. 방향키·Home·End로 탭을 전환할 수 있으며 탭 변경은 같은 조회 응답을 사용합니다. 모든 탭에 검색·상태 필터·초기화를 제공합니다. 수납과 미납에는 동 필터도 유지합니다. `10개씩 보기`를 포함한 표시 개수 선택은 네 탭 모두 표 위에 배치합니다. 네 탭의 검색·상태 필터와 같은 줄에 둡니다. 표 아래에는 건수와 페이지 이동만 두며 표시 개수 선택을 배치하지 않습니다. 초기화 버튼은 다른 필터와 같은 높이(48px)로 맞춥니다.

| 영역 | 표시 내용 |
| --- | --- |
| 월 요약 | 통장 입출금, 관리비 실제 수납, 당월 청구액·수납 반영액·미수금, 동별 보유금, 외부 미회수액 |
| 월말 점검 | 거래 분류, 통장 잔액, 동별 시작 보유금, 미정 청구, 수동 등록 중복 가능성, 외부 미회수 내역 |
| 통장별 잔액 | 은행 확인 잔액·확인시점·출처, 월말 계산 잔액, 같은 시점 차액과 비교 상태 |
| 동별 자금 | 동별 기초 보유금·기간 입금·부담 지출·기말 보유금 |
| 수납과 미납 | 전월 이월액·당월 발생액·수납 반영액·미수금·선입금·기존 납부 상태 |
| 외부 부담금 | 선택 월에 지출한 부담금의 부담·회수·미회수 내역과 회수 상태 |

사용자 후속 요청에 따라 동별 자금은 동 이름의 숫자를 기준으로 오름차순(`2동 → 10동 → 102동 → 103동`), 외부 부담금은 지출일 최신순으로 정렬합니다. 같은 지출일은 ID 순서로 고정하며 페이지를 나누기 전에 정렬합니다. 화면에서 원천 응답 배열을 변경하지 않고 정렬합니다. 월별 정산의 외부 부담금은 지출일이 선택 월에 속하는 내역만 표시합니다. 요약 미회수액·월말 점검 건수·PDF·Excel도 같은 범위를 사용합니다. 이전 달의 미회수 내역은 기존 동별 잔고·정산의 누적 외부 정산에서 확인합니다.

| 상세 탭 | 검색 대상 | 상태 필터 |
| --- | --- | --- |
| 통장별 잔액 | 통장 표시명·은행명 | 전체, 차액 없음, 차액 있음, 비교 자료 필요 |
| 동별 자금 | 동 이름 | 전체, 설정됨, 설정 필요 |
| 수납과 미납 | 기존 세대·대표·입금자 검색 | 기존 납부 상태, 동 |
| 외부 부담금 | 부담처·지출명 | 전체, 미회수 전체, 회수 필요, 일부 회수, 회수 완료, 정산 제외 |

외부 부담금의 상태 열은 `정산 대상` 대신 `회수 상태`로 표시합니다. 정산 제외를 우선 표시하고, 그 외 내역은 미회수액 0원이면 회수 완료, 잔여액이 있고 일부 회수했다면 일부 회수, 회수액이 없으면 회수 필요입니다. 미회수 전체에는 회수 필요·일부 회수만 포함하며 정산 제외는 포함하지 않습니다. 이는 기존 유효 회수액·미회수액의 표시이며 새로운 회수 확정 처리를 만들지 않습니다. 상태 색상은 회수 필요 Danger, 일부 회수 Warning, 회수 완료 Success, 정산 제외 Sub Text를 사용합니다.

필터는 탭별로 유지하고 변경·초기화 시 첫 페이지로 이동합니다. 검색 결과가 없으면 원천 자료가 없는 월과 구분해 안내합니다. 동별 보유금이 미설정인 값은 0원으로 취급하지 않으며 비교 불가 통장을 차액 없음으로 분류하지 않습니다. 요약·점검과 Excel·PDF는 화면 필터로 줄이지 않습니다.

요약의 도움말은 파란 원 배경 없이 작은 회색 아이콘(`InfoTooltip`의 `sm`)으로 제목 왼쪽에 표시합니다. 카드 장식 아이콘은 기존 Primary·Teal·Success·Warning·Danger·Sub Text 토큰을 사용해 항목별 색상을 구분합니다. `최종 조회`와 날짜는 별도 요소로 두고 8px 간격을 적용합니다.

요약의 도움말에서 실제 입출금·청구 충당·동별 부담액의 차이를 설명합니다. 미납 계산은 [기존 월별 수납 화면](paymentManagement.md)을 그대로 재사용하고 전월 이월을 포함한 잔여액으로 표시합니다. 전체 과거 세대를 별도로 조회하는 회계 미수원장을 추가한 것은 아닙니다.

은행 확인값이 없거나 비교 시점이 다르면 확인 필요·비교 불가를 표시합니다. 0원 차액을 대사 확정으로 표시하지 않습니다. 확인 이력과 원천 업무의 표현은 [통장 관리 화면](bankingManagement.md)을 참조합니다.

점검 항목과 각 표의 관련 링크는 같은 관리대상·조회 월의 통장 거래, 월별 수납, 동별 잔고·정산으로 연결합니다. 분류·수납 확정·지출 배분·외부 회수를 이 화면에서 중복 입력하지 않습니다. 마감 확정·재오픈·정산 완료 처리 버튼도 제공하지 않습니다.

## 조회 상태와 반응형

현재 관리 권한 확인 뒤 API를 호출하며 Server는 기존 통장 업무와 같은 ADMIN 권한을 검증합니다. Query key에 로그인 사용자·관리대상·요청 월을 포함하고 원천별 응답 검증을 재사용합니다.

월이나 관리대상을 변경하면 이전 범위의 금액을 새 결과처럼 표시하지 않습니다. 조회 중·권한 오류·자료 없음·서버 연결 실패를 구분하고, 조회 실패나 잘못된 응답을 빈 월·0원으로 대체하지 않습니다. 실패 중에는 다운로드를 비활성화하고 재시도를 제공합니다.

좁은 화면에서는 요약 카드를 두 열, 모바일에서는 한 열로 배치합니다. 모바일에서는 헤더의 가로축 정렬을 stretch로 전환해 제목·설명·월 선택과 카드의 왼쪽 기준선을 맞춥니다. 점검과 상세 탭은 두 열로 줄바꿈하고 검색 필터도 화면 폭에 맞춰 배치합니다. 표 영역에서만 가로 스크롤을 허용합니다. 별도 모바일 상세 페이지는 추가하지 않았습니다. 색상과 공통 컴포넌트는 [Client 규칙](../AGENTS.md)을 따릅니다.

## 다운로드 모달과 미리보기

헤더의 `다운로드`는 PC·모바일 모두 공통 ClientModal에서 `Excel / PDF / 이미지(PNG)`를 선택하고 미리본 뒤 저장합니다. 기본은 Excel입니다. 형식 선택과 하단 행동은 유지하고 본문만 세로 스크롤합니다. PDF·이미지의 페이지 번호와 이전·다음 버튼은 **미리보기 아래**에 둡니다. X·Escape·취소로 닫고 원래 버튼으로 포커스를 복원합니다. 파일 생성·미리보기·실패 재시도는 잔고·정산과 `shared/ui/report-download`를 공유합니다.

모달을 열 때의 성공한 월별 조회 응답 전체를 사용합니다. 상세 탭의 검색·상태·동·표시 개수·페이지는 보고서 범위를 줄이지 않습니다. 월별 정산 보고서는 관리대상 전체를 출력하며 동·계좌 필터는 두지 않습니다. 전체/개별 동·계좌 선택은 [잔고·정산 명세 다운로드](bankingManagement.md#동별-입출금-명세-다운로드)에서 제공합니다. 관리대상·월이 바뀌면 이전 모달을 표시하지 않고 실패한 조회로 파일을 만들지 않습니다.

## Excel·PDF 자료 범위

2026-10-24 후속 사용자 요청으로 기존 동별 입출금·거래 후 잔액 문서를 잔고·정산으로 옮기고, 월별 정산에는 새 첨부 PDF·Excel 템플릿의 종합보고서 구성을 적용했습니다. 첨부의 예시 거래·이름·금액은 복사하지 않습니다. 이전에 정한 Excel 한 시트와 `마감 미확정 자료` 문구 제거는 유지합니다.

| 영역 | 기준 |
| --- | --- |
| 종합 요약 | 화면과 같은 8개 핵심 지표. 실제 통장 입출금·관리비 실제 수납·청구 충당·동별 보유금 등을 분리 |
| 월말 점검 | 화면과 같은 6개 점검 항목·건수. 자동 마감 차단이나 대사 확정으로 해석하지 않음 |
| 통장별 잔액 | 은행 확인 잔액·확인시점/출처·월말 계산 잔액·비교 상태 |
| 동별 보유금 현황 | 동별 기초·월 입금·배분 부담 지출·기말 잔액. 동 이름 숫자 오름차순 |
| 수납과 미납 | 기존 청구월 기준의 전월 이월·당월 발생·수납 반영·미수·선입금·납부 상태. 세대 오름차순 |
| 통장 입출금 명세 | 해당 월의 은행 원본과 유효한 미연결 확정 수동 입금·수동 지출 전액. 월초→월말, 내부 이체 포함 |
| 외부 부담금 | **선택 월 지출**의 부담·회수·미회수·상태. 지출일 최신순. 제외 내역은 보존하되 합계 제외 |

월별 보고서의 통장 명세는 실제 통장 이동 전액이고, 잔고·정산의 동별 명세는 동에 귀속한 입금과 배분 지출입니다. 원본 출금 전액을 각 동 지출로 반복하지 않습니다. 모르는 잔액은 `확인 필요`로 유지하고 0원으로 채우지 않습니다. 금액은 BigInt와 공통 셀 생성 도구로 정밀도를 보존합니다.

Excel은 `월별 정산 보고서` 한 시트입니다. 진한 제목 띠, 운영 요약·점검의 병렬 배치, 옅은 파랑 표 머리글·교차 행·합계를 적용하고 일곱 영역을 이어 배치합니다. 첨부의 여러 시트 구성은 복사하지 않습니다. 공통 셀 규칙은 [엑셀 보고서](excelReports.md)를 따릅니다.

PDF는 첨부 A4 세로 디자인으로 ① 종합 요약·점검·동별 보유금 ② 통장 확인·입출금 명세 ③ 수납·미납·외부 부담금의 세 영역을 새 페이지에서 시작합니다. 표가 길면 다음 페이지로 이어 전체 행을 보존하며 3페이지로 강제 축약하지 않습니다. 기간·한국시간 조회시각·페이지 번호를 표시합니다. 0원 금액의 `—`는 하단에서 설명하고 미확인 잔액과 구분합니다. 실제 Blob을 PDF.js로 미리보고 같은 파일을 저장합니다.

파일명은 `모아홈_월별정산_YYYY-MM.xlsx/pdf`입니다. ISO 조회시각 원문 대신 `YYYY-MM-DD HH:mm:ss (한국시간)`을 표시합니다. 지난 월은 `9월 마감`, 현재 월은 `집계 중`, 미래 월은 `집계 예정`으로 표시합니다. 이 기간 표시는 저장 원장의 잠금·재오픈 이력이 아닙니다. 다음 조회에는 원천 정정이 반영될 수 있습니다. 주민 연락처·계좌번호 원문 열은 추가하지 않습니다.

## 이미지(PNG) 다운로드

같은 PDF의 모든 페이지를 2배 배율의 흰 바탕 PNG로 만들고 실제 Blob을 미리봅니다. 한 페이지는 PNG, 여러 페이지는 번호를 붙인 모든 PNG를 ZIP으로 저장합니다. 파일명과 범위는 월별 보고서를 따릅니다. 변환 중에는 저장을 막고 실패하면 재시도합니다. 닫기·형식·범위 변경 시 작업을 취소하고 캔버스·PDF·Object URL을 해제합니다. 외부 서비스에 업무 자료를 보내지 않으며 PDF의 Pretendard 글꼴은 로컬 `/fonts/pretendard/`에서 읽습니다.

## 구현 구조와 검증 범위

`screens/monthly-settlement`에서 월별 조회·화면·종합보고서 모델을 관리하고 기존 Widget의 공개 검증·수납 계산을 재사용합니다. 동별 명세 모델은 잔고 업무를 소유한 `widgets/banking-workspace`에, 도메인과 무관한 다운로드 모달·PDF 글꼴·시각 표시·PNG 변환은 `shared`의 공개 모듈에 둡니다. 회계기간·전표·마감용 폴더·Migration은 추가하지 않습니다.

`tests/monthlySettlement.spec.ts`는 원천 집계 구분·미확인 값·동 정렬·외부 지출월 경계·한 시트 종합보고서 합계를 확인합니다. `tests/monthlySettlementFlow.spec.ts`는 PC·모바일 메뉴·월 변경·탭·필터·다운로드·템플릿 PDF/PNG와 페이지 버튼의 아래 배치를 확인합니다. 동별 명세 범위·정렬·잔액·계좌 선택·실제 PDF/PNG·오류 재시도는 `balanceReport.spec.ts`와 `balanceReportFlow.spec.ts`에서 확인합니다. 테스트는 모의 API를 사용합니다.
