# 월별 정산 화면

작성일: 2026-10-24. **상태: 조회·점검·Excel·PDF·이미지(PNG) 및 사용자 선택 2번 시안의 화면 배치 적용.**

월별 정산은 한 달의 입출금·수납·지출·동별 자금과 확인할 항목을 모아 보는 관리자 화면입니다. 기존 통장 업무의 결과를 조회합니다. 다운로드는 동별 입금·지출 내역을 Excel·PDF·이미지(PNG)로 제공합니다. 회계와 실제 마감 확정·잠금은 후속입니다.

업무 범위와 집계 기준은 [도메인 규칙](../../docs/domainRules.md#월별-정산-조회-구현), 요청·응답·오류는 [월별 정산 API](../../docs/monthlySettlementApi.md), 저장 설계의 적용 범위는 [ERD](../../docs/erd.md#12-월마감--통장대사)를 따릅니다.

## 메뉴와 진입 경로

후속 사용자 요청에 따라 `정산 / 마감`은 관리비 부과처럼 드롭다운 없는 단일 링크입니다. 별도 월별 정산 하위 메뉴·통장 대사·보고서 메뉴를 두지 않으며 회계 그룹은 숨깁니다. 기존 통장 관리의 동별 잔고·정산은 유지합니다. 전체 메뉴는 [관리 레이아웃](managementLayout.md#메뉴별-목적지)을 참조합니다.

브라우저 탭 제목은 `월별 정산 | 모아홈`입니다. 페이지 metadata에서 제목을 지정하고 루트의 공통 제목 템플릿을 재사용합니다.

경로는 `/manage/[propertyId]/closing/monthly`이며 선택 월을 `month=YYYY-MM`으로 유지합니다. 생략하면 서버 한국시간의 현재 월을 선택하고 잘못된 월은 다시 선택하도록 안내합니다. 직접 진입·새로고침과 월 선택 변경을 지원합니다. 상세 탭은 `tab=accounts|buildings|collections|external`로 유지하며 기본은 `collections`(수납과 미납)입니다.

## 화면 구성

사용자가 선택한 2번 시안을 기준으로 기존 공통 `ListHeader`, 월 선택, 요약 카드, 도움말, DataTable과 다운로드 버튼을 조합했습니다. 제목 오른쪽에는 월 선택과 다운로드 버튼, 그 아래에는 한국시간 조회시각과 새로고침을 둡니다. 후속 요청에 따라 월 선택 양옆의 이전·다음 월 버튼은 제거했습니다.

요약 카드 8개는 PC에서 4열 두 줄로, 월말 점검 6개는 그 아래 한 줄로 배치합니다. 점검 건수를 표시하되 0건이라는 이유만으로 마감 완료나 대사 확정으로 표현하지 않습니다. 전월 대비 증감률은 현재 응답에 없으므로 임의로 표시하지 않습니다.

하단은 통장별 잔액·동별 자금·수납과 미납·외부 부담금의 네 탭으로 구성합니다. 방향키·Home·End로 탭을 전환할 수 있으며 탭 변경은 같은 조회 응답을 사용합니다. 모든 탭에 검색·상태 필터·초기화를 제공합니다. 수납과 미납에는 동 필터도 유지합니다. `10개씩 보기`를 포함한 표시 개수 선택은 네 탭 모두 표 위에 배치합니다. 네 탭의 검색·상태 필터와 같은 줄에 둡니다. 표 아래에는 건수와 페이지 이동만 두며 표시 개수 선택을 배치하지 않습니다. 초기화 버튼은 다른 필터와 같은 높이(48px)로 맞춥니다.

| 영역 | 표시 내용 |
| --- | --- |
| 월 요약 | 통장 입출금, 관리비 실제 수납, 당월 청구액·수납 반영액·미수금, 동별 보유금, 외부 미회수액 |
| 월말 점검 | 거래 분류, 통장 잔액, 동별 시작 보유금, 미정 청구, 수동 등록 중복 가능성, 외부 미회수 내역 |
| 통장별 잔액 | 은행 확인 잔액·확인시점·출처, 월말 계산 잔액, 같은 시점 차액과 비교 상태 |
| 동별 자금 | 동별 기초 보유금·기간 입금·부담 지출·기말 보유금 |
| 수납과 미납 | 전월 이월액·당월 발생액·수납 반영액·미수금·선입금·기존 납부 상태 |
| 외부 부담금 | 조회 월말까지 누적된 부담·회수·미회수 내역과 회수 상태 |

사용자 후속 요청에 따라 동별 자금은 동 이름의 숫자를 기준으로 오름차순(`2동 → 10동 → 102동 → 103동`), 외부 부담금은 지출일 최신순으로 정렬합니다. 같은 지출일은 ID 순서로 고정하며 페이지를 나누기 전에 정렬합니다. 화면에서 원천 응답 배열을 변경하지 않고 정렬합니다. 다운로드의 동별 입출금 순서는 아래 자료 범위를 따릅니다.

| 상세 탭 | 검색 대상 | 상태 필터 |
| --- | --- | --- |
| 통장별 잔액 | 통장 표시명·은행명 | 전체, 차액 없음, 차액 있음, 비교 자료 필요 |
| 동별 자금 | 동 이름 | 전체, 설정됨, 설정 필요 |
| 수납과 미납 | 기존 세대·대표·입금자 검색 | 기존 납부 상태, 동 |
| 외부 부담금 | 부담처·지출명 | 전체, 미회수 전체, 회수 필요, 일부 회수, 회수 완료, 정산 제외 |

외부 부담금의 상태 열은 `정산 대상` 대신 `회수 상태`로 표시합니다. 정산 제외를 우선 표시하고, 그 외 내역은 미회수액 0원이면 회수 완료, 잔여액이 있고 일부 회수했다면 일부 회수, 회수액이 없으면 회수 필요입니다. 미회수 전체에는 회수 필요·일부 회수만 포함하며 정산 제외는 포함하지 않습니다. 이는 기존 유효 회수액·미회수액의 표시이며 새로운 회수 확정 처리를 만들지 않습니다. 상태 색상은 회수 필요 Danger, 일부 회수 Warning, 회수 완료 Success, 정산 제외 Sub Text를 사용합니다.

필터는 탭별로 유지하고 변경·초기화 시 첫 페이지로 이동합니다. 검색 결과가 없으면 원천 자료가 없는 월과 구분해 안내합니다. 동별 보유금이 미설정인 값은 0원으로 취급하지 않으며 비교 불가 통장을 차액 없음으로 분류하지 않습니다. 요약·점검과 Excel·PDF는 화면 필터로 줄이지 않습니다.

요약의 도움말은 파란 원 배경 없이 작은 회색 아이콘(`InfoTooltip`의 `sm`)으로 제목 왼쪽에 표시합니다. 카드 장식 아이콘은 기존 Primary·Teal·Success·Warning·Danger·Sub Text 토큰을 사용해 항목별 색상을 구분합니다. `최종 조회`와 날짜는 별도 요소로 두고 8px 간격을 적용합니다.

요약의 도움말에서 실제 입출금·청구 충당·동별 부담액의 차이를 설명합니다. 미납 계산은 [기존 월별 수납 화면](paymentManagement.md)을 그대로 재사용하고 전월 이월을 포함한 잔여액으로 표시합니다. 전체 과거 세대를 별도로 조회하는 회계 미수원장을 추가한 것은 아닙니다.

은행 확인값이 없거나 비교 시점이 다르면 확인 필요·비교 불가를 표시합니다. 0원 차액을 대사 확정으로 표시하지 않습니다. 확인 이력과 원천 업무의 표현은 [통장 관리 화면](bankingManagement.md)을 참조합니다.

점검 항목과 각 표의 관련 링크는 같은 관리대상·조회 월의 통장 거래, 월별 수납, 동별 잔고·정산으로 연결합니다. 분류·수납 확정·지출 배분·외부 회수를 이 화면에서 중복 입력하지 않습니다. 마감 확정·재오픈·정산 완료 처리 버튼도 제공하지 않습니다.

## 조회 상태와 반응형

현재 관리 권한 확인 뒤 API를 호출하며 Server는 기존 통장 업무와 같은 ADMIN 권한을 검증합니다. Query key에 로그인 사용자·관리대상·요청 월을 포함하고 원천별 응답 검증을 재사용합니다.

월이나 관리대상을 변경하면 이전 범위의 금액을 새 결과처럼 표시하지 않습니다. 조회 중·권한 오류·자료 없음·서버 연결 실패를 구분하고, 조회 실패나 잘못된 응답을 빈 월·0원으로 대체하지 않습니다. 실패 중에는 다운로드를 비활성화하고 재시도를 제공합니다.

좁은 화면에서는 요약 카드를 두 열, 모바일에서는 한 열로 배치합니다. 모바일에서는 헤더의 가로축 정렬을 stretch로 전환해 제목·설명·월 선택과 카드의 왼쪽 기준선을 맞춥니다. 점검과 상세 탭은 두 열로 줄바꿈하고 검색 필터도 화면 폭에 맞춰 배치합니다. 표 영역에서만 가로 스크롤을 허용합니다. 별도 모바일 상세 페이지는 추가하지 않았습니다. 색상과 공통 컴포넌트는 [Client 규칙](../AGENTS.md)을 따릅니다.

## 다운로드 모달과 미리보기

사용자 요청으로 헤더의 `Excel 다운로드`를 `다운로드`로 변경했습니다. 클릭하면 PC·모바일 모두 공통 ClientModal을 중앙에 열고 `Excel / PDF / 이미지(PNG)` Radio로 파일 형식을 선택합니다. 기본은 Excel이며 상단에 조회 월, 하단에 취소·선택 형식 다운로드를 배치합니다. X·Escape·취소로 닫고 원래 다운로드 버튼에 포커스를 복원합니다. 헤더·형식 선택·동·계좌 필터·하단 행동은 유지하고 본문만 세로 스크롤합니다.

모달을 연 시점의 성공 응답을 유지해 미리보기와 파일의 기준 월·조회시각·자료를 맞춥니다. 화면의 검색·페이징을 적용하지 않습니다. 기존 응답에 동별 accountBalances 필드가 없으면 계좌를 선택할 때 기존 잔고 API로 해당 계좌를 한 번 조회해 기초·월말 잔액을 확인합니다. 로딩 중에는 설정 필요로 단정하거나 파일을 만들지 않고, 실패는 재시도를 제공합니다. 선택 범위가 전체로 복원된 응답을 개별 계좌 자료로 사용하지 않습니다. 이 경우 Excel·PDF는 동일한 계좌 잔고 응답을 사용합니다. 모달의 `조회 동`과 `조회 계좌`에서 전체 또는 개별 동·통장을 함께 선택하며 기본값은 `전체 동 / 전체 계좌`입니다. 이 선택은 Excel·PDF 전환에도 유지하고 미리보기·거래 건수·소계·합계·파일에 동일하게 적용합니다. 선택 변경 시 이전 PDF를 즉시 제거하고 새 PDF가 준비될 때까지 다운로드를 막습니다. 관리대상·조회 월이 바뀌면 이전 모달을 표시하지 않으며 응답을 URL·브라우저 저장소에 기록하지 않습니다.

Excel은 동별 입출금 내역을 한 표로 미리봅니다. 시트 선택 UI를 두지 않고, 전체 내용을 하나의 시트로 내려받습니다. PDF는 같은 입출금 문서의 실제 Blob을 PDF.js로 읽어 페이지별 캔버스 미리보기를 제공합니다. PDF 생성은 PDF를 선택했을 때 시작하고 생성 중·실패·재시도를 구분합니다. 다운로드 중 중복 클릭을 막으며 실패 후 같은 자료로 재시도할 수 있습니다.

## Excel·PDF 자료 범위

후속 사용자 정정으로 다운로드 범위는 **선택 월의 동별 입금·지출·잔액 내역 한 문서**입니다. 대시보드의 월말 점검·통장 비교·수납과 미납·외부 부담금 표를 별도 시트나 PDF 명세로 내보내지 않습니다.

기존 동별 잔고의 확정 현금 원장(`balances.entries`)을 사용합니다. 각 동의 실제 입금과 배분된 부담 지출을 사용하며 통장 출금 원액을 동마다 반복하거나 미분류 거래를 임의 동으로 배분하지 않습니다. 해당 월 밖의 거래와 금액이 모두 0인 행은 포함하지 않습니다.

- 표시 열: 동, 거래일시, 통장, 구분(입금·지출), 입금자·지출명, 입금액, 지출액, 잔액
- 동은 숫자 오름차순, 각 동 안에서는 거래일시 오래된 순(월초 → 월말)이며 같은 시각은 ID 순서로 고정합니다.
- 동마다 기초 잔액·입금·지출·월말 잔액을 표시하고 거래별 잔액은 월초 기초 잔액부터 날짜순으로 입금을 더하고 지출을 뺍니다. 마지막에 전체 합계를 표시합니다. 계좌 선택 시 동별 accountBalances에서 선택 계좌의 잔액만 사용하며 전체 계좌의 잔액을 가져오지 않습니다.
- 거래 없는 동은 `내역 없음`을 표시합니다. 기존 귀속 동의 이름을 확인할 수 없으면 `동 확인 필요`로 내역을 보존합니다.
- 화면의 상세 탭·검색·필터·표시 개수·페이지로 다운로드 범위를 줄이지 않습니다.

계좌 선택지는 기존 통장 거래의 월별 표시 함수와 `banking.accounts`의 `availableFrom / closedOn / hasHistory`를 재사용합니다. 시작 월 이전과 실제 입출금 없이 종료한 계좌는 제외하며, 사용한 종료 계좌는 종료 월까지 표시합니다. 과거 수납·현금 원장에 계좌 ID가 남아 있다는 이유로 선택지를 다시 생성하지 않습니다. 업무 기준은 [사용 종료 통장 표시 정책](../../docs/domainRules.md#사용-종료-통장-표시-2026-10-23-후속-확정)을 따릅니다.

Excel은 [기존 서식](excelReports.md)을 재사용해 `동별 입출금 내역` 시트 **하나**로 저장합니다. 후속 첨부 엑셀의 진한 제목 띠·가로 요약 카드·동별 자금 요약·동별 거래 명세·소계 디자인을 한 시트 안에 적용합니다. 첨부 파일의 별도 요약/동별/전체내역 시트 구성과 예시 금액을 복사하지 않습니다. 파일명은 `모아홈_월별정산_YYYY-MM.xlsx`, PDF는 `모아홈_월별정산_YYYY-MM.pdf`입니다. 개별 동·계좌를 선택하면 파일명 뒤에 선택 표시명을 덧붙입니다. 금액은 BigInt와 공통 생성 도구로 정밀도를 보존합니다.

PDF는 사용자가 제공한 A4 세로 디자인을 적용합니다. 동마다 새 페이지를 시작하고 상단에는 문서 제목·조회 동·통장·건수·한국시간 조회시각과 기간 상태, 기초 잔액·입금 합계·지출 합계·월말 잔액 카드 4개를 배치합니다. 거래 명세는 거래일시·구분·입금자/지출명·입금액·지출액·잔액의 6열이며 입금은 파랑, 지출은 빨강으로 구분하고 교차 행 배경을 적용합니다. 동별 소계와 마지막 동의 전체 합계를 표시하며 각 동의 큰 제목·조회 조건·잔액 요약은 해당 동의 첫 페이지에만 표시합니다. 이어지는 페이지는 위쪽 여백을 줄여 거래표와 열 제목만 이어 표시합니다. 하단에는 전체 페이지 번호와 잔액 계산 기준을 표시합니다. 첨부 예시의 거래·금액은 복사하지 않습니다. `jspdf`·`jspdf-autotable`로 만들고 `pdfjs-dist`로 미리봅니다. PDF 선택 전에는 해당 엔진을 읽지 않습니다. 한국어는 기존 Pretendard의 공식 v1.3.9 TTF Regular·Bold를 서비스의 `/fonts/pretendard/`에서 읽어 포함하며 기존 OFL LICENSE를 함께 유지합니다. 외부 CDN·PDF 변환 서버로 업무 자료를 전송하지 않습니다.

파일에는 조회 월과 한국시간 조회시각(`YYYY-MM-DD HH:mm:ss (한국시간)`)을 표시하고 서버의 ISO 일시 원문을 그대로 노출하지 않습니다. 지난 월은 한국시간 조회 월과 비교해 `9월 마감`처럼 표시하고 현재 월은 `집계 중`, 미래 월은 `집계 예정`으로 표시합니다. 사용자 후속 정정에 따라 `마감 미확정 자료` 문구는 제거합니다. 이 기간 표시는 저장된 자료의 잠금·정정 이력을 생성하지 않습니다. 일반 다운로드는 동일 스냅샷을 사용하므로 파일과 미리보기의 기준 자료는 같습니다. 다음 조회에는 원천 정정 결과가 반영될 수 있습니다. 주민 연락처·계좌번호 원문 열은 추가하지 않습니다.

## 이미지(PNG) 다운로드

2026-10-24 후속 요청으로 다운로드 모달의 파일 형식에 `이미지 (PNG)`를 추가했습니다. 사용자 요청은 제품 안에서 보고서를 이미지로 저장하는 기능이며, 대화에 시안 이미지를 붙이는 작업과 구분합니다.

기존 PDF와 동일한 조회 월·동·계좌·잔액·날짜·페이지 배치를 사용합니다. PDF.js로 페이지마다 2배 배율의 흰 바탕 PNG를 생성하고, 실제 생성한 Blob을 페이지별로 미리봅니다. 한 페이지는 `.png`, 여러 페이지는 페이지 번호를 붙인 PNG 전부를 하나의 `.zip`으로 저장합니다. 여러 페이지의 ZIP 저장은 연속 파일 다운로드 차단과 지나치게 긴 단일 이미지 생성을 피하기 위한 구현 선택입니다. 파일명과 동·계좌 범위 표시는 기존 다운로드 규칙을 따릅니다.

변환 중에는 다운로드를 막고 실패 시 재시도를 제공합니다. 동·계좌를 바꾸면 이전 PDF와 PNG를 즉시 제거하고 진행 중인 이미지 변환을 취소합니다. 창을 닫거나 형식을 전환하면 불필요한 변환과 PDF 문서 리소스를 해제하며 미리보기 Object URL도 해제합니다. 페이지별 캔버스는 PNG 변환 뒤 즉시 해제합니다. 외부 이미지 생성·변환 서비스에 거래 자료를 보내지 않습니다. `fflate`는 기존 의존성을 운영 의존성으로 옮겨 ZIP 저장에 사용합니다.

## 구현 구조와 검증 범위

단일 메뉴이므로 `screens/monthly-settlement`의 한 화면 슬라이스를 사용합니다. `app/.../closing/monthly/page.tsx`는 이 슬라이스의 공개 API를 연결합니다. API·모델·화면은 해당 슬라이스에서 관리하며 기존 Widget의 공개 검증·수납 계산을 재사용합니다. 회계기간·전표·마감용 빈 폴더나 Migration을 미리 만들지 않습니다.

`tests/monthlySettlement.spec.ts`는 실제 입출금과 이월·선입금 충당의 구분, 정산 제외, 미정 청구·미확인 잔액, 동일 시점 비교와 동별 입출금 범위·정렬·부담 지출·한 시트·합계를 검사합니다. `tests/monthlySettlementFlow.spec.ts`는 PC·모바일의 단일 메뉴·월 변경·탭과 키보드 전환·필터·페이지 변경·모달·형식 선택·실제 PDF의 한글과 전체 명세·페이지 나눔·다운로드와 실제 PNG 미리보기/다운로드 일치·여러 페이지 ZIP 누락 방지·이미지 실패/재시도·조회 실패·다른 관리대상 응답 거부를 검사합니다. 테스트는 모의 API를 사용하며 실은행 거래나 운영 자료를 변경하지 않습니다.
