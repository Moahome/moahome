# 관리자 대시보드

작성일: 2026-11-01. **상태: 화면·전용 API 구현.**

사용자가 제공한 대시보드 시안과 후속 금액·이동·선입금·툴팁 정정을 반영합니다. 이미지의 이름·금액·건수를 고정 데이터로 복사하지 않습니다. 업무 지표·조회 범위·응답·오류의 기준은 [대시보드 API](../../docs/api/dashboardApi.md), 기존 정책·저장 구조는 [도메인 규칙](../../docs/domain/domainRules.md)과 [ERD](../../docs/domain/erd.md)를 따릅니다.

## 화면과 조회

경로는 `/manage/[propertyId]/dashboard`입니다. 공통 관리 레이아웃의 현재 ADMIN / MANAGER 확인 뒤 전용 API를 호출하며 서버도 현재 권한을 검증합니다.

| 영역 | 구성 |
| --- | --- |
| 제목 | 공통 ListHeader의 대시보드 제목과 관리대상 설명 |
| 조회 조건 | 제목 아래 MonthPicker·공통 QueryRefresh의 한국시간 업데이트 시각·새로고침 |
| 요약 4개 | 선택 월 청구액 / 청구 납부반영액 / 당월 청구 미수금 / 관리대상 부담 지출 |
| 중간 패널 | 현재 처리할 업무 / 세대 납부 현황 / 통장별 잔액 |
| 하단 패널 | 선택 월 최근 거래 5건 / 최근 6개월 관리비 추이 |

조회 월은 URL의 `month=YYYY-MM`으로 유지하고 생략하면 서버 한국시간 현재 월입니다. 새 범위에 이전 월·다른 관리대상의 금액을 잠시 표시하지 않습니다. 잘못된 월은 API를 호출하지 않고 월 재선택을 안내합니다.

금액·건수가 0인 성공 응답과 조회 실패·미확인을 구분합니다. 공통 LoadingState·RequestError·재시도를 사용하고 잘못된 응답을 0원으로 채우지 않습니다. 계정·관리대상·월별 Query는 재진입·창 복귀·1분 주기와 상세 닫기에서 갱신합니다.

## 금액과 세대 납부 현황

사용자 후속 요청에 따라 선납에서 선택 월 청구에 충당한 금액도 상단 납부반영액에 포함합니다. 당월 신규 청구 미수금에 다른 달 미납을 섞지 않습니다. 예를 들어 신규 청구 100만원에 5만원이 충당됐다면 납부반영액 5만원·당월 미수금 95만원입니다. 입금일 기준 실제 신규 입금은 기존 통장 거래·실제 입금 영역에서 구분합니다.

월별 수납·월별 정산·다운로드도 공개 함수 `getMonthlyChargeSummary`의 같은 신규 청구 요약을 재사용합니다. 화면별로 누적 미수 합계를 다시 계산하지 않습니다. 세대별 이월·누적 미수·선입금 원장은 기존 계산을 유지합니다. 사용자가 요청하지 않은 이월 구성 설명과 `별도 보관` 문구는 카드에 추가하지 않습니다.

도넛은 기존 수납 대상의 납부완료·일부납부·미납·정산 확인 필요 세대 수입니다. 텍스트 목록과 함께 제공하고 대상 없음·정산 미확정을 0% 완납으로 단정하지 않습니다. 선입금 보유는 목록에 별도로 표시하며 납부완료와 겹칠 수 있어 전체 세대 수에 중복 합산하지 않습니다. 선입금 행 위의 구분선은 표시하지 않습니다.

상태 색상은 납부완료 Success, 일부납부 Warning, 미납 Danger, 정산 확인 필요 Sub Text, 선입금 Secondary Teal을 사용합니다. 카드와 도움말은 공통 SummaryCard·InfoTooltip을 재사용하고 도움말은 제목 왼쪽에 둡니다.

## 현재 처리할 업무

현재 업무는 선택 월과 별도이며 전체 과거 미처리·현재 미회수를 대상으로 합니다. 제목 줄의 `현재 기준`은 오른쪽 끝에 배치합니다. 상단 총건수를 임의로 합산하지 않습니다. 0건도 기존 업무 화면에 진입할 수 있습니다.

| 항목 | 목적지와 조건 |
| --- | --- |
| 확인 필요 입금 | `/banking/transactions?review=income&direction=INCOME&status=PENDING` |
| 가입·정보 수정 요청 | `/invitations`, 일반 신청이 없고 수정 요청만 있으면 `tab=invited` |
| 미분류 출금 | `/banking/transactions?review=expenses&direction=EXPENSE&status=PENDING` |
| 외부 부담금 미회수 | 현재 월 잔고·정산의 `externalStatus=UNRECOVERED`와 외부 정산 영역 |
| 중복 의심 거래 | `/banking/transactions?review=duplicates`, 실제 수동 후보만 표시 |

통장 거래 목록은 URL의 입출금·처리 상태를 초기 필터에 반영합니다. 현재 업무의 날짜 조건이 없으면 실제 후보의 첫 거래일부터 조회 기준일까지로 달력을 표시합니다. 후보가 없으면 조회 기준일을 표시하고 해당 조건의 빈 목록을 제공합니다. 가상의 최솟값 날짜를 링크에 넣거나 전체 거래를 중복 후보로 표시하지 않습니다. 중복 필터는 화면에서 식별할 수 있고 `전체 거래`로 해제할 수 있습니다.

## 통장·거래·그래프

통장 행은 상세와 같은 `getAccountBalanceDisplay`를 사용해 계산 잔액을 먼저 표시합니다. 계산값 0원도 유효한 잔액이며, 계산 자료가 없을 때만 마지막 확인값을 표시합니다. 표시명·은행·계좌 끝 네 자리와 잔액 기준·출처를 함께 보여줍니다. 선택 월 이후의 확인값을 사용하지 않습니다. 모든 통장의 값이 확인된 경우에만 참고 합계를 표시하며 미확인 값을 0원으로 합산하지 않습니다.

통장 상세와 기존 잔고 화면은 계산 가능한 잔액을 우선 사용하고 없으면 저장된 마지막 확인 잔액과 시점을 유지합니다. 기존 금액을 가리고 매월 초기 잔액을 다시 요구하지 않습니다. 합계와 차이 카드의 표시는 짧게 유지하고 은행 확인값을 이용한 차이는 참고임을 구분합니다. 새 초기값이나 가상 입출금을 저장하지 않습니다.

최근 거래는 실제 월 거래를 정렬해 최신 5건을 표시하고 입출금·상태·내부 이체를 구분합니다. 수동 거래에 가상의 시각·거래 후 잔액을 만들지 않습니다. 전체 내역은 같은 월의 통장 거래로 연결합니다.

PC는 기존 수납·지출·통장 상세 모달을 재사용합니다. 모바일은 기존 독립 상세와 헤더 뒤로가기로 출발 대시보드 또는 목록의 실제 이전 URL에 복귀합니다. [공통 탐색 규칙](managementLayout.md#모바일-상세-복귀와-방문-기록-2026-11-01)을 따릅니다.

6개월 그래프는 선택 월까지의 청구액과 납부반영액을 비교합니다. 선입금 충당도 해당 월 납부에 포함합니다. 호버·키보드 초점·터치로 해당 월과 선택한 막대 하나의 금액만 즉시 표시하고 Escape로 닫습니다. 큰 정수는 원금액을 유지하고 그래프 좌표만 비율로 변환합니다. 음수 청구도 기준선 아래에 표시하며 보조기술에는 월별 금액 표를 제공합니다.

## 구조·반응형·검증

기존 `screens/management-dashboard`의 `api/`, `model/`, 단일 진입 `ui/managementDashboardPage.tsx`와 전용 CSS Module을 확장했습니다. 내부 패널은 `ui/_components/`에 둡니다. 형제 화면을 직접 참조하지 않고 기존 Widget의 원장 검증·수납 계산·상세 공개 API를 재사용합니다.

PC는 요약 4열·중간 패널 3열·하단 2열, 태블릿은 2열, 모바일은 세로 배치입니다. 도넛·목록과 표는 카드 내부에서 줄바꿈·스크롤하며 페이지 전체 가로 넘침을 방지합니다. 공통 헤더·메뉴·달력·버튼·표·도움말·색상 토큰을 재사용합니다.

검증 대상은 선납의 당월 자동 충당·전월 미수와 신규 청구의 구분, 실제 0원·미확인 잔액, 거래 연결·취소·내부 이체·외부 부담·동 없는 지출, 과거 업무 필터·0건 이동·실제 날짜, 권한·대상/월 검증, 금액 툴팁·PC 모달·모바일 복귀입니다. 테스트의 API는 모의 처리하며 실제 저장 검증과 구분합니다. 서버 테스트는 격리된 PostgreSQL·Redis를 사용합니다.

2026-11-01 검증: Client ESLint·TypeScript 통과, API·계산 검사 147개 통과. 관련 브라우저 검사 33개 중 28개는 첫 실행에서 통과했고, 짧아진 잔액 안내와 기대 문구가 달랐던 5개는 문구를 맞춘 뒤 재실행해 통과했습니다. 테스트 전용 Next.js 프로덕션 빌드로 1440/390/320px 화면을 확인했습니다. Server 전체 빌드와 테스트 586개도 통과했습니다.

선택 배포 검증: 초기 등록·공용 입력 폼·Migration 변경을 제외한 별도 소스에서 Server 전체 빌드·테스트 583개, Client ESLint·타입 검사·API/계산 검사 147개·관련 브라우저 검사 21개와 프로덕션 빌드를 통과했습니다.

후속 수정 검증: 통장 목록·상세 금액 통일, 잔고 월 기간·관리대상 보고서명, 정산 기본 탭과 실제 이전 화면 복귀를 확인했습니다. 초기 등록 변경을 제외한 소스에서 Server 전체 빌드·테스트 586개, Client ESLint·타입 검사·API/계산 검사 149개·관련 브라우저 58개를 통과했습니다. 브라우저 58개 중 50개는 첫 실행, 이전 복귀 기대값·공통 접근성 이름과 이동 완료 대기를 수정한 8개는 후속 실행에서 통과했습니다. 테스트용 프로덕션 빌드를 사용했으며 실제 휴대폰 브라우저 검증은 포함하지 않습니다.
