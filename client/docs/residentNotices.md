# 주민 공지 화면

건물별 열람 범위·인증·수명·오류·재시도는 [공지사항 API](../../docs/api/noticeApi.md#주민-읽기-api)를 따릅니다. 본 문서는 브라우저와 컴포넌트의 처리만 설명합니다.

`src/app/notices`의 얇은 라우트가 `screens/resident-notices`의 공개 진입점을 연결합니다. 진입·목록·상세는 관리자 레이아웃을 거치지 않습니다. AppProviders는 이 경로에서 계정 세션 복원과 등록 초안 수명 관리를 마운트하지 않아, 주민 쿠키 오류가 로그인 강제 이동이나 관리자 토큰 재발급을 유발하지 않습니다. 주민 요청은 공통 `customAPI`, 관리자 링크 관리은 기존 `authenticatedAPI`를 사용합니다.

별도 `공지 보기` 중간 화면을 두지 않습니다. 링크의 fragment 토큰을 한 번 메모리로 옮기고 `history.replaceState`로 주소에서 제거한 뒤 POST로 자동 교환해 바로 건물 공지 목록으로 이동합니다. 토큰을 localStorage·sessionStorage·검색 쿼리에 저장하지 않습니다. 교환 실패에는 공통 오류 안내에서 같은 메모리 토큰으로 재시도합니다. 유효한 기존 쿠키로 일반 진입해도 해당 건물 목록을 엽니다. 새 세션 교환 후 진행 중인 진입 조회를 제외한 이전 주민 Query 캐시만 제거합니다.

목록·상세는 먼저 세션의 건물과 주소의 건물을 대조합니다. 서버도 세션에서 건물을 결정합니다. 검색·페이지는 주소에 유지하고 실제 목록에서 상세로 이동한 기록이 있으면 공통 navigation-history로 그 목록에 복귀합니다. 모바일 복귀는 헤더에만 둡니다. 페이지가 표시되는 동안 30초 간격과 창 복귀 시 다시 조회해 회수·삭제을 반영하며, 오류가 확인되면 기존 자료 대신 안내를 표시합니다. 서버의 접근 차단과 이미 수신한 브라우저 자료의 삭제는 구분합니다.

주민 시안에 맞춰 흰색 화면 틀과 상단 공지 메뉴, 건물 배너, 중요 공지 영역과 전체 목록을 구성합니다. 2026-11-14 사용자 정정: 중요 공지는 상단 중요 공지 영역에서만 표시하며 전체 공지 표에서는 해당 글 자체를 제외합니다. API의 `importantItems`를 상단에, 일반 공지만 담은 `items`를 전체 공지 표에 연결합니다. 페이지당 10개와 페이지 수는 일반 공지 기준이고, 상단 총 건수는 검색에 맞는 중요·일반 공지의 합계입니다. 중요 공지만 검색되면 상단에서 열람하고 전체 공지 표에는 일반 공지 검색 결과가 없다는 안내를 표시합니다. 상세의 작성자·작성일은 제목 아래 오른쪽에 표시하고, PC 목록 복귀 버튼은 왼쪽에 둡니다. 공통 목록·입력·버튼·상태 UI를 재사용합니다. `entities/notice`의 NoticeEditor·NoticeAttachments는 화면이나 인증 API에 의존하지 않습니다. 관리자 화면의 얇은 어댑터가 기존 업로드·읽기 함수를 주입하고 주민 화면은 현재 공지 ID가 포함된 주민 파일 요청 함수를 주입합니다. API 원본 참조를 `<img src>`에 직접 넣지 않고, 허용된 바이트를 Blob URL로 표시한 뒤 화면 종료 시 해제합니다. 편집 서식·RGB·기존 Base64 호환을 유지합니다.

주민 메타데이터는 일반 서비스 안내만 담고 `noindex,nofollow`, `no-referrer`를 설정합니다. 서버 렌더링이나 OG 미리보기에 건물명·공지 제목·본문을 포함하지 않습니다. 실제 알림톡·문자 링크 템플릿은 아직 연결하지 않았습니다.

대표 브라우저 검사는 residentNoticeFlow와 noticeFlow에서 중간 화면 없는 자동 진입·관리자 API 미호출·건물 범위 안내·목록·검색·복귀·다운로드와 기존 편집 동작을 확인합니다. 인증·DB 보장은 서버 검증과 구분합니다.

글별 관리자 전용·주민 공개 설정은 제공하지 않습니다. 저장된 공지는 같은 건물의 유효한 링크에서 모두 열람하며, 별도 공개 API 호출이나 공개 상태 캐시를 사용하지 않습니다.
