# 주민 역할과 관리자 관리 화면

2026-10-25 변경 설계: 기존 화면 구성은 유지하며 초대 인증·기한·재전달은 [변경 API 계약](../../docs/memberManagementApi.md#redis-이전의-변경-계약-2026-10-25)을 따릅니다. Redis 이전·기간 안내는 앞선 요청으로 수정했으며 커밋 전 실행한 기본 검사·관련 브라우저 회귀 결과는 [Server 검증 현황](../../server/docs/memberManagement.md#구현-순서와-검증-상태)에 기록합니다. 전체 운영 연동 검증의 완료를 의미하지 않습니다. 아래 과거 해시 전용 초대의 암호문 복원 설명은 이전 전 동작이며 Redis 유실 복구에 적용하지 않습니다.

기준일: 2026-10-24. 아래는 주민 역할·가입 승인·공통 및 개인 초대의 현재 화면 구현입니다. 공통 정책은 [도메인 규칙](../../docs/domainRules.md#주민-참여-흐름), 요청·오류는 [참여자 관리 API](../../docs/memberManagementApi.md)를 참조합니다.

## 주민 목록·상세

목록의 열 제목과 상세·수정 폼의 라벨은 모두 `역할`로 통일합니다. 목록에 역할을 추가하고 주민 구분·세대 대표·가입 상태와 구분합니다. 미가입을 주민 권한으로 표시하지 않습니다. 현재 연결 계정의 역할을 서버에서 조회합니다.

주민 상세는 기존 PC 중앙 모달·모바일 독립 상세를 유지합니다. 기존 상세의 필드 행에 `역할`을 표시하고, 기존 주민 수정 폼에서 같은 공통 Dropdown으로 주민·부담당자를 선택합니다. 가입 전 주민은 역할 선택을 비활성화하며 주민 상세에 초대코드·가입 승인 안내·별도 권한 관리 영역을 넣지 않습니다. 주민 정보와 역할은 하나의 수정 요청·트랜잭션으로 저장합니다.

현재 사이드바 `가입 요청`은 실제 미연결 주민 전원과 주민별 개인 초대 발급·재발급·철회를 제공합니다. 전체 초대코드는 제목 오른쪽에서 발급·재발급하며 별도 공통 코드 폐기 버튼은 표시하지 않습니다. 개인 초대는 한 개의 버튼만 표시합니다. 미발급 시 바로 발급하고, 발급 후에는 같은 버튼이 화살표가 있는 메뉴 버튼으로 바뀝니다. 메뉴는 `개인 초대`·`재발급`·`철회`입니다. 메뉴의 개인 초대는 기존 코드·링크 전달 모달을 다시 엽니다. 새로고침 후에도 다시 열 수 있으며 최초 만료 시각을 연장하지 않습니다. 메뉴는 버튼 바로 아래에 열고 오른쪽 끝을 맞춥니다. 화면 아래에 공간이 없을 때만 위로 펼칩니다. 연결 상태는 실제 가입 전까지 미연결입니다. 발급 성공 뒤 같은 코드 또는 바로 가입 링크의 복사·메시지 공유를 선택합니다. 해시만 남은 과거 초대는 보관한 코드·링크를 본문 입력으로 대조해 한 번 복원하고, 이후에는 새로고침해도 같은 초대를 다시 열 수 있습니다. 복원은 재발급하지 않으며 기존 링크와 만료를 유지합니다. `승인 관리`는 일반 신청의 명부 선택 승인·거절과 개인 초대 정정 검토를 구분해 표시합니다.

초대 전달 모달은 2026-10-24 사용자 제공 시안에 맞춰 제목 아이콘·코드 내 복사 버튼·유효기간 배지·안내 행·복사 결과 알림·전달 버튼 세 개로 구성합니다. 파란 채움은 사용하지 않고 개인 초대와 전달 버튼은 기존 공통 outline의 흰 배경·Primary 글자·연한 테두리를 사용합니다. 모바일 전달 버튼은 각 한 줄 전체 너비·높이 56px입니다. 네이티브 공유가 없는 PC에서는 초대 메시지를 복사하며 실제 발송 완료로 표시하지 않습니다.

코드 직접 입력은 검증 후 가입 폼을 열고 링크의 fragment는 자동 검증해 코드 입력을 건너뜁니다. 공통 가입 폼은 이름·세대 필수, 연락처 선택입니다. 개인 초대는 2026-10-24 사용자가 최종 선택한 첫 번째 시안에 맞춰 상단 건물 그림·하나의 주민 정보 카드·안내·세로 전체 너비 버튼으로 표시합니다. 색은 공통 Primary 파랑을 사용하고 행동 이름은 `수정`·`참여하기`입니다. 지정 정보를 확인해 즉시 가입하거나 이름·연락처 수정을 요청합니다. 정정 승인 전 명부와 권한은 바꾸지 않습니다. 로그인 세션을 재사용하고 로그인 필요 시 별도 로그인 창을 열어 초대 정보를 보존합니다.

## 설정과 초대 입력

사용자 후속 지시에 따라 `/manage/[propertyId]/settings`의 `등록 및 참여` 항목에는 같은 이름의 진입 버튼을 둡니다. 헤더 행동 영역·참여자 표·참여자 선택·외부 부담당자 초대·초대 신청·관리소장 인계 UI를 넣지 않습니다. 버튼은 `/properties/add`로 연결하며 [서비스 진입 설계](serviceEntry.md#관리할-곳-추가참여-진입-2026-10-17)를 따릅니다. 2026-10-18에 추가한 별도 관리계좌 카드의 정정 버튼은 [계좌 변경 설계](managementLayout.md#설정의-계좌-변경-2026-10-18)를 따릅니다.

공통·개인 주민 초대와 기존 외부 부담당자용 코드 입력은 PC의 `/start`·`/properties/add`에서 공통 모달로 열고 현재 주소를 유지합니다. `/join`·`/invitations`에 직접 접근해도 PC 코드 입력은 같은 모달을 사용합니다. 모바일은 각 독립 페이지를 사용합니다. 유효 fragment가 있는 가입 링크는 코드 입력을 생략하고 가입·정보 확인 페이지로 엽니다. 입력과 제출은 같은 폼을 재사용합니다. 모바일의 참여 신청·완료 확인 버튼은 입력창과 같은 전체 너비와 최소 높이 56px로 표시합니다. 코드 원문을 URL 경로·쿼리·저장소에 넣지 않으며 신청 성공 뒤 입력을 지웁니다. 역할 변경·인계·코드 발급·승인의 서버 API는 유지하지만 별도 관리자 관리 화면은 현재 제공하지 않습니다. 주민 역할 수정은 주민 수정 폼을 사용합니다.

## 목록 표현

`/manage/[propertyId]/join-requests`는 가입 업무용 미연결 주민 API를 사용합니다. 주민 목록의 가입 상태로 대신 필터링하지 않습니다. 공용 동·호수 숫자순 정렬을 먼저 적용하고 소속 없는 주민은 마지막에 표시합니다. 이름·연락처 끝 네 자리·동·호수 검색과 주민 구분 필터를 제공합니다. 미연결 명부에 동이 있으면 숫자순으로 정렬한 동 필터를 함께 표시하며, 동이 없으면 숨깁니다. 동 선택은 검색·주민 구분과 함께 적용하고 검색·필터·초기화·표시 개수 변경 시 첫 페이지로 복귀합니다.

`/manage/[propertyId]/invitations`는 `승인 관리`로 연결합니다. 2026-10-24 사용자 요청에 따라 상단을 `가입 요청`·`초대 가입` 두 탭으로 나눕니다. 기본 `가입 요청` 탭은 실제 신청 계정·명부 후보 이름·연락처 끝 네 자리·동·호수 검색, 승인 상태 필터와 기존 승인·거절 모달을 제공합니다. `초대 가입`은 `?tab=invited`로 선택을 보존하며 새로고침·직접 접근에서도 해당 탭을 표시합니다. 선택한 목록만 조회하며 일반 요청의 검색·상태 필터를 초대 내역에 적용하지 않습니다. 방향키·Home/End로 탭 선택과 포커스를 이동합니다.

`초대 가입`은 사용자 제공 시안의 총 건수·표시 개수·표·페이지 이동 배치를 적용하며 색은 모아홈 공통 토큰을 사용합니다. 표 열은 명부 이름·동·호수·정정 요청 이름·연락처·정정 요청 연락처·상태·처리입니다. 실제 가입·정정 제출 내역을 기존 기준대로 표시하고 상태는 의미 색상의 점이 있는 배지로 구분합니다. 정정 승인 대기 행에서만 기존 정정 후 가입 승인·거절을 제공하며 완료 행의 처리는 `—`입니다. 발급·재발급·철회는 기존 가입 요청 메뉴의 초대 전달 흐름을 유지합니다. 권한·승인 처리·연락처 마스킹은 공통 API 계약을 따릅니다.

일반 요청의 모바일 상세는 `/invitations/[requestId]`이며 기존 `/join-requests/[requestId]`도 같은 상세로 연결합니다. 공통 헤더의 뒤로가기는 승인 관리의 가입 요청으로 복귀합니다.

목록은 공용 ListCard·DataTable·ListToolbar·Pagination을 사용하고 검색·필터가 있는 목록에는 Input·Dropdown을 추가합니다. 표시 개수는 10·20·50이고 각 목록의 전체 결과에 페이지를 적용합니다. 검색·필터가 있으면 이를 먼저 적용하며 결과가 줄어들면 현재 페이지를 유효 범위로 보정합니다. 미연결 목록은 실제 가입 신청이 없어도 표시하지만 승인 관리에 가짜 신청 행을 만들지 않습니다.

가입 요청·승인 관리의 브라우저 탭 제목도 각 메뉴명으로 표시합니다. 승인 성공 시 실제 신청 목록을 갱신하고 미연결 주민·기존 주민 목록 캐시를 무효화해 방금 연결된 주민을 다시 미연결로 표시하지 않습니다. 원문 전화번호나 계정 ID를 이 목록에 받지 않습니다.

## 가입 요청 모바일 주요 버튼 (2026-10-17)

모바일(767px 이하)에서는 `전체 초대코드 발급`를 제목·설명 아래 한 줄 전체 너비의 버튼으로 표시한다. 최소 높이 56px·글자 크기 16px로 제공하고 글자는 가운데 정렬한다. PC의 기존 헤더 오른쪽 배치는 유지한다.

## 공통 계약과 구현 범위

정책·API·만료·충돌 처리의 기준은 [참여자 API](../../docs/memberManagementApi.md#주민-초대-발급과-전달)를 참조합니다. 승인된 주민의 임시 홈은 `/resident`이며 가입 완료 행동과 재로그인 기본 진입에서 연결합니다. 상세 진입은 [서비스 진입](serviceEntry.md)을 따릅니다. 주민용 업무 기능과 문자·알림톡 일괄 자동 발송 연동은 후속 범위입니다.

관리소장과 부담당자는 통장·주민 등 동일한 메뉴·업무 버튼을 사용합니다. 주민 수정 화면은 현재 역할이 주민인 경우 부담당자에게 관리자 승격 선택을 비활성화하고 일반 정보 수정은 유지합니다. 실제 승격 거부는 서버에서 다시 검사합니다.

부담당자가 관리소장 주민 상세를 열면 조회만 제공하며 수정·삭제 버튼을 표시하지 않습니다. 일반 주민과 다른 부담당자의 일반 정보 수정은 유지합니다.

## Redis 이전에 따른 화면 영향과 검증 계획 (2026-10-25)

`src/features/member-management/ui/invitationCodeForm.tsx`의 기간 안내와 `src/screens/household/join-requests/ui/_components/invitation-share/invitationShare.tsx`의 화면·공유 메시지에 유형별 기한을 반영합니다. 실제 만료시각은 서버 expiresAt을 사용하며 재열기에서 새 기한을 계산하지 않습니다. 링크와 입력 코드는 같은 초대이므로 수락·정정 후 둘 다 추가 사용이 불가능해야 합니다.

새 개인 초대의 share에서 Redis 값이 없으면 기존 복원 폼으로 DB 해시만 대조해 인증값을 되살리지 않습니다. 현재 화면에는 token:null일 때 과거 코드를 입력하는 복원 분기가 남아 있으므로, 변경 API의 실패 응답·재발급 안내와 양립하는지 확인해야 합니다. 유효 Redis가 있는 restore 호환 요청과 유실된 초대의 재발급을 구분합니다. 공유 코드·개인 코드의 자동 재발급 버튼을 새로 추가하지 않고 기존 명시적 메뉴를 재사용합니다.

`src/features/member-management/api/memberApi.ts`의 초대 Redis 장애 메시지를 구현했습니다. 503은 코드 만료로 표시하지 않고 현재 입력에서 재시도합니다. 관리자 승인 대기는 코드의 expiresAt 경과만으로 완료·거절·만료로 바꾸지 않습니다. 접수한 외부 신청의 화면 상태는 REQUESTED를 유지합니다.

검증은 기존 `tests/onboardingFlow.spec.ts`의 개인 발급·공유·재열기·모바일·정정·초대 링크 로그인을 재사용합니다. 변경된 안내·공유 메시지·동일 최초 기한·Redis 유실 시 재발급 안내·503 입력 보존·소진 후 코드/링크 재사용 거부를 보강하고, 이전 DB 암호문 복원 테스트는 변경 계약에 맞춰 갱신합니다. 서버 테스트는 [Server 계획](../../server/docs/memberManagement.md#구현-순서와-검증-상태)을 따릅니다. 역할 변경 후 화면 자동 전환과 백그라운드 입력 보존은 [공통 레이아웃 설계](managementLayout.md#동적-권한-확인과-화면-보존-설계-2026-10-25)를 참조합니다.
