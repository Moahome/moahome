# 계정과목 설정 화면

2026-11-07 구현. [사용자 확정 정책](../../docs/domain/domainRules.md#계정과목-설정의-변경사용-중지삭제-2026-11-07-사용자-확정)과 [API 계약](../../docs/api/accountingAccountsApi.md)을 따릅니다. 아래 검색·배치·상세 동작은 해당 정책을 적용한 구현 선택입니다.

## 목록과 상태

`/manage/[propertyId]/accounting/accounts`는 `screens/accounting/accounts`의 공개 API로 연결합니다. 공유 요청과 권한별 행동 계산은 `features/accounting-accounts`에 두며 기존 손익 화면도 과목 추가 요청을 재사용합니다.

세대 목록처럼 ListHeader는 흰 카드 밖에 둡니다. 필터·툴바·표·페이지네이션만 공통 ListCard의 흰 배경으로 감쌉니다. 로딩·실패를 제목과 큰 흰 카드 안에 넣지 않습니다. 조회 중에는 기존 LoadingState만, 실패하면 기존 RequestError만 표시합니다. 일반 조회 오류도 기존 오류 이미지를 사용합니다. 로딩의 원형 표시·700ms 후 캐릭터 전환은 공통 동작을 그대로 사용합니다.

- 전체·사용 중·사용 중지 FilterTabs, 코드·이름 Input 검색, 유형 Dropdown을 제공합니다.
- DataTable에 코드·과목명·유형·손익 분류·제공 구분·사용 상태를 표시하고 코드 오름차순으로 정렬합니다. 자산·부채의 손익 분류는 `—`입니다.
- 기본 표시 개수는 사용자 정정대로 10개이며 표시 개수와 페이지 이동은 ListToolbar·Pagination을 사용합니다. 필터와 표시 개수 사이에는 공통 툴바의 여백만 적용하고 화면의 grid 간격을 중복하지 않습니다. 검색·필터·크기 변경 시 첫 페이지로 이동합니다. 모바일 표는 DataTable 내부에서 가로 스크롤하고 전체 페이지를 넘치게 하지 않습니다.
- 조회 성공의 빈 결과는 StateMessage로 표시합니다. 실패한 조회를 기본 과목이나 0건으로 대체하지 않습니다. 일반 새로고침·조회 시각은 추가하지 않습니다.

## 상세와 변경

행 클릭·키보드 Enter/Space는 공통 ClientModal 상세를 엽니다. 추가 폼도 같은 공통 모달을 사용합니다. 이름·코드·유형/손익 분류는 Input·Dropdown으로 표시합니다. 기본 과목·사용 여부와 서버 canManage에 따라 수정·중지·재개·삭제를 구분합니다. MANAGER는 변경 행동을 제공하지 않습니다.

사용한 추가 과목의 수정은 이름만 입력할 수 있고 코드·유형/분류는 읽기 전용입니다. 기본 과목에는 수정·삭제를 제공하지 않고 기본 비용에만 사용 상태 변경을 제공합니다. 중지·재개·삭제는 해당 과목을 표시한 확인 단계에서 실행합니다. 중지는 과거 거래·손익·원장을 유지한다고 안내합니다.

수정·변경에는 조회 revision을 전송하며 요청 중 중복 실행·닫기·Escape를 막습니다. 저장 실패 시 입력·상세를 유지하고 충돌은 최신 정보 확인을 안내합니다. 성공하면 공통 Toast를 표시하고 계정 목록·손익·원장·통장 선택·미지급 조회를 무효화합니다. 이력 표는 날짜만 표시하고 원본 시각은 유지합니다.

## 검증

정책·인증·대상 격리·응답 검증은 `accountingAccountsApi.spec.ts`, 목록·추가·미사용 수정/삭제·기본 과목 보호·중지/재개·충돌 입력 보존·조회 권한·모바일 넘침은 `accountingAccountsFlow.spec.ts`에서 확인합니다. 실제 실행 결과는 완료 보고와 구분하며 실행 명령은 Client AGENTS.md를 따릅니다.

2026-11-07 후속 사용자 시안을 반영해 상세 모달은 파란 안내 배너, 2열 입력, 공통 SummaryCard의 연한 배경 상태 카드와 변경 이력 제목 표시를 사용합니다. 실제 변경이 없으면 시계 아이콘과 안내를 표시하며 변경이 있으면 최초 상태부터 이력 표를 제공합니다. 좁은 화면에서는 입력·상태 카드를 한 열로 전환하고 제목·행동 영역을 유지한 채 본문만 스크롤합니다.
