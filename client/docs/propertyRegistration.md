# Client 관리대상 등록 설계

이 문서는 관리대상 등록 화면, 단계 이동, 브라우저 초안과 최종 제출의 Client 처리 방식을 정의합니다. 요청 필드 / 응답 / 오류 코드는 [공통 등록 API](../../docs/propertyRegistrationApi.md), 업무 정책은 [도메인 규칙](../../docs/domainRules.md)을 참조합니다.

작성일: 2026-10-05. 수정일: 2026-10-09. 기본 정보 화면, 주소 검색, 검증 API 호출, 동·세대 / 관리계좌 / 관리비 항목 설정, 다섯 단계의 입력 초안, 등록 정보 확인과 최종 등록 제출 / 결과 조회 / 완료 표시를 구현했습니다. 저장 후 공통 사이드바와 임시 대시보드를 연결했습니다. 관리대상 목록과 현재 관리자 권한 조회도 연결했습니다.

화면에 표시하는 용어는 [관리 레이아웃의 화면 용어](managementLayout.md#화면-용어)를 따릅니다. 이름 입력은 `건물·단지 이름`, 등록 정보의 첫 영역은 `건물·단지 정보`, 등록 완료 제목은 `관리할 곳이 등록되었습니다!`로 표시합니다.

## 1. 화면과 입력 책임

등록 흐름은 기본 정보 → 동·세대 → 관리계좌 → 관리비 항목 → 등록 정보 확인 순서로 구성합니다. PC에서는 기본 정보 폼을 모달, 모바일에서는 페이지로 사용하며 입력 폼과 검증을 공유합니다. 마지막 확인 화면은 저장 전 요약입니다. API의 저장 성공을 확인한 뒤에 완료를 표시합니다.

- 범용 입력은 `shared/ui/form-controls`의 Input / Dropdown / Radio, 클릭 버튼은 `shared/ui/button`의 Button을 공개 API로 가져옵니다. 화면에는 배치와 업무 처리만 남기고 공통 표현은 각 컴포넌트가 관리합니다. 사용법은 [Client README](../README.md#공통-입력-컴포넌트)를 따릅니다.
- 글자 수 계산, 입력값 정리, 단계별 검증과 추가 / 수정 / 삭제 상태는 등록 화면 / 기능 책임으로 관리합니다. 업무 정책을 범용 입력 컴포넌트 안에 넣지 않습니다.
- 이름, 동 / 세대 참조, 기본 계좌 수와 금액 등 입력 기준은 공통 API 계약을 참조합니다. 검증 수치나 API JSON 예시를 이 문서에 중복 정의하지 않습니다.
- 동의 clientId는 초안에서 유지해 세대 참조와 연결합니다. 배열 순서는 최종 요청의 표시 순서로 사용합니다. 화면의 이름순 정렬은 원본 배열을 복사해 적용하므로 초안과 동·세대 연결을 변경하지 않습니다.
- 건물 유형의 고정 옵션은 빌라 / 아파트 / 공동주택 / 기타이며 선택한 표시 문자열을 API에 전달합니다. 건물 유형과 동 구분 옵션은 `entities/property/constants/propertyOptions.ts`에서 관리합니다. Server의 문자열 계약을 유지하고 새로운 유형 Enum이나 유형별 업무 제한을 추가하지 않습니다. 은행명 / 코드 대응은 [공통 등록 API의 은행 선택 목록](../../docs/propertyRegistrationApi.md#은행-선택-목록)을 따르며 `entities/banking/constants/bankOptions.ts`에서 구현합니다.

### 현재 기본 정보 화면

- `/start`의 `관리할 곳 만들기`에서 `/start?registration=basic`으로 이동합니다. `features/property-registration`의 같은 폼을 PC 모달과 모바일 전체 화면으로 표시합니다. 모바일 상단 뒤로가기, PC 닫기 / 취소, Escape와 브라우저 뒤로가기는 등록을 취소합니다.
- 이름, 주소와 동 구분을 모두 입력하고 선택 입력의 형식도 유효해야 `등록하고 계속` 버튼이 활성화됩니다. 공백뿐인 이름은 입력으로 인정하지 않으며, 동 구분은 미선택으로 시작하고 `동 없음`도 명시적으로 선택해야 합니다. 글자 수는 API와 같은 Unicode 코드 포인트 기준으로 표시합니다.
- 건물 유형의 안내 문구는 미선택 placeholder에만 표시하며 실제 선택지에는 넣지 않습니다. 공통 Dropdown의 입력 폭에 맞춘 목록, 선택 표시와 키보드 이동을 사용하고 선택 해제 버튼으로 미선택 상태로 돌아갑니다. Escape로 목록을 닫을 때는 등록 화면을 취소하지 않습니다.
- 주소는 [카카오 우편번호 서비스](https://postcode.map.kakao.com/guide)의 공식 스크립트를 검색할 때 불러와 다이얼로그 안에 삽입합니다. 선택한 도로명 / 지번 주소를 읽기 전용 입력에 반영한 뒤 상세주소로 포커스를 이동합니다. 로딩 실패에는 재시도 / 닫기를 제공하고 기존 입력을 유지합니다.
- 검증 성공에는 정리한 기본 정보를 초안에 반영하고 `/start?registration=units`의 동·세대 설정으로 이동합니다. 최종 등록 API는 호출하지 않습니다.
- 기본 정보, 동·세대, 관리계좌, 관리비 항목과 현재 단계는 사용자 ID와 함께 현재 탭의 `sessionStorage`에 보관하고 새로고침에서만 복원합니다. 초안은 등록 흐름 전체에서 관리하며 모달과 단계 화면 사이 이동으로 폐기하지 않습니다. 등록 취소 / 등록 흐름 밖 이탈 / 로그아웃에는 폐기하고 새 진입과 다른 사용자의 입력은 복원하지 않습니다. 탭 저장소가 차단된 환경에서는 현재 화면의 메모리 입력만 유지합니다. 계좌번호 / 예금주를 포함한 진행 중 입력을 같은 탭의 새로고침 복원용 초안에 포함합니다. localStorage / 서버에는 단계별 입력을 저장하지 않으며 인증 토큰은 포함하지 않습니다. 최종 제출 본문과 결과 확인용 식별자는 아래 최종 제출 설계에 따라 별도로 관리합니다.

### 현재 동·세대 화면

- PC는 관리대상 이름, 다섯 단계의 진행 표시와 세대 표를, 모바일은 상단 뒤로가기, `2 / 5` 진행 표시, 세대 카드와 고정된 이전 / 다음 버튼을 제공합니다. 기본 정보가 검증되지 않은 직접 진입은 기본 정보 화면으로 돌립니다.
- 새 등록은 빈 동 / 세대 목록으로 시작합니다. 시안의 예시 호수를 자동 등록하지 않습니다. 호수와 표시 이름 검색, 동 선택 칩을 통한 동별 보기, 추가 / 수정과 초안 항목 삭제를 지원합니다.
- PC와 모바일 모두 `동 관리`에서 동을 추가 / 수정 / 삭제하며 본문에는 동 선택 칩을 표시합니다. PC의 별도 동별 드롭다운은 사용하지 않습니다. 동 관리 목록의 수정은 초록색 펜 아이콘, 삭제는 붉은색 쓰레기통 아이콘으로 표시합니다. PC 동 선택 칩은 건물 아이콘과 동 이름을 넣은 둥근 네모, 모바일은 둥근 형태를 사용합니다. 미선택 칩에는 Card 배경과 Border 테두리를 적용하고 선택 칩은 Primary 배경과 Card 글씨를 사용합니다.
- 동 칩 / 동 관리 목록 / 동 선택 드롭다운은 숫자를 인식하는 한국어 이름순으로, 세대 목록은 동 이름 → 원본 호수 순으로 정렬합니다. 표시 이름은 호수 정렬에 영향을 주지 않습니다.
- PC 세대 표에는 초록색 수정 / 붉은색 삭제 버튼을 나란히 제공하고 수정 창에는 취소 / 수정만 표시합니다. 모바일은 카드의 수정 버튼으로 들어가 입력 영역 끝의 전체 너비 붉은색 테두리 버튼으로 세대를 삭제합니다. 모바일 수정 창의 하단 취소 / 수정은 320px에서도 같은 너비로 나란히 배치합니다.
- 모바일은 가로로 스크롤하는 동 선택 버튼, 호수 검색, 선택한 동의 세대 수와 카드 순서로 표시합니다. 톱니바퀴 아이콘이 있는 `동 관리`에서 동을 추가 / 수정 / 삭제하며 본문에 동 편집 버튼을 나열하지 않습니다. 선택한 동에서 세대를 추가하면 편집 창의 동을 미리 선택하고, 삭제된 동의 필터는 전체로 돌아갑니다.
- 호수는 일반 문자열 Input으로 문자 입력과 붙여넣기를 허용하고 앞자리 0을 보존합니다. 층만 정수로 입력합니다. 상태 선택은 사용중 / 공실만 제공합니다. 기존 초안의 비활성 상태는 입력을 보존하되 유효한 상태를 다시 선택해야 다음 단계로 진행합니다.
- PC / 모바일의 `세대 자동 입력`에서 동, 시작 층, 마지막 층과 층당 세대 수를 지정하고 추가 / 중복 제외 개수와 생성될 호수·층을 미리 확인합니다. 기본 호수는 층 번호 + 두 자리 순번으로 만들며 2~6층 / 층당 2세대는 201·202부터 601·602까지 생성합니다. 지하층은 음수로 입력하고 호수에는 `B` 접두사를 붙입니다(-1층 → B101·B102, 층 표시는 B1층). 0층은 생성 범위와 수량 계산에서 제외하며 0층만 지정하면 추가할 수 없습니다. 층 값은 음수 정수로 저장합니다. 두 자리 순번은 1~99이고 브라우저 미리보기 한 번에는 최대 1,000세대를 생성합니다. 같은 동의 기존 호수 원문과 같은 항목은 제외하고 새 세대만 사용중 상태로 일괄 추가합니다. 규칙은 등록 초안에 보관해 다른 동, 이전 단계 이동과 새로고침에서 재사용하고 등록 취소 / 흐름 이탈 시 함께 폐기합니다. 자동 생성 이후에도 개별 수정 / 삭제와 수동 추가를 사용할 수 있습니다.
- PC와 모바일의 세대 삭제 버튼은 동·호수를 표시한 확인 창을 엽니다. 취소 / Escape는 목록과 모바일 편집 입력을 유지하고, 확인한 경우에만 초안을 제거합니다. 확인 창의 삭제 버튼은 Card 배경·Danger 글씨 / 테두리로 표시하고 최초 포커스는 취소에 두며 모바일에서는 편집 창 위에 표시합니다.
- 동 관리의 쓰레기통은 동 이름과 연결된 세대 수를 표시하는 삭제 확인 창을 엽니다. 삭제 범위 선택 UI 없이 동과 세대를 함께 삭제한다는 안내와 취소 / 삭제 버튼만 제공합니다. 세대가 없는 동도 같은 확인 창을 사용합니다. 취소 / Escape는 확인 창만 닫고 동 관리와 입력을 유지하며 확인 후 삭제된 버튼 대신 관리 창으로 포커스를 돌립니다. 초안 삭제 범위는 [도메인 규칙](../../docs/domainRules.md#초기-등록의-동호수와-상태-입력)을 따릅니다.
- 동 있음에는 동을 먼저 추가하고 세대가 속한 동을 지정합니다. 동 이름 수정은 기존 clientId와 세대 연결을 유지합니다. 동 삭제는 쓰레기통에서 범위를 확인한 후 연결된 세대와 함께 처리합니다.
- PC / 모바일 세대 목록은 동 이름·세대 수 오른쪽에 파란색 텍스트 `편집` 버튼을 둡니다. 편집을 누르면 버튼을 `완료`로 바꾸고 PC 표 / 모바일 카드에 체크박스를 표시하며 그 아래 전체 선택 / 선택 개수 / 붉은색 삭제 도구를 표시합니다. `완료`는 선택을 해제하고 일반 목록으로 돌아갑니다. 320px에서는 동·세대 수와 편집 / 완료 버튼은 한 줄로 유지하고 선택 도구는 아래에 배치하며 삭제 버튼은 전체 너비로 표시합니다. 현재 표시된 목록 안에서 개별 / 전체 선택하며 동 또는 검색 변경 시 선택을 초기화합니다. 선택 삭제 확인 창에는 동·호수와 개수를 나열하고 확인한 초안 ID만 제거합니다. 취소 / Escape는 선택을 유지하고 확인 후에는 선택 모드를 종료합니다. 다른 동의 같은 호수는 별도 ID로 구분하고 문자 / 앞자리 0 호수도 선택할 수 있습니다. 모든 세대 삭제 후에는 최소 세대 조건을 다시 적용합니다.
- 필수 호수, 선택 표시 이름 / 층, 등록 계약의 세대 상태를 입력받습니다. 중복 범위, 문자열 길이와 층의 정수 범위는 공통 API 계약을 따르며 호수의 문자열 검증과 동 이름 정리도 공통 계약에 맞추고 표시 이름에는 문자 입력을 허용합니다. 표시 이름이 없고 호수가 숫자로만 구성되거나 자동 생성한 지하 호수 형식(`B101` 등)이면 화면에만 `호` 접미사를 표시합니다. 그 밖의 문자 호수는 원문으로 표시합니다. 음수 층의 표시에는 `B` 접두사를 사용합니다.
- 이전 버튼 / 모바일 뒤로가기와 브라우저 뒤로가기는 기본 정보 입력을 유지합니다. 수정 후 다시 계속하면 기본 정보를 다시 검증합니다. 동 구분 변경에도 기존 배열을 자동 삭제하지 않으며, 동 없음으로 바꿨다면 사용자가 `동 연결 해제`를 눌러 동 참조를 정리할 수 있습니다. 이때 기존 세대는 유지하고 전체 범위의 호수 중복을 다시 검사합니다.
- 한 세대 이상이고 동 / 세대 입력이 유효해야 다음 버튼을 활성화합니다. 다음 버튼은 입력을 유지한 채 관리계좌 설정으로 이동합니다. 동·세대 편집만으로 업무 데이터를 저장하거나 등록 완료를 표시하지 않습니다.

### 현재 관리계좌 화면

- `/start?registration=account`에서 공용 관리계좌 하나를 입력합니다. 기본 정보 검증과 유효한 동·세대 입력을 선행 조건으로 확인하며 직접 진입 / 손상된 초안은 해당 이전 단계로 돌립니다.
- PC는 관리대상 이름과 다섯 단계 진행 표시, 흰 카드 안의 은행 일러스트 / 설명과 가로 라벨·입력 배치를 사용합니다. 모바일은 상단 뒤로가기, `3 / 5` 진행 표시와 설명 아래의 흰 폼 카드를 사용하며 이전 / 다음을 카드 하단에 나란히 배치합니다. 단계 진행 표시는 동·세대 화면과 같은 내부 컴포넌트를 사용합니다.
- 은행은 공통 SelectDropdown으로 국내 은행과 지역농축협 / 새마을금고 / 신협 / 산림조합 / 우체국을 선택합니다. 입력칸을 누르면 아래에 아이콘·이름 그리드(PC 4열 / 모바일 3열)를 펼치며, 같은 입력칸에서 이름·별칭을 검색하면 일치하는 아이콘·이름 리스트를 표시합니다. 코드는 노출하지 않고 확정한 코드·이름만 초안에 반영합니다. 선택 후 입력칸에 아이콘·이름을 표시하며 재개방은 검색을 비우고 전체 목록과 현재 선택을 보여줍니다.
- 은행 검색어는 확정 선택과 별도로 화면에서만 관리합니다. 빈 결과에서는 Enter로 확정하지 않으며, Escape / Tab / 외부 클릭 / 목록 닫기는 기존 은행을 유지합니다. 방향키로 후보를 탐색하고 한글 조합 중 Enter는 선택으로 처리하지 않습니다. 은행 아이콘은 [로컬 자산](../public/banks/README.md)으로 제공해 런타임 외부 이미지 요청을 하지 않습니다.
- 새 등록에는 은행 / 계좌번호 / 예금주 예시나 로그인 닉네임을 채우지 않습니다. 단일 계좌의 기본 지정은 선택된 상태로 시작하며 해제하면 안내를 표시하고 다음 버튼을 비활성화합니다. 계좌 추가 / 삭제는 이 화면의 구현 범위에 포함하지 않습니다.
- 은행, 계좌번호, 예금주와 기본 지정이 공통 계약을 만족해야 다음 버튼이 활성화됩니다. 계좌번호 입력과 초안에는 ASCII 숫자만 허용하고 문자열로 관리해 앞자리 0을 보존합니다. 공통 Input의 숫자 전용 입력으로 하이픈·공백·문자 타이핑을 거부합니다. 은행에서 복사한 번호를 붙여넣을 때에는 공통 계약의 공백·하이픈만 제거하고 다른 문자가 남으면 붙여넣기를 거부합니다. 이전 초안의 구분 기호도 복원에서 제거하며 다른 문자가 남으면 번호만 비워 다시 입력받습니다. 입력값·요청과 등록 확인 화면의 계좌번호 표시에는 하이픈을 포함하지 않습니다. 실제 계좌 / 예금주 조회는 수행하지 않습니다.
- 이전 버튼 / 모바일 뒤로가기 / 브라우저 이력 이동에도 계좌와 이전 단계의 입력을 유지합니다. 계좌 입력은 같은 사용자·탭의 sessionStorage로 새로고침에서만 복원하고 등록 취소 / 흐름 이탈 / 로그아웃에 함께 폐기합니다. 이전 버전의 초안에 계좌가 없거나 계좌 자료형이 손상되면 이전 입력을 유지하고 계좌 폼만 빈 값으로 복원합니다.
- 관리계좌의 다음 버튼은 유효한 계좌 입력을 유지하며 관리비 항목 설정으로 이동합니다. 입력 확인만으로 최종 등록 API를 호출하거나 저장 완료를 표시하지 않습니다.

### 현재 관리비 항목 화면

- `/start?registration=fees`에서 기본 관리비 항목을 입력하며 기본 정보·동·세대·관리계좌의 유효성을 선행 조건으로 확인합니다. 새 등록은 확정 정책에 따라 빈 목록으로 시작합니다.
- PC는 항목명 / 금액 / 수정·삭제 표, 모바일은 종류별 아이콘·이름·금액·수정 카드와 편집창의 삭제 버튼을 사용합니다. 추천 종류에는 건물 / 빗자루 / 승강기 / 번개 / 물방울 / 정화조 / 쓰레기통 아이콘을 각각 사용합니다. 일반관리비는 등록 확인 화면의 보라색, 청소비·정화조 청소비는 청록색, 승강기 유지비·공용 수도료는 파란색, 공용 전기료·생활폐기물 처리비는 주황색으로 구분하며 같은 색의 연한 원형 배경을 사용합니다. 코드 없는 직접 입력은 보조 텍스트 색상의 공통 문서 아이콘을 사용하며 모든 색상은 기존 전역 토큰을 참조합니다. PC 목록의 수정 버튼은 기존 초록색 글씨·테두리·호버 배경을 유지합니다. 모바일 목록의 수정 글씨와 화살표만 공통 Primary 파란색으로 표시합니다. PC 수정창에는 삭제 버튼을 표시하지 않습니다. 항목 추가, 세대당 월 기본 합계, 실제 부과 시 변경 가능 안내와 이전 / 다음을 배치합니다. 기존 공통 진행 표시·입력·버튼·일러스트를 재사용합니다.
- Server는 [공통 등록 API](../../docs/propertyRegistrationApi.md#기본-관리비-항목)의 선택적 항목 코드를 검증·저장합니다. Client는 `entities/billing`의 추천 옵션과 공통 Dropdown으로 7개 종류와 직접 입력을 제공하며 선택한 코드를 초안에 보존합니다. 종류별 코드 목록은 공통 API 계약을 기준으로 합니다.
- 추가·수정창은 항목 종류와 기본 금액을 입력받으며 항목명 입력칸은 직접 입력을 선택했을 때만 표시합니다. 새 항목은 종류 미선택 상태로 시작하고 추천 종류나 직접 입력을 선택해야 추가할 수 있습니다. 추천 종류는 선택지의 정해진 이름으로 저장하고 별도 이름 편집을 제공하지 않습니다. 직접 입력으로 전환하면 이전 항목명과 이름 오류 표시를 비우고 금액은 유지하며 코드는 null로 보존합니다. 이미 저장한 직접 입력 항목을 수정할 때는 기존 이름과 금액을 유지합니다. 처음 열거나 종류만 선택한 상태에서는 빈 항목명·금액을 오류로 표시하지 않으며, 각 입력칸에서 포커스가 나간 뒤 해당 칸의 오류만 표시합니다. 원 단위 정수 입력은 맨 앞의 음수 부호와 숫자만 허용하며 `-`만 입력한 상태와 빈 금액은 확정하지 않습니다. 0원과 음수는 허용하고 실제 제한은 공통 등록 API를 따릅니다. 금액 입력은 공통 AmountInput으로 천 단위 콤마를 표시하고 초안·검증에는 콤마 없는 정수 문자열을 사용합니다. 포커스가 있으면 금액은 왼쪽, 포커스가 없으면 오른쪽으로 정렬하고 원 단위 표시는 오른쪽에 유지합니다. 입력 중 빈칸·음수 부호를 유지하며 중간 입력·선택 교체와 콤마 경계의 Backspace·Delete에서 커서를 보정합니다. 올바른 천 단위 콤마가 포함된 붙여넣기도 허용하고 잘못된 콤마·소수·문자 붙여넣기는 거부합니다. 목록·합계·등록 확인의 정수·원 표시는 shared/lib/format의 formatInteger / formatWon을 공유하며 최종 API에는 정수 값을 보냅니다. 항목명 중복 제한을 임의로 추가하지 않습니다.
- 편집 중 값은 편집창의 로컬 상태로 두고 취소 / Escape는 목록을 보존합니다. 최초 포커스는 항목 종류이며 드롭다운이 열린 상태의 Escape는 목록만 닫습니다. 수정은 같은 초안 ID와 순서를 유지합니다. 삭제는 항목명 확인 후 해당 ID만 제거하고 취소하면 편집창과 미확정 입력을 유지합니다. 삭제 확인창의 최초 포커스는 취소이며 삭제 후 항목 추가 버튼으로 돌아갑니다.
- 합계는 세대 수를 곱하지 않으며 BigInt로 상쇄 항목까지 정확히 계산합니다. 개별 항목과 최종 합계는 공통 계약의 양·음수 범위를 검사합니다. 유효한 항목이 하나 이상이어야 다음을 활성화하며 마지막 항목 삭제 시 다시 비활성화합니다. 초기 빈 목록과 마지막 항목 삭제 뒤에는 빈 상태 안내와 비활성 버튼으로 조건을 알리고 항목 수 오류를 붉게 표시하지 않습니다.
- 이전 / 브라우저 이력 / 새로고침은 항목과 이전 입력을 유지하고 이탈 / 로그아웃 / 사용자 변경은 함께 폐기합니다. 새로고침에서 항목 자료형·추천 코드·중복 ID·입력이 손상되면 관리비 목록만 비워 이전 단계를 보존합니다. 코드 필드가 없던 기존 초안은 항목명을 바꾸거나 종류를 추측하지 않고 코드 null의 직접 입력으로 복원합니다. 편집창의 미확정 입력은 새로고침 복원 대상에 포함하지 않습니다.
- 관리비의 다음 버튼은 유효한 입력을 유지하며 `/start?registration=review`로 이동합니다. 항목 편집과 단계 이동은 저장 API를 호출하지 않으며 실제 청구를 생성하지 않습니다.

### 현재 등록 정보 확인 / 완료 화면

- `/start?registration=review`에서 PC는 흰 카드 안의 요약 행, 모바일은 아이콘·요약·수정 표시가 있는 세로 리스트를 표시합니다. 다섯 번째 단계의 기본 문구는 `등록 정보를 확인해주세요`이며 실제 저장 성공을 확인한 뒤에만 별도 완료 페이지로 이동합니다.
- 관리대상 이름·주소, 동·세대 수와 호수, 은행·전체 계좌번호·예금주, 세대당 월 기본 합계와 항목별 금액을 초안에서 표시합니다. 등록 전 오타를 확인할 수 있도록 계좌번호는 앞자리 0을 유지한 전체 숫자 문자열로 표시하며 하이픈은 추가하지 않습니다. 세대는 기존 표시 정렬을 적용하고 첫 호수와 나머지 세대 수를 요약합니다. 관리대상·동/세대·관리계좌·관리비 네 항목 모두 같은 위치의 위·아래 화살표로 상세 정보를 펼치거나 접으며 별도의 전체 세대 보기 버튼은 두지 않습니다. 동별 제목 오른쪽에 세대 수를 한 번 표시하고 아래 호수는 연한 배경의 읽기 전용 목록으로 표시합니다. 호수는 저장된 층 값으로 묶고 지하부터 지상 순서로 표시하며 층마다 새 줄에서 시작합니다. 동 전체 세대 수나 마지막 자동 입력 규칙으로 열 수를 정하지 않습니다. PC에서는 각 층의 실제 세대 수를 기준으로 1·2·3개는 각각 1·2·3열, 4개 이상은 최대 4열로 표시하고 같은 층 안에서 줄바꿈합니다. 목록 공간이 좁으면 열 수를 줄입니다. 층 미입력 세대는 호수로 층을 추측하지 않고 별도 목록으로 마지막에 표시합니다. PC에서는 목록 패널을 요약 행 전체 너비로 펼치고 전체 패널에 최대 높이 360px와 내부 스크롤을 적용합니다. 모바일도 층별 구분을 유지하며 최대 2열로 표시하고, 긴 세대명이 포함된 층이나 매우 좁은 목록은 1열로 전환합니다. 세대별 테두리·클릭·호버는 사용하지 않습니다.
- 관리비는 합계와 항목 수를 요약하고 아코디언 안에 항목·금액 표를 표시합니다. 버튼처럼 보이는 항목 추가 / 수정 안내는 표시하지 않습니다. 네 항목의 요약 행 터치는 펼치기 / 접기만 수행하며 수정 단계로 이동하지 않습니다. 모바일 진행률은 상단의 5 / 5와 전체 너비 막대로 표시합니다.
- 처음에는 네 항목 모두 요약만 표시합니다. 요약 행 오른쪽 같은 위치에 테두리·배경·호버 밑줄 없는 파란색 `수정` 글씨를 고정하며 접힌 상태에서도 접근할 수 있습니다. 요약 전체는 실제 펼치기 버튼의 터치 영역으로 만들고 수정은 중첩되지 않는 별도 동작으로 연결합니다. 수정 선택은 펼침 상태를 바꾸지 않습니다.
- 수정 단계에 진입한 뒤에도 다음은 기본 정보 → 동/세대 → 관리계좌 → 관리비 → 등록 확인의 순서를 따릅니다. 3단계에서 다음은 4단계로 이동하며 5단계로 건너뛰지 않습니다. 이전 버전의 초안에 남은 요약 복귀 표시는 읽거나 저장하지 않습니다. 입력과 현재 단계의 새로고침 복원은 유지합니다.
- 관리대상 상세에는 이름·주소·상세주소·건물 유형·동 구분, 관리계좌 상세에는 은행·전체 계좌번호·예금주·공용 / 기본 계좌 구분을 표시합니다. 요약과 펼친 상세 모두 초안의 전체 계좌번호를 하이픈 없이 표시합니다.
- 화살표 회전과 상세 높이 변화에만 180ms 애니메이션을 적용하고 버튼 이동·축소·상세 투명도 변화는 사용하지 않습니다. 닫힌 내용은 포커스와 읽기를 차단하며 동작 감소 설정에서는 애니메이션을 끕니다.
- 아이콘은 제공된 시안대로 관리대상 보라색·동/세대 초록색·계좌 파란색·관리비 주황색으로 구분하고 전역 색상 토큰을 사용합니다.
- `관리 시작하기`에서 전체 입력을 최종 API 계약으로 변환합니다. 화면용 세대 ID·자동 생성 규칙은 보내지 않고 추천 항목 코드와 직접 입력의 null 코드, 정수 원 단위 금액을 보존합니다. 기본 정보의 선택 빈 값은 null로 정리합니다.
- 제출 중 / 결과 확인 중에는 배경을 잠그는 모달과 스피너를 표시합니다. API에서 개별 저장 단계의 진행 상황을 제공하지 않으므로 등록할 정보 목록만 안내하며 단계별 완료나 진행률을 만들지 않습니다. Escape와 배경 클릭으로 요청을 취소하거나 모달을 닫지 않습니다. 제출 중 / 결과 확인 중에는 수정·이전·새 제출을 제공하지 않습니다. 결과 미확인 상태에서는 조회가 404를 반환한 경우에만 입력 수정과 같은 ID의 재등록을 제공합니다. 브라우저 뒤로가기로 이전 단계 URL을 선택해도 결과 확인 화면으로 돌아옵니다. 흐름 밖 이탈이나 로그아웃은 서버 저장의 취소로 취급하지 않습니다.
- 명확한 `400 / INVALID_REQUEST`는 초안을 유지하고 실패 모달에 안전한 사유를 표시합니다. `등록 정보로 돌아가기` 또는 Escape는 확인 화면으로 복귀하고 `입력 수정하기`는 해당 단계의 안내로 연결합니다. 기본 정보는 모달 내부, 다른 단계는 폼 앞의 접근 가능한 오류 안내에 Client 메시지를 표시합니다. 수정 이후에도 기존 ID를 유지해 재제출하며 수정 전 요청이 늦게 성공한 경우의 중복 생성을 막습니다. 서버 원문 메시지와 입력값은 오류에 포함하지 않습니다.
- 통신 실패 / 잘못된 성공 응답 / 서버 장애는 같은 요청 ID로 결과를 먼저 조회합니다. 조회로도 확인하지 못하면 실패와 구분되는 결과 미확인 모달에서 결과 확인을 제공합니다. 결과 미확인과 명확한 실패의 모달은 닫기 버튼·Escape·배경 클릭으로 닫을 수 있으며 닫기는 저장 요청의 취소나 미확인 요청 ID의 폐기를 의미하지 않습니다. 결과 미확인 모달을 닫으면 확인 화면에 결과 확인·가능한 동일 요청 재시도·입력 수정·등록 설정 나가기를 표시하고 결과 확인 버튼으로 포커스를 돌립니다. 확인 또는 재시도를 선택하면 처리 모달을 다시 표시합니다. 나가기는 `/start`로 돌아가며 제출 본문을 폐기하지만 미확인 요청 ID는 유지해 재진입 시 조회합니다. 404를 확인했고 원래 제출 본문을 보유한 경우에는 동일 ID·본문 재시도와 입력 수정을 제공합니다. 입력 수정은 기본 정보로 이동해 초안을 유지하며 수정한 최종 제출도 기존 ID를 재사용합니다. 본문을 폐기한 재진입에서 404이면 기본 정보 입력을 바로 열고 새 입력을 같은 ID로 제출할 수 있습니다. 입력 화면으로 돌아갈 때 이전 등록 조회 결과나 수정 안내를 오류 문구로 표시하지 않습니다. 조회 자체가 실패하면 결과 확인을 제공하며 새 ID는 생성하지 않습니다.
- 저장 성공 시 입력 초안과 제출 본문을 즉시 폐기하고 현재 URL을 `/start?registration=complete&requestId={UUID}`로 치환합니다. ID는 조회 대상이며 별도 인증 토큰이 아닙니다. 완료 페이지에는 성공 아이콘, 관리대상·주소·동/세대·계좌·예금주·월 기본 관리비 요약과 완료 항목을 표시합니다. 버튼을 누르지 않으면 완료 페이지에 머물며 자동 이동하지 않습니다. 완료 뒤 브라우저 뒤로가기는 문서를 다시 열어 로그인과 기존 결과의 현재 권한부터 확인하며, 확인된 결과로 완료 페이지를 표시하고 이전 입력을 재제출하지 않습니다.
- 완료 페이지 상단의 초록 원은 살짝 커지며 나타나고 흰 체크를 순서대로 그리는 애니메이션을 한 번 재생합니다. 동작 감소 설정에서는 완성된 아이콘을 즉시 표시합니다.
- POST 성공을 직접 확인한 완료 페이지는 메모리의 요약을 유지합니다. 새로고침 / 재진입에서는 URL 또는 본인의 탭 기록에서 조회 ID만 읽고 GET 성공 전에는 이전 요약·계좌·초안을 표시하지 않습니다. GET은 로그인한 제출자와 현재 접근 권한을 검사합니다. 확인 후 응답의 최소 성공 스냅샷으로 관리대상·개수·합계를 표시하며 주소·계좌·예금주는 등록 완료 안내로 대신합니다. `등록 정보 다시 보기`는 현재 메모리의 확인된 정보를 읽기 전용으로 표시하고 `완료 화면으로 돌아가기`로 복귀합니다. 재진입 후 확인 화면도 최소 성공 요약만 표시합니다.
- 조회 ID가 없거나 형식이 잘못된 완료 진입, 결과 없음(404), 현재 접근 거부(403)는 `/start`로 돌아가며 새 등록 폼을 자동으로 열지 않습니다. 인증 만료 / 계정 이용 불가는 로그인으로 이동합니다. 조회의 일시 장애는 이전 정보 없이 결과 재확인 / 시작 화면 이동만 제공하며 POST를 재전송하지 않습니다. 제출 결과가 불명확한 요청의 404 복구와 완료 페이지의 404 처리를 구분합니다.
- 시작 화면의 `pagehide`에서 개인정보가 있는 페이지를 숨기고 입력을 차단합니다. `pageshow.persisted`로 bfcache 문서가 복원되면 새 문서에서 세션과 등록 결과를 다시 확인해 로그아웃 전 화면이나 다른 계정의 정보를 그대로 복원하지 않습니다.
- `관리자 대시보드로 이동`은 성공 결과의 관리대상 ID로 `/manage/[propertyId]/dashboard`에 연결합니다. 공통 레이아웃은 현재 관리 권한 API로 관리자 역할을 확인한 뒤 사이드바와 `임시 페이지`를 표시합니다. 상세 정보 재조회는 후속 범위입니다.

### 관리 영역 연결과 후속 조회

관리 화면은 [서비스 진입 설계](serviceEntry.md#현재-조회-연결)와 [관리 레이아웃 설계](managementLayout.md)를 따릅니다. [관리 영역 접근 API](../../docs/managementAccessApi.md)로 현재 목록과 역할을 확인하며 등록 당시 스냅샷으로 대체하지 않습니다.

일반 `/start`의 자동 진입 분기를 추가하더라도 등록 완료 페이지는 버튼을 누를 때까지 유지합니다. 진행 중 결과 확인·동일 요청 복구와 명시적인 추가 등록을 보존하는 연결 기준은 [서비스 진입 설계](serviceEntry.md#6-기존-등록-흐름과-연결)를 참조합니다.

## 2. 기본 정보 검증과 단계 이동

1. 첫 단계에서 입력의 필수 여부와 길이를 확인합니다. 같은 입력 규칙을 Server에서도 검증합니다.
2. `등록하고 계속`을 선택하면 기존 `authenticatedAPI()`로 검증 요청을 보내고, 응답 대기 중에는 같은 버튼의 중복 요청을 막습니다.
3. 성공하면 정리한 입력을 Client 초안에 반영하고 동 / 세대 단계로 이동합니다. 입력 오류와 일시 장애에는 현재 단계와 입력을 유지하며 인증 / 계정 오류에는 공통 API 계약과 아래 오류 표시 기준을 적용합니다.
4. 이전으로 돌아가면 초안의 기본 정보를 표시합니다. 수정 후 다시 다음으로 이동할 때 기본 정보를 재검증합니다.

기본 정보 검증에는 업무 데이터 쓰기가 없으므로 요청 중 취소나 통신 단절로 부분 등록이 생기지 않습니다. 최종 제출을 시작한 이후에는 아래 결과 확인 절차를 적용합니다.

## 3. 초안과 제출 상태

초안은 현재 사용자 / 탭 / 등록 흐름 단위로 입력과 현재 단계를 관리합니다. 브라우저 임시 저장의 구체적인 구현과 탭 복구 동작은 확정 정책을 만족하는지 Client 구현에서 검증합니다.

| 상태 | Client 처리 |
| --- | --- |
| 입력 중 | 단계 이동과 새로고침에 입력 / 현재 단계 유지, 취소 / 이탈 / 탭 닫기 / 로그아웃 시 초안 폐기 |
| 기본 정보 검증 중 | 같은 검증 버튼의 중복 입력 차단, 실패 시 현재 입력 유지 |
| 최종 제출 중 | 제출 ID / 본문을 고정하고 중복 입력과 초안 수정을 막음 |
| 결과 확인 중 | 저장 결과를 모르는 상태로 표시, 기존 ID로 결과 조회 또는 동일 본문 재시도 |
| 저장 완료 | 성공 응답을 확인하고 초안 / 제출 본문을 폐기한 뒤 완료 표시, 확인한 대상의 임시 대시보드로 이동 가능 |

최종 제출 직전에 requestId를 생성하고 제출 당시 본문을 고정합니다. 통신 재시도와 Access Token 재발급 후 재시도에는 같은 ID / 본문을 사용합니다. 명확한 검증 실패나 결과 조회의 404 뒤에는 입력 수정을 허용하고 같은 ID로 다시 제출합니다. 늦게 완료된 기존 요청과 본문이 다르면 서버의 충돌 응답 뒤 기존 성공 결과를 조회하며 수정 중인 초안을 저장된 상세로 표시하지 않습니다. 조회 자체가 실패한 경우에는 결과를 먼저 다시 확인합니다.

현재 탭에서 최종 제출 중 새로고침하면 제출 ID와 제출 당시 본문도 복원합니다. 최종 저장은 Server가 기본 정보를 포함한 전체 입력을 재검증하므로 첫 단계의 검증 응답을 저장 권한이나 검증 생략의 근거로 사용하지 않습니다.

탭 닫기 / 로그아웃으로 입력 초안을 폐기하더라도 이미 시작된 요청의 커밋을 취소하지 않습니다. 제출 후 결과가 불명확하면 민감한 본문과 구분해 최소한의 결과 확인 정보인 사용자 ID / requestId를 관리하고 재로그인도 같은 사용자에서만 조회합니다. 다른 계정에 이전 입력이나 결과를 전달하지 않습니다.

`model/registrationSubmission`은 `sessionStorage`의 제출 기록에 사용자 ID / 고정 본문을 보관하며 같은 사용자·탭의 새로고침에서만 복원합니다. 저장소 본문도 자료형과 단계별 검증을 재적용해 손상된 본문을 재전송하지 않습니다. `localStorage`에는 사용자별 키의 requestId만 보관해 같은 사용자의 재로그인 / 재진입에서 조회할 수 있게 하며 계좌·예금주·입력 본문·토큰은 기록하지 않습니다. 이탈 / 로그아웃에서는 제출 본문을 폐기하고 미확인 ID는 결과 확인까지 유지합니다. 앱의 등록 초안 수명 컴포넌트는 전체 문서 이동으로 등록 흐름 밖에 진입한 경우에도 입력 / 제출 본문 / 완료 조회 기록을 정리합니다. 본문이 없는 미확인 요청의 재진입에서는 먼저 결과를 조회하고 404이면 기본 정보부터 다시 입력하게 합니다. 이전 ID를 유지해 재제출하므로 404를 이전 요청의 취소나 새 ID 발급의 근거로 사용하지 않습니다. 완료 기록에는 사용자 ID / requestId만 저장하며 브라우저의 성공 요약을 신뢰하지 않습니다. 이전 버전의 기록도 ID만 읽고 반드시 서버 조회를 거칩니다. 등록 성공 후 관리대상 목록 캐시를 무효화하며 이미 성공한 등록을 자동 삭제하거나 권한 해제로 처리하지 않습니다.

## 4. 오류 표시와 재시도

| 오류 | Client 처리 |
| --- | --- |
| 기본 정보 검증의 INVALID_REQUEST | 현재 입력 유지, 입력 기준 / 형식 확인 안내 |
| 기본 정보 검증의 통신 실패 / 일시 장애 | 현재 입력 유지, 다음 단계 이동 없이 검증 재시도 |
| 최종 등록의 INVALID_REQUEST | 실패 모달에서 안전한 사유 안내, 입력 수정 선택 시 해당 단계로 이동 |
| ACCESS_TOKEN_EXPIRED | 기존 authenticatedAPI가 같은 요청을 재발급 후 1회 재시도 |
| SESSION_EXPIRED / 인증 필요 | 기존 로그인 흐름 적용, 미확인 제출은 같은 사용자 재로그인 후 기존 requestId로 조회 |
| ACCOUNT_UNAVAILABLE | 초안 폐기, 기존 계정 이용 불가 흐름 적용 |
| ACCESS_DENIED | 미확인 제출은 접근 거부 안내, 완료 페이지 재진입은 시작 화면 이동, 과거 ADMIN 스냅샷으로 현재 권한을 복구하지 않음 |
| REGISTRATION_REQUEST_CONFLICT | 같은 ID로 본문을 덮어쓰지 않고 기존 성공 결과 확인 |
| REGISTRATION_IN_PROGRESS | 기존 ID로 결과 조회, 조회 결과에 따라 복구 |
| 미확인 제출 결과 조회의 404 | 입력 잠금 해제 가능, 본문이 있으면 같은 정보 재시도 / 입력 수정, 본문이 없으면 기본 정보부터 재입력, 모든 재제출은 기존 ID 유지 |
| 완료 페이지 재진입 조회의 404 | 시작 화면 이동, 새 등록 폼을 자동으로 열거나 이전 요청을 재제출하지 않음 |
| 최종 제출의 NETWORK_ERROR / INVALID_RESPONSE / HTTP_ERROR / 500 / 503 | 저장 실패로 단정하지 않고 결과 조회, 조회 자체가 실패하면 새 ID 생성 보류 |

최종 제출의 공통 전송 함수 15초 타임아웃도 결과가 불명확한 통신 실패로 처리합니다. 인증 / 서버 오류에서 검증 성공으로 다음 단계에 이동하지 않습니다. 201 / 200 / GET 성공 응답의 requestId·식별자·요약 자료형을 확인한 뒤 완료를 표시합니다. 이후 property.id 기반 임시 대시보드 연결은 위 관리 영역 연결 기준을 따릅니다. 관리대상 목록과 현재 관리자 권한 조회도 연결했습니다.

ApiError는 HTTP 상태와 최상위 오류 코드에 더해 형식과 허용 reason이 확인된 errors의 field / reason만 보존합니다. 응답 메시지·원문·입력값과 잘못된 경로는 포함하지 않습니다. 메시지는 API 코드 / reason을 기준으로 표시하고 민감한 응답 원문을 그대로 노출하지 않습니다.

## 5. 구현 시 검증

- 기본 정보의 정상 입력 / 선택 필드 / 공백 정리와 검증 실패 시 입력 유지, 검증 버튼의 중복 요청 차단.
- PC 모달과 모바일 페이지의 공통 폼 사용, 라벨 / 설명 / 오류 연결과 반응형 표시.
- 이전 / 다음 이동과 새로고침 복원, 취소 / 이탈 / 탭 닫기 / 로그아웃 이후 초안 폐기, 계정 변경 시 초안 격리.
- 동 추가 / 수정 후 clientId 연결 유지와 세대 참조, 배열 순서 유지, 공용계좌 기본 지정과 항목 금액 검증.
- 제출 중 입력 잠금, 같은 requestId / 본문의 재시도, 제출 중 새로고침 후 요청 복원.
- 입력 오류의 단계 이동 / 필드 안내, 응답 유실 시 조회와 동일 요청 재시도, 다른 사용자에게 결과 확인 정보가 전달되지 않음.
- 저장 전 확인 화면과 저장 성공 표시의 구분, 성공한 property.id로 진입하고 초안을 폐기함.
- 완료 주소의 직접 진입 / 새로고침 / 뒤로가기에서 서버 재검증, 저장소 요약 조작·권한 해제·다른 사용자·비로그인 접근 차단, 조회 장애의 재확인과 캐시 복원 시 세션 재확인.

기본 정보, 동·세대, 관리계좌와 관리비 항목 화면의 사용자 상호작용, 중복 / 참조 검증, 새로고침 복원과 API 경계는 `tests/propertyRegistration.spec.ts`에서 검증합니다. 정수 금액 / 최종 합계 경계와 상쇄는 `tests/feeItems.spec.ts`에서 브라우저 없이 검증합니다. 검증 명령과 작성 규칙은 [Client AGENTS.md](../AGENTS.md)를 따릅니다. 등록 확인의 반응형 요약·전체 계좌번호 표시·수정 단계 이동과 순서 진행, 최종 저장의 중복 클릭 차단·응답 유실·404 재시도·제출 중 새로고침·입력 오류·사용자 격리·손상된 제출 기록·잘못된 성공 응답도 같은 테스트에서 검증합니다. 임시 관리 영역 진입과 공통 사이드바 동작은 `tests/managementLayout.spec.ts`에 목록 / 현재 권한 조회와 함께 검증을 작성했습니다.
