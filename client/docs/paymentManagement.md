# 입금 관리 화면과 서버 연결

상태: 2026-10-16, **실제 수납 API·DB 연결 구현**. 회계전표·환급은 후속 범위입니다. 사용자가 제공한 HTML과 입금 확인·매칭 / 월별 수납 현황 이미지를 기준으로 기존 관리 레이아웃에 적용했습니다.

2026-10-17 후속: 사이드바는 [통장 관리](bankingManagement.md)로 통합했습니다. `/banking/*`의 입금·월별 수납 상세도 PC 중앙 ClientModal·모바일 독립 페이지 기준을 적용합니다. 통장 업로드와 거래 설정의 최신 흐름은 통장 관리 화면 문서를 따릅니다. 수납 계산·상태·입력 검증은 새 경로에서도 재사용합니다.


## 사용자 요청과 화면 구성

- 수동 입금 등록과 은행 거래 파일 가져오기를 병행합니다.
- 확인 필요·보류·처리 완료·기타 입금·취소 이력은 선택한 글씨 색과 밑줄만 강조합니다. 탭 배경을 채우지 않습니다.
- 은행 입금은 명단의 이름·동호수가 한 세대에 일치하면 가져오기에서 자동 확정합니다. 수동은 용도를 먼저 선택하며 세대 관리비에서만 선택 세대의 대표 이름을 자동 입력합니다. 기타·동별 입금은 세대 없이 입금자명을 입력합니다. 세대 선택은 동·호수로 표시하고 대표·가족 이름과 동·호수로 검색합니다. 월별 표에는 세대 대표를 표시하며 2026-10-31 후속 요청으로 최근 입금자 열은 제거했습니다. 거래 표의 추천 이유 열과 상세의 추천 근거 문구는 표시하지 않습니다.
- `입금 확인·매칭`은 전체 너비의 거래 표로 구성합니다. 상세는 PC 중앙 ClientModal, 모바일(767px 이하) 독립 상세 페이지로 엽니다.
- 모바일 입금·월별 수납 상세는 [모바일 상세페이지 절대 규칙](../AGENTS.md#모바일-상세페이지-절대-규칙)을 따릅니다. 공통 헤더의 `<` 뒤로가기로 해당 목록에 복귀하고 본문·푸터의 목록 버튼은 제공하지 않습니다. 직접 접근·새로고침·대상 없음에도 헤더 뒤로가기를 유지합니다.
- 기존 DataTable의 행 클릭으로 상세를 엽니다. 확인·보기·상세 버튼 열을 두지 않고 키보드 Enter·Space로도 같은 상세를 엽니다. 세대 후보와 처리·납부 상태는 뱃지로 구분합니다.
- 월별 표·합계·다운로드는 조회월에 실제 발행된 `ISSUED` 청구의 세대만 포함합니다. 수동 등록과 입금 상세의 세대 선택은 후속 요청에 따라 입금월의 청구 유무와 관계없이 현재 사용 중 명단의 세대를 표시합니다. 취소·공실 제외·해당 월 청구가 없는 세대는 표시하지 않고 `부과 제외` 상태를 제거합니다. 숫자 20을 고정하지 않고 실제 청구의 세대 ID로 판정합니다. 과거 원장과 수납·배분은 삭제하지 않으며 과거월 조회도 그 월의 실제 부과 대상에 맞춥니다.
- `월별 수납 현황`은 전월 이월액·당월 발생액·당월 수납 반영액·월말 미수금, 세대별 표와 계산식을 제공합니다.
- 페이지 맨 위 ListHeader에 제목·설명과 주요 행동을 두고 조회 월·검색은 아래에 둡니다. 월별 수납의 조회 기간은 MonthRangePicker, 입금 확인·매칭의 조회 기간은 DateRangePicker를 사용합니다. 두 기간 선택기는 CalendarRangePicker를 공유하고, 실제 입금일 입력은 CalendarPicker의 날짜 모드를 유지합니다. 검색창은 남는 폭을 채우고 작은 화면에서는 컨트롤을 줄바꿈합니다. 공통 달력은 입력의 왼쪽에서 열고 본문·모달·뷰포트 경계 안에 위치시킵니다. 아래 공간이 부족하면 위로 열며 날짜·월 버튼은 달력에 맞는 높이를 사용합니다.
- 2026-10-16 후속 요청에 따라 두 목록에 기본 10개·10/20/50개 표시 선택과 표 아래 공통 Pagination을 적용했습니다. 입금 확인·매칭은 조회 월·검색·동 필터·표시 개수 순서로 배치합니다. 동 필터는 검색 오른쪽의 `전체 동 / 실제 동 이름`이며 숫자 순서로 나열합니다. 세대 후보는 동·호수 숫자 오름차순, 후보 없음은 마지막에 표시하며 제목 클릭 정렬은 제공하지 않습니다. 월별 수납도 조회 월·검색·동 필터·표시 개수 순서로 배치하고 동 필터는 검색 오른쪽에 둡니다. 입금 확인·매칭의 `전체 / 엑셀 / 수동` 출처 필터는 제거하고 표의 출처 정보는 유지합니다. 월별 수납 현황의 중복된 `미수 있는 세대만` 체크박스도 제거합니다.
- 두 목록의 처리·납부 상태는 공통 `FilterTabs`로 목록 상단에서 글자·밑줄만 강조하며 검색 줄과 분리합니다. 월별 수납의 상태는 `전체 / 미납 / 일부납부 / 선입금 / 납부완료`이며 각 탭에 `(세대 수)`를 표시합니다. 숫자는 선택한 동·검색 조건에 해당하는 세대를 상태별로 집계하며 페이지 이동이나 선택 상태 탭 때문에 다른 탭 숫자를 줄이지 않습니다. 요약 카드는 선택 기간의 전체 범위를 유지합니다. 여러 달의 상태별 건수는 세대·월별 행 수입니다. 일반 다운로드는 현재 상태 탭·검색·동 조건의 전체 세대를 내보내며, 후속 선택 다운로드는 편집에서 고른 세대로 범위를 좁힙니다. 검색·조회 월·동·상태·표시 개수를 변경하면 첫 페이지로 이동하고 수납 처리로 목록이 줄어들면 유효 페이지로 조정합니다. 페이지 이동은 표의 행만 나누며 요약 집계와 현재 조회 조건의 전체 엑셀 다운로드 범위를 바꾸지 않습니다. 수납 상세의 최근 입금일은 다른 금액 행처럼 오른쪽에 정렬하고 값이 없어도 `—`를 같은 위치에 표시합니다.
- 엑셀 다운로드 버튼은 [Client 공통 엑셀 규칙](../AGENTS.md#4-ui--design)에 따라 흰 배경·초록 글자·테두리·Excel 아이콘을 사용합니다. 모바일 월별 수납 화면에서는 버튼 하나가 한 줄 전체 너비를 채웁니다.
- 별도의 미납 관리 이동 버튼과 계좌 필터를 추가하지 않습니다. 계좌 설정 기능은 입금 화면의 책임이 아닙니다.
- Dropdown / SelectDropdown의 선택 해제 X는 표시하지 않습니다. 모달은 뷰포트 중앙에 배치하며 우측 상단 X로 닫습니다. 푸터 행동 버튼은 간격을 두고 오른쪽 정렬합니다.
- 입금 처리 상세의 PC 모달은 지출 상세와 같이 제목·우측 상단 X를 스크롤 영역 밖에 두고 본문만 스크롤합니다. 기타 입금에도 하단 닫기 버튼을 두지 않으며 모바일은 기존 헤더 뒤로가기를 사용합니다.
- 납부기한은 실제 월말입니다. 취소 / 공실 제외 청구는 배분·미수금 집계에서 제외하되 현재 공실 세대의 과거 유효 청구는 유지합니다.

업무 기준은 [도메인 규칙](../../docs/domainRules.md#6-수납--수납-배분--납부-상태), 데이터 구조는 [ERD](../../docs/erd.md#81-payments)를 참조합니다.

## 월별 수납 상세 표시 규칙

2026-10-16 첨부 이미지를 참고해 요약·계산 내역·수납 정보·안내를 분리했습니다. 사용자가 위임한 상태별 색상은 기존 의미 색상 기준으로 정하며 목록 배지와 상세가 같은 색상 매핑을 공유합니다. 금액과 납부 상태는 아래 누적 수납 계산을 사용합니다.

| 납부 상태 | 요약 강조 | 핵심 금액 |
| --- | --- | --- |
| 미납 | Danger 빨강 | 조회월 말 기준 남은 미납금액 |
| 일부납부 | Warning 주황 | 조회월 말 기준 남은 미납금액 |
| 납부완료 | Success 초록 | 당월 관리비에 확정 반영된 수납액 |
| 정산 확인 필요 | Sub Text 회색 | 0원·음수를 보존한 당월 부과금액 |

- 요약에는 상태 배지·핵심 금액·해당 월 말일 납부기한을 표시합니다. Warning은 기존 토큰을 Main Text와 혼합해 밝은 배경에서도 큰 금액을 읽을 수 있도록 하며 별도 색상을 추가하지 않습니다.
- 계산 내역은 전월 이월 미수금·당월 관리비 발생액·당월 수납 반영액·남은 미납금액 순서입니다. 부과는 양수일 때 `＋`, 수납 반영액은 `−`를 금액 앞에 표시하며 음수 부과의 원래 부호를 유지합니다. 수납 반영액은 초록, 마지막 미납금액 행은 중립색 배경·기본 본문색으로 구분합니다.
- 수납 정보는 세대 대표·선입금 잔액·최근 입금일이며 최근 입금자 항목은 제거했습니다. 원본 입금자명을 대표 이름으로 바꾸지 않습니다. 금액과 날짜는 오른쪽 정렬합니다. 확정 수납이 없으면 `확정 수납 없음`, 날짜는 `—`로 표시합니다.
- 은행 입금 총액과 청구에 반영한 수납액은 구분합니다. 수납 내역이 있어도 미납 상태를 초록으로 바꾸지 않으며, 초과입금은 선입금으로 별도 표시합니다. 0원·음수 부과를 납부완료나 선입금으로 표현하지 않습니다.
- PC 모달은 내부 스크롤 중에도 제목·우측 상단 X를 유지하며 하단 닫기 버튼을 추가하지 않습니다. 모바일은 같은 상세 내용을 사용하고 [모바일 상세페이지 절대 규칙](../AGENTS.md#모바일-상세페이지-절대-규칙)을 유지합니다.


## 최근·전체 입금 내역

- 수납 상세에는 `최근 입금 내역`을 최신순 최대 3건 표시합니다. 날짜·원본 입금자·금액과 `전체 N건`을 보여줍니다.
- 범위는 조회월 말까지 해당 세대의 확정 입금입니다. 취소·미확정·조회월 이후 입금은 제외합니다. 수납·선입금 계산은 표시 개수와 관계없이 전체 유효 입금을 사용합니다.
- 입금이 없으면 `전체 0건`과 빈 내역 안내를 표시합니다.
- `전체 내역` 버튼은 `/banking/monthly/[month]/[unitId]/receipts` 페이지로 연결합니다. PC·모바일 모두 독립 페이지이며 직접 접근·새로고침을 지원합니다. 기존 `/payments/monthly` 경로도 같은 화면을 사용합니다.
- 전체 내역은 날짜·입금자·금액·확정 상태를 최신순으로 표시합니다. 연도 필터, 10/20/50개 표시, 페이지 이동을 제공합니다.
- PC의 `목록`은 조회월·세대를 유지해 원래 수납 상세 모달을 엽니다. 모바일은 공통 헤더 `<`로 수납 상세 페이지에 복귀합니다. 본문 복귀 버튼은 없습니다.
- 전체 내역 화면은 관리 목록의 가로폭·ListHeader·DataTable·Pagination 규격을 사용합니다. 표 16px, 페이지 건수·수납 배지 14px는 공통 컴포넌트에서 관리합니다. 별도의 좁은 최대 폭이나 작은 글씨 규격을 만들지 않습니다.
- 버튼명은 [Client 공통 규칙](../AGENTS.md#4-ui--design)에 따라 짧게 씁니다. 이동 설명을 버튼 문장으로 붙이지 않습니다.

## 누적 수납·자동 확정·삭제 (2026-10-16 후속 요청)

사용자는 같은 달 추가 입금도 모두 누적하고 명단에 이름·동호수가 일치하면 자동 확정하며 선입금으로 다음 달 납부를 처리하도록 요청했습니다. 상세에는 `몇 월 관리비로 반영할까요?`·`오래된 미납부터 추천`·월별 반영액 입력을 표시하지 않습니다. `수납 확정`은 세대만 지정하며 미납이 없어도 누를 수 있습니다.

- 파일 가져오기에서 유일한 명단 일치 입금은 자동 확정합니다. 미일치·동명이인·기존 수동 수납 중복 의심만 확인 필요로 남깁니다. 기존 PENDING을 한 번에 처리하는 구현 행동은 `일치 입금 자동 확정` 버튼입니다.
- 삭제는 목록의 `편집 → 행 체크 → 선택 삭제`로 제공합니다. 같은 DataTable에 편집 중에만 체크박스 열을 표시합니다. 현재 페이지 전체 선택과 개별 선택을 지원하고 조회 월·상태·검색·표시 개수·페이지를 바꾸면 선택을 초기화합니다. 확인창은 `취소 / 삭제`이며 실패하면 체크와 확인창을 유지합니다. 삭제한 미확정 입금은 같은 엑셀로 다시 가져올 수 있습니다. 상세에는 중복 삭제 버튼을 두지 않고 확정 입금에 `납부 취소`를 제공합니다.
- 상세의 확정·납부 취소·보류·해제·연결과 목록 선택 삭제의 요청 실패는 공통 오류 Toast로 표시합니다. 붉은 오류 문단을 남기지 않고 같은 실패 재시도 때 표시 시간을 다시 시작합니다. 선택 삭제 안내에 `미확정 입금만 삭제할 수 있습니다` 문구는 표시하지 않습니다.
- 조회월 수납 반영액에는 이전 선입금의 충당도 포함하며 초과분은 선입금으로 표시합니다. 실제 은행 입금월과 청구 충당월을 같은 것으로 취급하지 않습니다.

## 현재 구현과 제한

- `screens/payment/matching`, `screens/payment/monthly`가 `widgets/payment-workspace`를 공유합니다. payments 레이아웃의 PaymentWorkspaceProvider가 계정·관리대상별 실제 원장을 인증 API로 조회합니다. 성공한 저장 응답만 캐시에 반영하며 조회 장애를 예시 데이터로 대체하지 않습니다. 새로고침하면 DB 결과를 다시 조회합니다.
- 세대 선택과 누적 부과·기존 입금·이번 입금·반영 후 미납·선입금을 브라우저에서 검토하며 등록·확정·보류·해제·취소·원본 연결은 [입금 API](../../docs/paymentApi.md)로 처리합니다. 저장 중 중복 클릭·모달 닫기를 막고 실패하면 입력을 유지합니다. 다른 관리대상의 응답과 잘못된 금액·참조는 거부합니다.
- 수동 입력의 요청 ID는 폼을 유지하는 동안 재사용합니다. 사용 중인 실제 입금 통장과 용도를 선택하고 세대 관리비는 대표 이름, 기타·동별 입금은 직접 입력한 입금자를 사용합니다. 동별 배분과 화면 전환은 [통장 Client 설계](bankingManagement.md#수동-입금-용도와-동별-직접-입금-2026-10-18)를 참조합니다.
- 은행 파일은 FileDropzone에서 드롭 또는 선택하고 서버 미리보기 후 같은 파일을 서버로 다시 보내 가져옵니다. 검증·지원 형식·한도·중복 정책은 API 계약을 따릅니다. 브라우저 파일 파서는 실제 저장 경로에서 사용하지 않습니다.
- 은행에서 받은 `.xls`·`.xlsx`·UTF-8 CSV 원본을 서버에 그대로 전달합니다. 제목·계좌 안내가 있는 거래내역의 머리글 탐색과 입출금 양식의 적요 매핑을 지원하며, 안내·파일 선택 확장자·오류 문구도 [입금 API](../../docs/paymentApi.md#은행-파일추천중복)에 맞춥니다. 미리보기에는 양수 입금만 표시하며 출금을 수납으로 가져오지 않습니다.
- 월별 표는 조회월까지의 실제 양수 발행 청구와 월말까지의 확정 입금 전액을 누적해 계산하며 수납 취소 후 이월도 다시 계산됩니다. 입금 전액과 청구 충당액을 구분하고 초과분은 선입금 잔액으로 별도 표시합니다. 0원·음수 부과액은 원 금액과 정산 확인 상태를 유지하며 일반 배분·환급으로 처리하지 않습니다.
- 선입금은 다음 실제 청구 생성 때 자동 충당합니다. 환급·부분 취소·마감 후 정정·회계전표는 구현하지 않습니다. 선택월 수납표는 XLSX로 내보냅니다.

가져오기 성공 후 서버 응답에서 새 입금의 상태와 거래월을 확인합니다. 확인 필요가 있으면 해당 월·상태로, 모두 자동 확정되었다면 처리 완료·해당 거래월로 이동합니다. 성공했지만 빈 목록만 보이는 상황을 방지합니다.

## 검증

`tests/paymentPreview.spec.ts`는 월말·금액·배분 한도·취소·중복 연결·월별 이월을 검증합니다. `tests/paymentFlow.spec.ts`는 기존 헤더 순서, 선택 해제 X 미표시, 월·날짜 달력, 중앙 모달·모바일 상세 경로, 반응형 배치, 검색창의 공간 사용, 열린 달력의 경계, 드래그·파일 선택 후 중복 가져오기와 수납표 연결을 검증하는 브라우저 시나리오입니다. 두 목록의 여러 페이지 이동·10/20/50개 선택·필터 변경 시 첫 페이지 복귀·빈 목록·요약 집계 유지와 최근 입금일의 빈 값 정렬도 확인합니다. 실행 결과는 완료 보고에서 별도로 구분합니다.

XLS 브라우저 시나리오는 파일 선택 허용·서버 미리보기와 가져오기에 원본 바이트 전달·결과 목록 표시를 검증합니다. 브라우저 테스트의 서버 응답은 모의 처리하며 실제 XLS 파싱·수납 저장·재업로드 중복은 Server 테스트에서 검증합니다.

## 세대 외 기타 입금

은행 입금 상세의 `입금 분류`에서 세대 납부·기타 입금을 선택합니다. 기타 입금은 세대 선택과 누적 수납 미리보기를 숨기고 필수 항목명·선택 메모를 입력합니다. 원본 입금자·금액·날짜·메모는 유지합니다. 확정 요청 실패는 공통 오류 Toast로 안내하고 입력을 보존합니다.

기타 입금으로 확정하면 별도 `기타 입금 (건수)` 탭으로 이동합니다. 같은 월 선택·페이지네이션을 재사용하고 입금자·항목·메모·금액으로 검색합니다. 동 귀속이 없으므로 기타 탭의 동 필터는 비활성화하고, 이전 동 선택 때문에 기타 입금이 사라지지 않게 합니다. 합계·건수는 기타 입금 확정액만 표시하며 세대 수납·선입금 요약과 월별 수납·내보내기에는 포함하지 않습니다.

기타 상세는 `확정 취소`를 제공하며 사유 입력 후 원본이 확인 필요로 돌아갑니다. 취소 이력에서 기존 항목·메모·사유를 조회하고 다시 분류할 수 있습니다. 모바일 상세는 헤더 뒤로가기를 유지합니다. PC·390px·320px 브라우저 시나리오에서 확정·검색·합계 분리·취소·화면 폭을 확인합니다.

## 은행 미리보기 선택과 페이지네이션

사용자의 후속 요청에 따라 미리보기는 10건씩 공통 Pagination으로 표시합니다. 처음에는 모든 후보가 선택되고 행 체크를 해제하면 이번 가져오기에서만 제외합니다. 현재 페이지 전체 선택·해제와 전체 후보 선택·해제를 구분하며 페이지를 이동해도 다른 페이지의 선택을 보존합니다. 선택·제외 건수와 가져오기 버튼의 실제 선택 건수를 표시하고 0건이면 가져오기를 막습니다.

파일을 교체하거나 모달을 새로 열면 페이지·선택·중복 건수를 초기화합니다. 요청 실패는 오류 Toast로 표시하고 파일·페이지·체크를 유지해 재시도합니다. 원본 파일과 선택한 미리보기 ID를 서버에 함께 전달하며 제외한 거래를 먼저 저장한 뒤 화면에서 숨기는 방식으로 처리하지 않습니다. 제외 건은 다음 업로드 때 다시 선택할 수 있습니다.

## 월별 실제 입금 합계

월별 화면은 기존 부과·충당·미수 요약과 별도로 세대 입금액·기타 입금액·전체 입금액과 기타 입금 건수를 표시합니다. `getMonthlyPreviewIncome`은 선택월의 확정 입금을 실제 입금일로 합산하고 일부납부·선입금도 포함합니다. 월말 충당액·전월 이월액을 더해 실제 입금을 중복 집계하지 않습니다. 검색·동 필터와 독립적인 전체 월 합계임을 표시하며 월 선택 시 갱신합니다. 세대 납부 표·상세·기존 수납 엑셀은 청구·세대 기준을 유지합니다.

기타 입금 메모를 비운 경우 클라이언트는 선택 필드를 생략하고 서버도 빈 값을 미입력으로 정리합니다. 빈 메모 확정과 월별 합계·취소 제외, 미리보기 25건의 페이지 이동·선택 유지·실패 재시도를 브라우저에서 검증합니다.

## 기존 잔액 표시 (2026-10-17)

초기 미수는 당월 신규 부과액과 구분해 이월 잔액에 포함하며 초기 선납은 잔액·납부 상태에만 반영합니다. 실제 입금 목록과 월별 은행 입금 합계에는 포함하지 않습니다. 당월 실제 부과가 없어도 조회월 이하 초기 미수가 있는 세대는 조회할 수 있습니다. 2026-11-01 후속 요청으로 초기 선납만 있고 아직 신규 청구가 없는 세대도 조회월 말 잔액이 남으면 월별 표에서 확인합니다. [공통 계약](../../docs/paymentApi.md#기존-잔액-연결-2026-10-17)을 참조합니다.

### 월별 수납 모바일 배치 보완 (2026-10-17)

실제 입금 합계의 세 카드는 좁은 본문에서 위 두 개·아래 전체 너비 한 개로 표시한다. 기존 네 개 부과·미수 요약은 두 열을 유지한다. 세대별 월별 수납 표는 세대 열 너비 150px·동호수 줄바꿈 방지·표 최소 너비 1100px로 제공하며 작은 화면에서는 표 영역만 가로 스크롤한다. 숫자나 동·호수를 한 글자씩 잘라 페이지 폭에 맞추지 않는다.

월별 수납현황 XLSX는 [공통 엑셀 보고서 서식](excelReports.md)을 사용합니다. 일반 상태에서는 선택한 상태 탭(2026-11-01 선입금 탭 추가)과 현재 검색·동 조건의 전체 세대를 내보냅니다. 편집 중에는 선택한 월·세대 행만 같은 조건 안에서 내보냅니다. 페이지에 보이는 행 수로 제한하지 않으며 합계도 내보낸 세대만 집계합니다. 파일명에 조회월과 상태를 포함하고 보고서에는 상태·동·검색 조건을 기록합니다. 이월·당월 발생·수납 반영·미수·선입금 계산은 유지합니다.


## 월별 수납 보고서 미리보기·다운로드 (2026-10-31)

사용자 요청에 따라 월별 수납 헤더의 `다운로드`에서 Excel·PDF·이미지(PNG) 형식을 선택하고 실제 파일을 미리본 뒤 저장합니다. 기존 동별 입출금의 `ReportDownload`·한국어 PDF 글꼴·이미지 변환을 재사용합니다. 제목과 파일명은 현재 권한에서 확인한 빌라·공동주택 이름을 사용하고 서비스 이름을 관리대상 이름으로 대신하지 않습니다.

일반 다운로드는 선택 월·납부 상태·검색·동 조건의 전체 세대를 포함합니다. 아래 선택 다운로드에서는 같은 조건 안에서 고른 세대만 포함합니다. 목록의 페이지·표시 개수로 범위를 줄이지 않으며 전월 이월액·당월 발생액·당월 수납 반영액·미수금의 기존 계산을 재사용하며 선택한 납부 상태에 필요한 열과 합계만 보고서에 표시합니다. `정산 확인 필요`를 0원 또는 납부완료로 바꾸지 않으며 실제 통장 입금액을 청구 충당액과 섞지 않습니다. 열기 시점의 원장·빌라 이름·조회 조건·조회시각을 함께 보관해 미리보기와 저장 범위가 일치하도록 구성했습니다.

PDF·이미지는 첨부 시안에 맞춰 큰 빌라 제목·옅은 건물 장식·의미 색상의 금액 카드·납부 상태 배지·합계 행을 적용합니다. Excel은 한 시트를 유지하면서 같은 금액 카드·열·합계와 상태별 셀 색상으로 구성하며 최근 입금자 열은 모든 보고서에서 제외합니다. 선입금 잔액 열은 기존 전체·미납·일부납부·납부완료 보고서에서 제외하고 2026-11-01 추가한 선입금 전용 보고서에만 표시합니다. 미납은 전월 이월액·당월 발생액·미수금 잔액의 카드 3개와 세대·대표·이월·발생·미수·상태의 6개 열입니다. 납부완료는 미수금 잔액 카드·열을 생략하고 이월·발생·수납 반영액을 표시합니다. 전체·일부납부는 수납 반영액과 미수금을 함께 표시합니다. PDF·이미지는 A4 가로·본문과 표 헤더 14.5pt·합계 15.5pt·행 높이 최소 17mm로 출력하고 모든 세대를 페이지에 나누어 담습니다. 한 장인 이미지는 PNG로, 여러 장은 번호를 붙인 PNG 전체를 ZIP으로 저장합니다. 빈 결과도 조회 조건과 0건 안내를 표시하며 파일 생성 실패·재시도·닫기와 포커스 복귀는 공통 다운로드 UI를 따릅니다.

최근 입금자 제거는 월별 목록·상세의 표시와 해당 검색 필드에 적용합니다. 실제 입금 거래의 입금자명은 입금 확인·명단 매칭·원본 이력을 위해 유지하며 세대 대표 이름으로 덮어쓰지 않습니다. 보고서의 선입금 열 제거는 기존 선입금 계산·조회·충당 동작을 변경하지 않습니다.

조회 월은 PDF·이미지에서 달력 표식과 18pt 굵은 글씨로 분리하고 Excel에서도 20pt 독립 행으로 강조합니다. 세대 수·기간 상태·조회시각은 옆의 보조 정보로 표시합니다.

표 경계선은 후속 요청에 따라 PDF·이미지에서 Sub Text 색상의 0.3mm 선으로, Excel에서는 같은 색상의 중간 굵기 선으로 표시합니다. 금액의 오른쪽 정렬은 유지합니다.


## 선입금 보유 세대 (2026-11-01)

사용자 요청으로 월별 수납현황에 당월 미부과 선입금 보유 세대를 포함합니다. `선입금 (세대 수)` 탭은 월말 선입금 잔액이 양수인 세대의 필터입니다. 당월 부과 없는 잔액 보유 행은 선입금, 당월 관리비가 모두 충당된 행은 선입금 잔액 유무와 관계없이 납부완료로 표시하므로 두 필터의 대상은 겹칠 수 있습니다. 당월 부과 없는 세대의 상태는 `선입금`으로 표시하고 행 클릭으로 PC 모달·모바일 상세에서 잔액과 실제 입금 내역을 확인합니다. 검색·동 조건과 페이지네이션을 함께 적용하며 상태별 건수는 검색·동 범위에서 집계합니다.

선입금 탭의 Excel·PDF·이미지와 미리보기에는 선입금 잔액 열·합계를 추가합니다. 기존 전체·미납·일부납부·납부완료 보고서의 열 구성은 유지합니다. 선입금 잔액 계산·기존 인계값·취소·미래 입금 제외 기준은 [도메인 정책](../../docs/domainRules.md#월별-수납의-선입금-보유-세대-조회-2026-11-01)을 참조합니다.


같은 날 후속 요청으로 상태 탭은 `전체 → 미납 → 일부납부 → 선입금 → 납부완료` 순서입니다. 선입금 탭의 표는 세대·대표·선입금 잔액·상태·최근 입금일만, 보고서는 세대·대표·선입금 잔액·상태만 표시합니다. 전월 이월액·당월 발생액 열과 그 요약 카드는 선입금 보고서에서 제외합니다. 잔액은 당월까지의 청구를 충당한 뒤 남은 금액이므로 당월 발생액을 다시 빼지 않습니다. 예를 들어 선입금 70,000원에서 당월 관리비 50,000원을 충당했다면 잔액 20,000원을 표시합니다.


2026-11-01 검증: ESLint·TypeScript 타입 검사·Next.js 프로덕션 빌드 통과. API/모델 검사 126개와 주민 상세·인계·월별 수납·다운로드 관련 프로덕션 브라우저 검사 31개 통과. 선입금 전용 PDF의 열·차감 후 잔액과 PNG 다운로드도 확인했습니다.


## 선입금의 다음 달 음수 이월·배지 (2026-11-01)

사용자 확인은 다음 **달** 전월 이월액입니다. 월별 표의 이월액은 이전 양수 청구 누계에서 전월 말 확정 입금·인계 선납을 뺀 순액으로 음수를 보존하고 붉게 표시합니다. 합계 카드 명칭은 전월 이월액이며 음수 합계도 붉게 표시합니다. 수납 상세의 계산용 전월 미수금은 양수 부분만 사용하고, 전월 선입금은 별도 수납 정보에 음수·붉은색으로 표시해 충당액을 두 번 빼지 않습니다. Excel·PDF·이미지에도 같은 음수 이월과 붉은색을 적용합니다.

후속 사용자 요청으로 배지는 변경 전의 당월 납부 상태 기준으로 되돌립니다. 부과 없이 선입금 잔액만 있는 행은 선입금, 당월 관리비를 모두 충당한 행은 납부완료입니다. 남은 선입금 잔액은 잔액 열·선입금 필터에서 별도로 확인하며 납부완료 필터와 겹칠 수 있습니다. 정산 확인 필요의 우선순위와 원장·실제 입금 금액은 유지합니다. 목록에는 보조 문구를 붙이지 않습니다.


## 월별 수납 선택 다운로드 (2026-11-01)

사용자 요구: 월별 수납 목록의 `편집` 글씨로 세대를 선택하고 선택한 세대만 다운로드합니다. 기존 다운로드 형식·보고서·미리보기를 재사용하며 수납 원장은 변경하지 않습니다.

구현 동작: 월·검색·동·표시 개수 아래 오른쪽에 텍스트 `편집`을 표시합니다. 편집 중에는 체크박스 열과 선택 건수를 표시하고 행 클릭·Enter·Space도 선택을 전환합니다. 선택 키는 월과 세대 ID의 조합이며 같은 세대의 다른 월은 독립 선택합니다. 표 머리 체크박스는 현재 페이지를 선택·해제하고 다른 페이지에서 고른 세대는 유지합니다. 페이지·표시 개수 변경은 선택을 유지하며 조회 월·검색·동·상태 변경과 `완료`는 선택을 해제합니다.

상단 버튼은 편집 중 `선택 다운로드`로 표시하고 선택이 없으면 비활성화합니다. 일반 상태에서는 기존 전체 조건 다운로드를 유지합니다. 보고서를 열 때 선택 ID를 복사해 원장·월·필터와 함께 고정합니다. Excel·PDF·PNG의 행·조회 세대 수·합계 모두 조회 조건과 선택 ID의 교집합만 사용하며 `선택 N세대`(단일 월) 또는 `선택 N건`(월 범위) 범위와 파일명으로 구분합니다. 미선택 ID·중복 ID·조회에서 제외된 세대는 포함하지 않고, 빈 선택을 전체 세대 출력으로 해석하지 않습니다. 전체 월 요약 카드와 실제 입금 합계는 기존 조회 범위를 유지합니다.


## 월 기간·날짜 기간 공통 조회 (2026-11-01)

사용자 요구: 월별 수납 현황은 한 달로 제한하지 않고 시작 월부터 종료 월까지 조회합니다. 예를 들어 `2026-11 ~ 2027-03`의 양 끝 월을 포함합니다. 통장 거래·지출·입금 확인은 일 단위 기간도 선택할 수 있어야 합니다. 월별 행은 최신 월부터 표시하며 같은 월 안에서는 기존 세대 순서를 유지합니다.

구현: `CalendarRangePicker`가 시안의 빠른 선택·시작/종료 입력·취소/조회를 공유합니다. 월별 수납은 `MonthRangePicker`, 실제 입출금 목록은 `DateRangePicker`를 연결합니다. 기존 단일 `month` 주소도 유지하며 조회 후에는 각각 `startMonth/endMonth`, `startDate/endDate`를 저장합니다. 날짜 입력·부과 대상 단일 월 등은 기존 달력을 유지합니다. 역전된 기간은 적용하지 않고 취소·Escape는 편집 전 조건을 유지합니다.

여러 달의 수납 표·Excel·PDF·PNG에는 부과 월을 함께 표시합니다. 발생액·수납 반영액만 기간 합산하고 이월은 시작 월, 미수·선입금은 종료 월의 잔액으로 표시합니다. 같은 잔액을 매달 더하지 않습니다. 선택 다운로드는 월·세대 행만 포함하고 선택 내역의 첫 월·마지막 월을 잔액 집계 기준으로 보고서에 기록합니다. 미선택 편집 상태는 다운로드를 막고 전체 출력으로 바꾸지 않습니다. PDF·PNG의 기간 상자는 연도 포함 범위의 실제 폭에 맞추고 조회 시각과 겹치지 않게 배치하며 화살표를 넣지 않습니다.

상태 판단은 [선입금의 음수 이월과 납부 상태](../../docs/domainRules.md#선입금의-음수-이월과-납부-상태-2026-11-01)를 따릅니다. 목록에는 상태 배지만 표시하며 전월 선입금의 충당 후 잔액 설명은 상세에서 제공합니다.

조회 기간 패널의 빠른 선택과 하단 버튼은 불투명 배경과 테두리로 구분합니다. 빠른 선택의 선택 상태와 조회 버튼은 Primary 채움으로 표시하며 호버 시 배경·테두리가 변하지 않습니다. 키보드 포커스 표시는 유지합니다.


## 선입금의 당월 수납 표시 (2026-11-01 최종 정정)

[최종 수납 표시 규칙](../../docs/domainRules.md#선입금의-월별-수납-표시-기준-2026-11-01-최종-정정)에 따라 상단의 신규 청구·청구 납부반영액·당월 청구 미수금을 같은 집합으로 계산합니다. 이전 선입금으로 충당한 금액도 그달 수납이며 100만원 청구에 5만원 충당이면 미수는 95만원입니다. 납부 배지도 해당 월 청구의 충당 여부를 사용합니다. 기존 이월·누적 미수 원장과 실제 통장 입금은 보존합니다. 임의로 추가했던 이월 구성·별도 보관 문구는 표시하지 않습니다. 대시보드 카드·그래프는 같은 공개 계산을 재사용합니다.
