# 입금 관리 화면과 서버 연결

상태: 2026-10-16, **실제 수납 API·DB 연결 구현**. 회계전표·선입금 자동 충당·환급은 후속 범위입니다. 사용자가 제공한 HTML과 입금 확인·매칭 / 월별 수납 현황 이미지를 기준으로 기존 관리 레이아웃에 적용했습니다.

## 사용자 요청과 화면 구성

- 수동 입금 등록과 은행 거래 파일 가져오기를 병행합니다.
- 확인 필요·보류·처리 완료·취소 이력은 선택한 글씨 색과 밑줄만 강조합니다. 탭 배경을 채우지 않습니다.
- 입금자 추천은 현재 대표 주민을 기준으로 하고 수동 입금자명은 선택 세대의 대표로 자동 입력합니다. 세대 선택과 월별 표에는 동·호수만 표시하며 주민 이름을 붙이지 않습니다. 거래 표의 추천 이유 열과 상세의 추천 근거 문구는 표시하지 않습니다.
- `입금 확인·매칭`은 전체 너비의 거래 표로 구성합니다. 상세는 PC 중앙 ClientModal, 모바일(767px 이하) 독립 상세 페이지로 엽니다.
- 기존 DataTable의 행 클릭으로 상세를 엽니다. 확인·보기·상세 버튼 열을 두지 않고 키보드 Enter·Space로도 같은 상세를 엽니다. 세대 후보와 처리·납부 상태는 뱃지로 구분합니다.
- 월별 표·합계·다운로드는 조회월에 실제 발행된 `ISSUED` 청구의 세대만 포함합니다. 수동 등록과 입금 상세의 세대 선택은 입금일이 속한 월의 실제 부과 세대로 제한하며 수동 등록은 현재 사용 중 세대 조건도 유지합니다. 취소·공실 제외·해당 월 청구가 없는 세대는 표시하지 않고 `부과 제외` 상태를 제거합니다. 숫자 20을 고정하지 않고 실제 청구의 세대 ID로 판정합니다. 과거 원장과 수납·배분은 삭제하지 않으며 과거월 조회도 그 월의 실제 부과 대상에 맞춥니다.
- `월별 수납 현황`은 전월 이월액·당월 발생액·당월 수납 반영액·월말 미수금, 세대별 표와 계산식을 제공합니다.
- 페이지 맨 위 ListHeader에 제목·설명과 주요 행동을 두고 조회 월·검색은 아래에 둡니다. 조회 월은 MonthPicker, 입금일은 CalendarPicker의 날짜 모드를 사용해 공통 달력으로 통일합니다. 월·검색·출처는 같은 필터 영역에 배치하고 검색창이 남는 폭을 채웁니다. 작은 화면에서는 컨트롤을 줄바꿈합니다. 공통 달력은 입력의 왼쪽에서 열고 본문·모달·뷰포트 경계 안에 위치시킵니다. 아래 공간이 부족하면 위로 열며 날짜·월 버튼은 달력에 맞는 높이를 사용합니다.
- 별도의 미납 관리 이동 버튼과 계좌 필터를 추가하지 않습니다. 계좌 설정 기능은 입금 화면의 책임이 아닙니다.
- Dropdown / SelectDropdown의 선택 해제 X는 표시하지 않습니다. 모달은 뷰포트 중앙에 배치하며 우측 상단 X로 닫습니다. 푸터 행동 버튼은 간격을 두고 오른쪽 정렬합니다.
- 납부기한은 실제 월말입니다. 취소 / 공실 제외 청구는 배분·미수금 집계에서 제외하되 현재 공실 세대의 과거 유효 청구는 유지합니다.

업무 기준은 [도메인 규칙](../../docs/domainRules.md#6-수납--수납-배분--납부-상태), 데이터 구조는 [ERD](../../docs/erd.md#81-payments)를 참조합니다.

## 현재 구현과 제한

- `screens/payment/matching`, `screens/payment/monthly`가 `widgets/payment-workspace`를 공유합니다. payments 레이아웃의 PaymentWorkspaceProvider가 계정·관리대상별 실제 원장을 인증 API로 조회합니다. 성공한 저장 응답만 캐시에 반영하며 조회 장애를 예시 데이터로 대체하지 않습니다. 새로고침하면 DB 결과를 다시 조회합니다.
- 초안 입력과 추천 배분은 브라우저에서 검토하며 등록·확정·보류·해제·취소·원본 연결은 [입금 API](../../docs/paymentApi.md)로 처리합니다. 저장 중 중복 클릭·모달 닫기를 막고 실패하면 입력을 유지합니다. 다른 관리대상의 응답과 잘못된 금액·참조는 거부합니다.
- 수동 입력의 요청 ID는 폼을 유지하는 동안 재사용하며 입금자는 선택 세대의 현재 대표로 표시합니다. 계좌는 서버의 공용 기본 계좌를 사용하며 설정 입력을 추가하지 않습니다.
- 은행 파일은 FileDropzone에서 드롭 또는 선택하고 서버 미리보기 후 같은 파일을 서버로 다시 보내 가져옵니다. 검증·지원 형식·한도·중복 정책은 API 계약을 따릅니다. 브라우저 파일 파서는 실제 저장 경로에서 사용하지 않습니다.
- 월별 표는 실제 발행 청구와 유효 수납 배분을 기준으로 계산하며 수납 취소 후 이월도 다시 계산됩니다. 입금 전액과 청구 충당액을 구분하고 초과분은 선입금 잔액으로 별도 표시합니다. 0원·음수 부과액은 원 금액과 정산 확인 상태를 유지하며 일반 배분·환급으로 처리하지 않습니다.
- 선입금 자동 충당·환급·부분 취소·마감 후 정정·회계전표는 이번 화면/API에서 구현하지 않습니다. 선택월 수납표는 XLSX로 내보냅니다.

이전 단계의 독립 HTML 참고 시안은 [paymentPrototype.html](paymentPrototype.html)입니다. 단독 시안은 제공된 HTML의 독립 샘플 원장을 사용하며 실제 프로젝트와 데이터를 공유하지 않습니다. 현재 화면·공통 달력·드래그 업로드·서버 연결의 기준은 위 Client 구현이며 이전 HTML에 같은 변경이 적용됐다는 의미는 아닙니다.

## 검증

`tests/paymentPreview.spec.ts`는 월말·금액·배분 한도·취소·중복 연결·월별 이월을 검증합니다. `tests/paymentFlow.spec.ts`는 기존 헤더 순서, 선택 해제 X 미표시, 월·날짜 달력, 중앙 모달·모바일 상세 경로, 반응형 배치, 검색창의 공간 사용, 열린 달력의 경계, 드래그·파일 선택 후 중복 가져오기와 수납표 연결을 검증하는 브라우저 시나리오입니다. 실행 결과는 완료 보고에서 별도로 구분합니다.
