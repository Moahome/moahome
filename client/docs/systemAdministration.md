# 시스템 관리 화면

2026-11-03 구현. 운영 배포는 중지 상태입니다. 정책·API는 [공통 계약](../../docs/api/systemAdministration.md)을 참조합니다.

- `/admin`: 회원 검색·목록. `/admin/administrators`: 시스템 관리자 목록. `/admin/members/[userId]`: 모바일 회원 상세입니다.
- 프로필과 모바일 메뉴에 시스템 관리자만 `시스템 관리` 링크를 표시합니다. 특정 관리대상이 없는 계정도 같은 진입점을 사용합니다. 서버 API는 현재 역할을 별도로 검사합니다.
- PC 목록의 행 클릭은 공통 ClientModal, 모바일은 독립 상세 경로를 사용합니다. 모바일 헤더 뒤로가기는 실제 방문 기록으로 복귀하며 직접 진입 시 `/admin`으로 대체합니다.
- 상세는 전체 계정 UUID로 대상을 식별하고 생성 권한 부여·회수와 시스템 관리자 승격을 별도 행동으로 제공합니다. 최종 확인 전에는 쓰기 요청을 보내지 않습니다. 승격만으로 생성 허용을 표시하지 않습니다.
- 검색·페이지·표시 개수는 URL에 보관합니다. 목록·상세는 로그인 계정 ID가 포함된 Query 키를 사용하며 계정 전환 시 하위 화면을 다시 만듭니다. 로그아웃 시 기존 공통 Query 캐시 정리를 적용합니다.
- 저장 실패는 확인창과 요청 UUID를 유지합니다. 상태 충돌은 최신 회원을 다시 조회하고 이전 요청을 자동 적용하지 않습니다. 성공하면 회원·관리자 목록·상세·본인 세션을 무효화해 서버 결과를 다시 읽습니다.
- 2026-11-08 사용자 요청으로 시작·추가 등록 화면의 만들기 카드와 설정의 빌라 등록 항목은 `canCreateProperty`가 true인 계정에만 표시합니다. 플랫폼 ADMIN 또는 기존 관리소장이라는 이유로 생성 진입을 표시하지 않습니다. 생성 버튼은 최신 본인 정보로 허용 여부를 다시 확인합니다. 직접 등록 경로의 미허용 계정은 등록 입력 대신 권한 안내를 표시합니다. 이미 전송한 등록의 결과 복구와 완료 조회는 유지하며 실제 신규 저장 여부는 서버에서 판정합니다. 기존 관리계좌·관리 업무 권한은 생성 허용과 별개이며, 초대 참여는 권한과 무관하게 유지합니다.
- 이전 API 응답에 생성 허용 필드가 없으면 허용으로 추정하지 않습니다. 정상 신규 API는 `canCreateProperty`를 반환합니다.
- 탈퇴 유예 계정(`WITHDRAWAL_PENDING`)도 목록·상세에서 조회하며 `탈퇴 유예`로 표시합니다. 해당 계정의 생성 권한 변경·관리자 승격은 비활성화하고 서버의 정상 계정 검증도 유지합니다.

개발 서버의 `/preview/membership`은 기존 `/properties/add?creationPreview=disabled`로 연결합니다. 복제한 설정·등록 폼을 만들지 않고 실제 StartPage에서 생성 진입만 숨깁니다. 실제 설정도 `/manage/{propertyId}/settings?creationPreview=disabled`에서 같은 표시 상태를 확인할 수 있습니다. 계정의 실제 권한·서버 인증은 변경하지 않으며, 이 매개변수는 권한이 없는 계정의 생성을 허용하지 않습니다. 미리보기 별칭 경로는 production에서 404이고 production 화면은 표시용 매개변수를 무시합니다.
