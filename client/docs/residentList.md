# Client 주민 목록

갱신일: 2026-10-10. 주민 목록·등록·상세·수정·삭제·엑셀 업로드 화면과 조회·저장 API를 구현했습니다. 업무 기준은 [도메인 규칙](../../docs/domainRules.md#확정된-주민-목록-조회), 데이터 구조는 [주민 명부](../../docs/erd.md#54-residents)와 [세대 주민 관계](../../docs/erd.md#55-unit_residents), 요청·응답·오류는 [주민 관리 API](../../docs/residentManagementApi.md)를 따릅니다.

## 1. 사용자 요청과 구현 범위

- 관리소장용 주민 목록을 `/manage/[propertyId]/residents`에 연결합니다.
- 삭제되지 않은 주민 전체를 표시합니다. 주민의 활성·비활성 상태 필터는 제공하지 않고 가입 상태 필터는 별도로 제공합니다.
- 목록과 기본 상세의 연락처는 끝 4자리만 표시하며 상세의 공개 버튼으로 전체 번호를 확인합니다.
- 한 세대에 여러 주민이 있으면 주민마다 한 행을 표시합니다. 각 주민의 현재 동·호수는 하나만 표시하며 과거 세대를 합산하지 않습니다.
- 개별 등록·상세·수정·삭제·엑셀 업로드를 구현했습니다. 세대 목록의 주민 정보 연동을 구현했으며 별도 대표 변경은 후속 범위입니다.
- 주민 등록 버튼을 제공하며 웹에서는 공통 모달, 모바일에서는 `/manage/[propertyId]/residents/new` 별도 페이지로 엽니다. 동일한 등록 폼을 공유합니다.

## 2. 현재 화면

| 영역 | 구현 |
| --- | --- |
| 요약 카드 | 전체 주민·가입 완료·미가입·승인 대기. 필터와 페이지에 관계없이 조회한 전체 명부 기준 |
| 필터 | 이름·연락처 끝 4자리·동/호수 검색, 동·주민 구분·가입 상태와 초기화 |
| 표 위 | 필터 결과 수, 엑셀 다운로드와 10 / 20 / 50명씩 보기 |
| 표 | 주민명·연락처·동·호수·주민 구분·대표 주민·가입 상태 |
| 표 아래 | 세대 목록에서 분리한 공통 페이지네이션. 표시 범위와 페이지 이동 |

가입 상태는 서버의 `signupStatus`를 받아 카드·표·필터에서 동일하게 사용합니다. 판정 기준은 [API의 가입 상태 판정](../../docs/residentManagementApi.md#가입-상태-판정)을 따릅니다. 승인 대기는 사용자 결정에 따라 명부에서 확인된 주민만 집계합니다. 미확인 신청자는 주민으로 추가하지 않습니다.

전체 주민은 세 가지 가입 상태의 합이며, 검색·필터를 적용해도 카드 집계는 전체 명부를 유지합니다. PC에서는 네 카드를 한 줄에, 모바일에서는 두 열에 배치합니다. 가입 완료는 등록 화면과 공유하는 공통 체크 아이콘, 승인 대기는 공통 Warning 색상과 시계 아이콘으로 표시합니다.

관리자의 주민 명부 등록과 주민의 서비스 가입은 구분합니다. 명부 등록만으로 서비스 가입이 완료되지는 않습니다. 가입 완료·확인된 대기 신청에 해당하지 않는 주민은 미가입이며, 확인된 가입 신청이 승인 전이면 승인 대기입니다.

주민 목록은 동 이름 → 호수의 숫자 순으로 정렬한 뒤 페이지를 나눕니다. 같은 동·호수의 주민은 이름·ID 순이며 소속이 없는 주민은 마지막에 표시합니다. 검색·필터 후에도 같은 정렬을 유지합니다.

동 필터는 서버의 등록·저장 순서를 그대로 쓰지 않고 세대 목록과 같은 공통 정렬 함수로 동 이름순으로 표시합니다. 숫자를 인식하므로 `2동 → 10동 → 101동 → 102동 → 103동` 순서이며 문자 동 이름도 같은 한국어 비교 기준을 사용합니다.

목록 조회에는 전화번호 전체를 브라우저로 전달하지 않습니다. `phoneLast4`만 받아 `•••• 1234`로 표시하며 값이 없으면 `—`로 표시합니다. 검색도 서버가 제공한 끝 4자리 범위에서 동작합니다.

동·호수는 동이 있으면 `103동 301호`, 동이 없으면 `301호`로 표시합니다. 현재 관계가 없거나 동·호수가 삭제되었으면 `—`로 표시하며 주민 행 자체는 유지합니다. 같은 301호에 김민수와 박서연이 있으면 두 행의 동·호수가 같고, 서버의 대표 여부가 참인 사람에게만 `대표` 배지를 표시합니다. 최초 지정과 변경 권한은 [확정된 세대 대표 지정과 변경](../../docs/domainRules.md#확정된-세대-대표-지정과-변경)을 따르며 이번 조회 화면이 대표를 지정하거나 변경하지는 않습니다.

동 구분을 사용하지 않거나 등록된 동이 0개인 관리대상에서는 동 필터를 숨기고 필터 배치도 맞춥니다. 표만 가로 스크롤되며 모바일에서도 페이지 전체가 화면 폭을 넘지 않도록 합니다. 조회 중·조회 실패·권한 거부·빈 명부·검색 결과 없음을 구분하고 실패 시 이전 명부를 표시하지 않습니다.

## 3. 구조와 상태

- 화면은 `screens/household/resident-list/`에 두고 라우트는 공개 `index.ts`로 연결합니다. 형제 `unit-list` 슬라이스를 직접 참조하지 않습니다.
- 목록과 엑셀 다운로드의 두 진입 UI는 `ui/resident-list-page/`, `ui/resident-export-page/`로 구분합니다. 두 진입점이 공유하는 미리보기는 `ui/_components/resident-export-preview/`에 두며 페이지별 전용 보조 UI는 해당 페이지 폴더 안에서 관리합니다. 진입 UI가 하나인 주민 등록·상세·업로드 화면은 각 슬라이스의 `ui/`에 바로 둡니다.
- 주민 구분 선택지는 `entities/resident/constants/residentOptions.ts`에 둡니다. `OWNER`의 표시 명칭은 `소유주`이며 기존 저장 값을 유지합니다.
- 등록·수정의 주민 구분 드롭다운에는 선택 해제 X를 표시하지 않고 다른 구분을 선택해 변경합니다.
- 카드·페이지네이션·표·입력·선택·버튼은 기존 `shared/ui` 공개 API를 사용합니다. 공통 UI는 주민 조회나 정책을 소유하지 않습니다.
- API는 관리대상의 명부 전체를 한 번 조회합니다. 세대 목록과 동일하게 화면에서 검색·필터·페이지 분할을 수행하며 필터·표시 개수 변경 시 첫 페이지로 이동합니다.
- 조회 키에는 현재 사용자와 관리대상 ID를 포함합니다. 저장소에 명부를 보관하지 않으며 잘못된 관리대상·중복 주민·전체 번호가 들어간 `phoneLast4` 등 계약에 맞지 않는 응답은 실패로 처리합니다.
- 관리 공통 틀의 접근권한과 주민 조회권한은 구분합니다. 부담당자도 공통 틀에는 접근할 수 있지만 주민 API는 관리소장만 허용합니다.

### 주민 목록 엑셀 다운로드

사용자가 요청한 `엑셀 다운로드` 버튼은 주민 목록에만 제공하며, 페이지당 표시 개수 드롭다운의 왼쪽에 배치합니다. 업로드와 다운로드의 색상·아이콘은 2026-10-16 후속 요청을 반영한 [Client 공통 엑셀 규칙](../AGENTS.md#4-ui--design)을 따릅니다. 모바일에서도 다운로드와 드롭다운을 같은 행의 왼쪽·오른쪽에 둡니다.

다운로드는 검색·필터·동호수 정렬이 적용된 **전체 결과**를 `주민_목록.xlsx`로 저장하며 현재 페이지로 제한하지 않습니다. 파일 열은 **주민명·연락처·동·호수** 세 개이며 미리보기에도 같은 세 열을 표시하되 연락처는 `**** 5678`처럼 끝 네 자리만 표시하고 미등록 번호는 `—`로 표시합니다. 엑셀 파일에는 전체 번호를 포함합니다. 주민 구분·대표 주민·가입 상태는 미리보기와 파일에서 모두 제외합니다. [별도 내보내기 API](../../docs/residentManagementApi.md#주민-목록-엑셀-다운로드)로 현재 대상 ID들을 전달해 관리소장 권한을 검증한 뒤 전체 번호를 조회합니다. 일반 목록 API의 마스킹 응답은 유지합니다.

버튼을 누르면 768px 이상에서는 공통 `ClientModal`, 모바일에서는 `/manage/[propertyId]/residents/export` 페이지와 공통 헤더의 `<`를 제공합니다. `resident-list` 슬라이스 안의 `ResidentExportPreview`를 두 진입점에서 공유합니다. 전체 건수와 처음 최대 5행을 표시하고 같은 응답의 전체 행을 다운로드합니다. 항목 선택 UI는 제공하지 않습니다. 실패는 고정 안내의 전역 하단 토스트와 재시도 버튼으로 처리하며 생성 중 중복 클릭을 차단합니다.

모바일 이동에는 현재 계정·관리대상별 메모리 캐시로 **주민 ID 목록만** 일시 전달하고 수신 페이지에서 즉시 캐시를 제거합니다. 전체 번호는 API 조회 캐시에 넣지 않고 미리보기 컴포넌트의 일시 상태에만 둡니다. 개인정보·검색어를 URL이나 브라우저 저장소에 기록하지 않습니다. 새로고침·직접 접근으로 전달 범위가 없으면 목록에서 다운로드를 다시 선택하도록 안내하며 임의로 전체 명부를 내보내지 않습니다. 닫기·이탈 시 원문 상태를 폐기합니다.

`model/residentExport.ts`가 세 열의 표시 값과 XLSX 생성을, `ui/_components/resident-export-preview/_utils/downloadResidents.ts`가 브라우저 저장과 임시 URL 해제를 담당합니다. `write-excel-file`은 실제 다운로드 시에만 불러옵니다. 연락처는 전체 국내 휴대폰 번호에 하이픈을 넣어 저장하고 미등록은 빈칸, 국제번호는 전체 값을 유지합니다. 모든 값을 문자열 셀로 저장해 앞자리 0과 수식처럼 시작하는 이름을 보존합니다.

첨부 `주민목록.xlsx`의 스타일을 기준으로 맑은 고딕, 굵은 회색 헤더(13pt·43 높이), 본문(12pt·32 높이), 흰색·옅은 회색 교차 행, 얇은 테두리와 가운데 정렬을 적용합니다. 첫 행을 고정하고 세 열의 너비는 16·20·23으로 설정합니다. 첨부 시트에 있는 나머지 열과 빈 입력 양식 시트는 내보내기에 포함하지 않습니다.

## 4. 개별 주민 등록

사용자 결정에 따라 이름·동·호수는 필수, 연락처·주민 구분은 선택입니다. 신규 폼의 주민 구분은 `기타`를 기본 선택하며 엑셀의 빈 구분도 `OTHER`로 저장합니다. 수정 폼은 기존 구분 값을 유지합니다. 필드 정규화·중복 기준·오류는 [등록 API 계약](../../docs/residentManagementApi.md#주민-등록)을 참조합니다.

- 화면 폭 768px 이상에서 목록의 등록 버튼은 모달을 열고 그 미만에서는 독립 등록 페이지로 이동합니다. 독립 주소는 직접 접근·새로고침도 지원합니다. 모바일 공통 헤더 왼쪽에는 `<`와 주민 등록 제목을 표시하며 뒤로가기는 같은 관리대상의 주민 목록으로 이동합니다.
- 목록은 관리소장 조회가 성공한 뒤 등록 버튼을 표시하고 독립 페이지는 현재 관리소장 역할을 확인합니다. 최종 권한과 세대 소속은 Server가 다시 검증합니다.
- `features/resident-management`는 두 진입점이 공유하는 입력·세대 조회·검증·저장을 소유합니다. `screens/household/resident-registration`은 독립 페이지를 조합하며 형제 목록 화면을 참조하지 않습니다.
- 동과 호수는 기존 저장된 목록에서 선택하며 이름순으로 정렬합니다. 동을 바꾸면 호수 선택을 초기화합니다. 동 없는 대상에서는 동 선택을 숨깁니다.
- 필수 입력·연락처 형식 오류는 필드에 표시하고 중복·권한·저장 실패는 고정 안내로 표시합니다. 실패에는 입력과 등록 요청 ID를 유지하고 취소·이탈·새로고침에는 초안을 폐기합니다. 저장 중에는 제출·취소·모달 닫기·Escape를 막습니다.
- `ClientModal`, `Button`, `Input`, `Dropdown`, `ServiceIcon`, `Toast`를 재사용합니다. 저장 중 모달 밖의 브라우저 이동을 막는 별도 초안 기능은 없습니다.
- 저장 성공 뒤 모달은 닫고 목록을 재조회합니다. 모바일은 목록으로 돌아와 새로 조회하며 잠시 성공 Toast를 표시합니다. 이동용 성공 쿼리는 표시 후 URL에서 제거하고 명부·전체 연락처를 저장소나 URL에 기록하지 않습니다.
- 대표 지정·가입 상태는 폼 입력으로 받지 않습니다. 서버가 저장한 결과를 목록에서 표시합니다.

## 5. 엑셀 업로드

사용자가 요청한 업로드 → 데이터 검증 → 등록 완료 흐름을 `/manage/[propertyId]/residents/import`의 독립 화면으로 구현했습니다. 주민 목록의 `엑셀 업로드` 버튼으로 이동하며 모바일 헤더의 `<`는 주민 목록으로 돌아갑니다. 최종 대표 지정·오류/중복 제외 정책은 [확정 도메인 규칙](../../docs/domainRules.md#확정된-주민-엑셀-일괄-등록)을 따릅니다. 아래는 현재 화면 구현입니다.

- 업로드: 파일 선택·드래그 앤 드롭, `.xlsx` 양식 다운로드와 작성 안내. 파일을 끌어 올리면 업로드 영역의 배경·테두리·아이콘과 안내 문구를 강조하고, 영역을 벗어나거나 파일을 놓으면 해제합니다. 자식 요소 사이를 이동해도 강조가 깜박이지 않으며 검증 중에는 다시 강조하거나 업로드하지 않습니다. 지원 형식·열·파일/행 제한은 [API 계약](../../docs/residentManagementApi.md#파일-검증)을 따릅니다. 다운로드 양식은 `public/residentImportTemplate.xlsx`에서 제공하며 사용자가 전달한 `주민 업로드 양식.xlsx`를 적용했습니다. 다운로드 이름도 `주민 업로드 양식.xlsx`입니다. 첫 시트에는 지정 열 헤더와 1,000행의 빈 입력 칸을 두며 안내는 두 번째 시트에 넣어 예시 주민을 실수로 등록하지 않도록 합니다. 호수·연락처 열은 텍스트 형식입니다.
- 파일 선택 버튼과 양식 다운로드 링크도 [Client 공통 엑셀 규칙](../AGENTS.md#4-ui--design)을 따릅니다. 업로드 영역의 큰 아이콘과 드래그 강조는 기존 녹색 토큰을 사용하며 영역의 SVG 색상을 버튼 안 아이콘에 덮어쓰지 않습니다. 양식 다운로드는 Excel 아이콘·호버 강조·키보드 포커스 표시를 제공합니다.
- 검증: 전체·등록 가능·중복 제외·오류 카드, 마스킹 표와 사유, 정상 행 선택·전체 선택, 이름/동/호수/끝 네 자리 검색·상태 필터·10/20/50명 페이지네이션. 오류와 중복은 선택할 수 없습니다. 검색이나 페이지 변경으로 다른 페이지의 선택을 지우지 않습니다.
- 저장: 선택한 원본 행 번호만 제출하고 중복 클릭을 막습니다. 응답 유실·장애 시 검증 ID와 선택을 유지하고 같은 요청 재시도 버튼을 제공합니다. 최초 저장 시도 후에는 선택을 잠가 재시도 대상을 바꾸지 않습니다.
- 사용자 요청에 따라 파일 형식·헤더·크기 검증 실패와 업로드·저장 요청 실패는 화면 하단 중앙의 공통 오류 토스트로 안내합니다. 같은 오류를 다시 받으면 토스트 표시 시간을 새로 시작합니다. 행별 검증 오류는 표의 사유에서 확인하며 하단 `주민 목록` 버튼은 작업 버튼 뒤 오른쪽에 배치합니다. 공통 기준은 [Client 알림 규칙](../AGENTS.md#공통-모달과-처리-알림)을 따릅니다.
- 완료: 전체·등록 성공·중복 제외·오류 카드와 행별 결과·대표 배지, 선택하지 않은 수, 주민 목록 이동·새 파일 등록·결과 CSV 다운로드를 제공합니다. 검증·완료 표와 CSV는 `엑셀 행` 열을 제외하고 `주민 구분`을 표시합니다. 원본 행 번호는 선택·저장 순서를 위한 내부 값으로 유지합니다. 결과는 전체 행을 포함하며 연락처는 끝 네 자리만 넣고 CSV 수식 실행을 방지합니다. 별도 다운로드 API는 없습니다.

`resident-import` 화면 슬라이스에서만 사용하는 API·상태·표·다운로드 코드를 소유하고 형제 목록 화면을 참조하지 않습니다. `SummaryCard`, `Pagination`, `DataTable`, `Input`, `Dropdown`, `Button`, `ServiceIcon`을 재사용하며 오류 카드에는 공통 Danger 토큰을 추가했습니다. 업로드는 공통 API의 multipart 전송과 기존 Bearer 재발급을 사용합니다.

파일·검증 결과는 화면 메모리에만 두고 localStorage·sessionStorage·URL에 쓰지 않습니다. 이탈·새로고침 시 화면 상태는 폐기되며 복원 기능은 없습니다. 저장 도중 이탈하면 일부 행이 저장되었을 수 있으므로 주민 목록에서 확인합니다. 완료 시 주민·세대 목록의 캐시를 무효화해 돌아갈 때 새로 조회합니다. 전체 전화번호가 들어간 `phoneLast4` 등 계약과 다른 응답은 표로 표시하지 않습니다.

## 6. 상세·수정·삭제

- 목록의 행 또는 주민명 버튼으로 상세를 엽니다. 768px 이상은 `ClientModal`, 모바일은 `/manage/[propertyId]/residents/[residentId]` 페이지와 공통 헤더의 `<`를 사용합니다. 새로고침·직접 접근을 지원하고 뒤로가기는 같은 관리대상의 주민 목록으로 이동합니다.
- 상세 푸터는 세대 상세와 같은 `shared/ui/detail-actions`를 사용합니다. 웹은 오른쪽에 `닫기 → 수정 → 삭제` 순서의 테두리 버튼을 두고 닫기는 중립색·수정은 Success·삭제는 Danger로 표시합니다. 상단 구분선·20px 여백·10px 버튼 간격을 공유하며 모바일 페이지는 `수정 → 삭제`를 같은 너비로 표시합니다. [모바일 상세페이지 절대 규칙](../AGENTS.md#모바일-상세페이지-절대-규칙)에 따라 복귀는 헤더의 `<`만 사용하며 목록 버튼을 두지 않습니다.
- 주민 수정 제출 버튼은 웹·모바일 모두 `수정`, 처리 중에는 `수정 중…`으로 표시합니다. 신규 등록은 `등록` / `등록 중…`을 유지합니다.
- 수정 진입·제출 버튼은 기존 세대 화면과 같은 공통 Success 색상의 글씨·테두리를 사용합니다. 기본 상세는 이름·마스킹 연락처·동·호수·주민 구분·대표·가입 상태·등록일을 표시합니다. `전체 번호 보기`는 별도 POST 요청으로 전체 번호를 가져오고 `번호 숨기기`로 마스킹합니다. 원문은 컴포넌트의 일시 상태에만 두며 조회 캐시·저장소·URL에 기록하지 않습니다. 상세를 다시 열거나 수정·삭제로 전환하면 공개 상태를 폐기합니다.
- 상세의 수정·삭제는 같은 모달 또는 페이지 안에서 전환합니다. 수정은 등록의 공통 폼을 재사용하며 연락처 유지·새 번호 입력·삭제를 구분합니다. 연결된 가입 신청이 있으면 연락처 삭제는 제공하지 않고 새 번호로 변경합니다. 번호 변경은 연결된 신청에도 함께 반영합니다.
- 대표를 다른 동·호수로 이동하거나 삭제할 때 남은 주민이 있으면 새 대표 선택을 필수로 받습니다. 임의의 주민을 기본 선택하지 않습니다. 기존 세대가 삭제되어 동·호수가 보이지 않아도 서버가 반환한 대표 승계 후보는 선택할 수 있습니다. 실패 시 입력·선택을 유지하고 저장 중 제출·닫기를 막습니다.
- 삭제 확인 화면의 제출 버튼 이름은 `삭제`입니다. [공통 삭제 버튼 규칙](../AGENTS.md#공통-모달과-처리-알림)에 따라 흰색 Card 배경·빨간 Danger 글씨·테두리를 사용하며 빨간 배경을 채우지 않습니다.
- 삭제 확인 후 성공하면 상세를 닫고 목록·카드를 재조회하며 공통 성공 토스트를 표시합니다. 해당 관리대상의 주민 접근권한도 종료한다는 안내를 확인 화면에 표시합니다.
- `features/resident-management`가 두 상세 진입점의 조회·번호 공개·수정·삭제와 등록/수정 폼을 공유합니다. 독립 페이지는 `screens/household/resident-detail`에서 조합합니다. 기본 상세 캐시도 현재 사용자·관리대상·주민별로 구분하며 미사용 시 보관하지 않습니다.

## 7. 후속 작업

아래 항목은 후속 구현 범위입니다.

- 별도 대표 변경: 삭제·이동 없이 대표만 바꾸는 기능은 후속 범위입니다.

작업 순서는 공통 카드·페이지네이션 분리 → 주민 목록 → 등록·상세·수정 → 세대 목록의 주민 정보 연동 → 엑셀 등록입니다. 목록·등록·엑셀 업로드·상세·수정·삭제를 구현했습니다. 세대 목록의 대표 주민·가입 인원 연동도 구현했으며 별도 대표 변경은 후속 범위입니다.

## 8. 검증

`tests/residentExport.spec.ts`는 실제 XLSX의 시트와 문자열 셀을 읽어 페이지 밖 주민의 포함·필터 제외·동호수 정렬·전체 연락처와 앞자리 0 보존·빈 연락처·수식 형태 이름의 문자열 저장·주민 구분/대표/가입 상태와 내부 ID 제외·시트 스타일를 확인합니다. 기존 `npm run test:api`에 포함합니다.

`tests/managementLayout.spec.ts`에 1440 / 375 / 320px 다운로드 모달·페이지·뒤로가기·세 열과 연락처 끝 네 자리 마스킹·필터 전체 범위·파일 저장·닫기/새로고침 시 원문 폐기를 검증하는 시나리오를 포함합니다.

`tests/managementLayout.spec.ts`에서 사람별 행과 같은 세대의 여러 주민, 대표 표시, 세 가지 가입 상태와 네 카드 집계, 마스킹, 검색·필터·페이지 이동·표시 개수, 동 없음, 조회 중·오류·재시도·권한 거부·빈 목록과 잘못된 연락처·가입 상태 응답을 검증합니다. 1440 / 375 / 320px에서 페이지 폭과 모바일 배치를 확인합니다. 추가로 웹 모달·모바일 페이지의 등록, 선택 연락처, 국내 번호 변환, 필수값 검증, 저장 중 닫기 차단, 실패·재시도·취소와 목록 갱신을 검증합니다. 실행 명령은 [Client 검사 규칙](../AGENTS.md#9-test--build)을 따릅니다.

엑셀 흐름은 1440 / 375 / 320px에서 파일 형식 사전 검증·multipart 전송·선택 제외·페이지와 검색·대표 결과·CSV 다운로드·모바일 뒤로가기를 검증합니다. 실패 재시도의 동일 선택 유지·잘못된 연락처 응답 거부·부담당자 직접 접근 차단과 공통 API의 파일 인증 재시도도 확인합니다. 파일/헤더 오류의 토스트 표시·화면 하단의 가로 중앙 배치·같은 오류의 표시 시간 갱신·자동 닫기, 하단 주민 목록 버튼의 명칭·오른쪽 정렬·목록 이동도 확인합니다.

상세는 1440 / 375 / 320px에서 웹 모달·모바일 페이지와 뒤로가기·번호 공개/숨김·재진입 마스킹·수정 실패 재시도·명시적 대표 선택 삭제·목록 갱신을 검증합니다. 잘못된 기본 응답과 번호 공개 실패에는 원문을 표시하지 않는지 확인합니다.

## 9. 목록 공통 구성

주민 목록과 세대 목록은 `shared/ui/list-header`(상위 메뉴명·제목·설명·오른쪽 버튼), `shared/ui/list-toolbar`(조회 건수·선택적 버튼 영역·페이지당 표시 개수), `shared/ui/list-card`(필터·툴바·표·페이지네이션의 배경·여백)를 공유합니다. 화면별 필터·열 정의·API·페이지 계산은 각 화면에서 관리합니다. `SummaryCard`, `DataTable`, `Pagination`도 기존 공통 컴포넌트를 유지합니다. 공통 성공 토스트는 진한 초록색 배경·흰 글씨로 화면 하단 중앙에 표시합니다.

### 삭제 후 명부 재입력

기존 등록 폼·엑셀 업로드에서 재등록을 처리합니다. 엑셀의 `READY` 재등록 행은 서버의 `재등록 가능 · 기존 주민 기록 재사용` 안내를 표시하고 기존 정상 행처럼 선택·저장할 수 있습니다. 검증만으로 목록을 복구하지 않습니다. 개별 등록 응답의 주민 ID는 요청 ID와 달라도 유효한 UUID·관리대상·세대이면 성공으로 처리하고 목록을 다시 조회합니다. 업무 기준과 중복·기존 ID 유지·권한 처리는 [주민 API](../../docs/residentManagementApi.md#주민-등록)를 따릅니다.
