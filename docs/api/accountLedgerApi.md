# 계정별 원장 API

상태: 2026-11-07 **기존 통장·미수·선수금·손익 원천 연결 구현**. [회계 확정 범위](../domain/domainRules.md#9-회계) 중 202 발생·지급 연결과 101 기초잔액 반영을 구현했습니다. 정식 자동전표·전 과목 이월 잔액·일반 정정·재처리는 남아 있습니다. 이번 조회를 전체 회계 구현 완료로 보지 않습니다. [손익계산서 API](incomeStatementApi.md)의 현재 분류·기간 기준을 그대로 사용합니다.

저장·누계는 [Server 설계](../../server/docs/accountLedger.md), 화면·다운로드는 [Client 설계](../../client/docs/accountLedger.md)를 참조합니다.

## 조회

`GET /api/properties/{propertyId}/accounting/ledger?startMonth=2026-10&endMonth=2026-11&accountIds={uuid},{uuid}&buildingId={uuid}`

ADMIN·MANAGER가 조회하며 응답은 `Cache-Control: no-store`입니다. 시작·종료 월은 함께 지정하거나 함께 생략하며 생략 시 한국 현재 월입니다. 포함 범위는 최대 120개월입니다. 과목·동 생략은 각각 전체 계정과목, 전체 동입니다. 과목과 동은 같은 관리대상 소속이어야 합니다. 회계 시작 전 기간을 임의로 잘라 합산하지 않습니다.

| 응답 | 의미 |
| --- | --- |
| `propertyId/propertyName/generatedAt` | 관리대상과 조회 시각 |
| `range/configuration/completeness` | 손익 API와 동일한 시작 설정·기간·자료 확인 상태 |
| `accountIds/accountId/buildingId/bankAccountId` | 적용된 과목 목록(전체는 빈 배열)·단일 선택 호환값·동·101 실제 계좌. 미선택은 null |
| `canManage` | 현재 ADMIN 변경 권한. MANAGER는 조회만 가능 |
| `supported` | 선택 과목의 현재 조회 지원 여부. 현재 모든 과목 true. 빈 목록과 오류는 구분 |
| `accounts/buildings` | 손익 API의 동일한 계정 ID·코드·이름·분류와 과거 삭제 동 |
| `rows` | 전체 조건의 최신순 거래. 각 행은 아래 `entry`·`cumulativeAmount`·`sourceIds`·`cashBalance` |
| `issues` | 같은 조회 조건에서 손익 API가 반환한 전체 과목의 미반영 원천. 귀속 미확인 거래를 선택 동에 임의 배분하지 않으며 선택 과목에만 해당한다고 보지 않음 |
| `revenue/expense` | 과목 필터까지 적용한 수익·비용 반영액, 서로 구분해 반환 |

`entry`는 `id/accountId/accountName/group/month/buildingId/amount/source`입니다. `month`는 회계 귀속 월이며 `amount`와 `cumulativeAmount`는 원 단위 정수 문자열입니다. 자산·부채는 증가 양수·감소 음수이며 수익·비용 합계에 섞지 않습니다. 기간 누계는 **같은 과목의 조회 시작 월부터 반영액 합계**이며 기초·기말 잔액이나 차변·대변 금액이 아닙니다. 서로 다른 과목의 누계를 더하지 않습니다.

`source`는 `{kind,id,date,time,name,context,path}`입니다. 원장 부과는 `kind=BILLING`, id=null이며 관리대상·귀속 월·과목 ID와 sourceIds로 식별합니다. sourceIds는 합계에 포함된 원본 `charge:{청구항목 UUID}` 배열입니다. 손익 kind는 `EXPENSE/OTHER_INCOME`이며 id는 각각 지출·수납 ID입니다. 자산·부채는 아래 표의 원본 종류, 미지급은 `PAYABLE`과 발생 ID를 사용합니다. 기존 손익 원천의 CHARGE는 청구 ID를 유지합니다. 부과는 기존 billing_periods.billing_date(현재 매월 1일)를 날짜로 반환하며 시각만 null입니다. 지출·입금은 실제 거래일·원본 시각(없으면 null)을 전달하고 시각은 표에 표시하지 않습니다. path는 기존 관리 화면의 상대 경로입니다. 401의 날짜 열은 부과일, 입출금 과목은 거래일, 혼합 조회는 일자로 표시합니다. 원장 부과는 월·과목별로 합산하며 전체 조회에서는 동들을 합쳐 한 행으로, 동 선택 시 해당 동의 합계로 반환합니다. 합계의 동은 전체 조회 시 null입니다. 부과의 path는 `/billing/monthly/history/{month}`이며 수납·미납 상세로 연결하지 않습니다. Client는 sourceIds에 해당하는 항목만 기존 부과 상세에서 확인합니다. 지출은 기존 거래 상세, 기타 입금은 수납 상세로 연결합니다. 기존 손익 응답의 `records[].source`에도 같은 정보를 추가하며 기존 필드는 유지합니다.

100·200번대는 기존 원본을 읽는 연결이며 정식 분개를 새로 생성하지 않습니다.

| 과목 | 연결 원본 |
| --- | --- |
| 101 통장 | 기존 유효 통장 원본·자동 상대 이체 행·수동 입출금. 동 선택은 기존 동별 입출금 배분 |
| 102 미수금 | 확정 청구·인계 미수 증가, 유효 수납·초기 선납 충당 감소, 외부 부담 원액·실제 회수 |
| 103 통장간 거래 | 기존 이체 posting의 계정 FK와 양쪽 행, 상대 은행 원본이 도착한 경우 자동 행을 중복하지 않음. 이전 양쪽 원본 연결 방식도 지원 |
| 201 선수금 | 입금일까지 청구에 충당하고 남은 초과 수납·기존 초기 선납과 이후 청구 충당 |
| 202 미지급금 | 등록 시 증가, 유효한 실제 출금 연결 시 감소. [발생·지급 API](payableApi.md) |

청구 원본은 당시 동·호수를 사용합니다. 입금 동 귀속은 수납의 저장된 cash_building_id를 사용하며 현재 세대 위치로 추측하지 않습니다. 인계 선수금은 기존 수납 작업공간의 세대 연결을 사용합니다. 충당의 반영일은 입금·인계 날짜와 대상 부과일 중 늦은 날이며 실제 은행 거래일로 표시하지 않습니다. 현재 유효 배분을 재구성하는 조회이며 처리 당시 이벤트 원장·마감 보존 자료가 아닙니다. 미수·선수금의 날짜 열은 반영일입니다. 외부 정산 제외를 채권 소멸로 보지 않습니다. 동 귀속이 없는 외부 부담은 전체 조회에서만 표시합니다.

정렬은 계정 코드 오름차순을 항상 유지합니다. 정렬 선택에는 최신순(기본)·오래된순만 있으며 같은 과목 안의 날짜·원본 시각 방향만 바꿉니다. 같은 날짜도 계산 기준의 정확한 역순을 보존하고 누계를 재계산하지 않습니다.

회계 시작 미설정·시작 전 조회와 지원하지 않는 과목의 rows는 빈 배열입니다. 이때 0원 요약을 정상 장부 잔액으로 표시하지 않습니다. 미확인 원천은 issues에 보존하고 반영액에 더하지 않습니다. `READY`도 현재 분류된 원천 조회 가능 상태이며 전표 대조·마감 완료를 뜻하지 않습니다.

## 오류와 변경 범위

인증·접근·기간·저장소 오류는 손익 API와 같습니다. 타 관리대상 또는 없는 계정 ID는 400 `INVALID_ACCOUNTING_ACCOUNT`입니다. 오류 본문은 `{code,message}`입니다. 조회 실패를 빈 목록·0원으로 대체하지 않습니다.

조회는 청구·입출금·기초 잔액·분류·전표를 생성하거나 수정하지 않습니다. 신규 Migration과 별도 회계 쓰기 API는 없습니다. 이후 분류 정정은 다음 과거 조회 결과도 바꿀 수 있으며 정식 전표의 당시 연결 고정·역분개를 구현한 것은 아닙니다.

### 다중 과목과 101 계좌·잔액

- `accountIds`는 쉼표 구분 또는 반복 UUID 목록입니다. 합집합으로 조회하고 같은 관리대상의 계정만 허용합니다. 생략은 전체, 중복 ID는 한 번 적용합니다. 기존 단일 `accountId`도 받으며 응답의 `accountId`는 정확히 하나 선택했을 때만 채웁니다.
- `bankAccountId`는 101 단독 조회에서만 받으며 현재 관리대상·조회 기간에 존재하는 실제 계좌를 검증합니다. 다른 과목·타 대상 계좌와 잘못된 UUID는 거부합니다.
- `bankBalances`는 계좌 필터 선택지를 위한 통장별 이름·기초·입금·출금·기간말 자료입니다. 별도 화면 표로 표시하지 않습니다. 통장 시작 근거는 기존 통장 잔고 계산을 재사용하며 미확인 금액을 0으로 대체하지 않습니다.
- 101의 `row.cashBalance.ledgerBalance`는 전체 계좌일 때 **101 합산 기초잔액 + 유효 입금 − 유효 출금**입니다. 특정 계좌를 선택하면 그 계좌만 계산합니다. 전체 범위의 내부 이체 양쪽은 한 사건으로 처리해 잔액 합계를 바꾸지 않습니다. 다른 과목의 `cumulativeAmount`는 기존 기간 누계입니다.
- `cashBalance.bankAccountId/bankAccountName`은 원본 계좌 연결 정보, `reportedBalance`는 원본에 저장된 은행 거래 후 잔액입니다. 화면·보고서에 계좌 열·은행 잔액 열·통장별 요약 표를 추가하지 않습니다. 101 합산 잔액을 개별 은행 원본 잔액으로 덮어쓰지 않습니다.
- 선택 목록은 숫자 코드순이고 무선택은 전체입니다. 다운로드·모바일 복귀에 모든 선택 과목과 101 계좌 조건을 보존합니다.
