# 관리자 대시보드 API

작성일: 2026-11-01. **상태: 전용 조회·화면 구현. 검증 결과는 Client 화면 문서에서 관리합니다.**

화면 배치·브라우저 상태·이동은 [Client 대시보드](../client/docs/dashboard.md), 업무 정책은 [도메인 규칙](domainRules.md), 저장 구조는 [ERD](erd.md)를 따릅니다.

## 조회 요청

`GET /api/properties/{propertyId}/dashboard?month=2026-11`

Bearer 인증과 해당 관리대상의 현재 ADMIN / MANAGER 권한을 확인합니다. 응답은 `Cache-Control: no-store`입니다. 주민과 다른 관리대상의 관리자는 조회할 수 없습니다.

| 입력 | 계약 |
| --- | --- |
| `propertyId` | 실제 관리대상 UUID |
| `month` | 선택. 기존 월 조회와 같은 `YYYY-MM`, 연도 1000~9999. 생략하면 서버 한국시간 현재 월 |

미래 월도 실제 저장된 자료만 조회하며 예정 청구를 생성하거나 금액을 예측하지 않습니다. 통장·동 필터는 대시보드 API에 추가하지 않습니다.

## 응답

| 필드 | 내용 |
| --- | --- |
| `propertyId`, `propertyName`, `month` | 관리대상과 실제 조회 월 |
| `generatedAt` | 조회를 구성한 ISO 8601 오프셋 시각 |
| `businessDate` | 서버 한국시간 조회 기준일 |
| `banking` | [기존 통장 Workspace](bankingManagement.md). 선택 월·조회 기준일 이내 거래만 반환하며 사용하지 않는 배분 규칙은 빈 배열 |
| `balances` | [잔고 Workspace](bankingManagement.md#동별-잔고외부-회수-api)의 선택 월·전체 통장 결과 |
| `payments` | [기존 수납 원장](paymentApi.md) 한 벌. 이월·선입금·6개월 계산을 위해 누적 범위 유지. 대시보드에 불필요한 처리 이력은 빈 배열 |
| `tasks.income` | 조회 기준일 이내 PENDING 은행 입금과 은행 미연결 PENDING 수동 입금 건수 |
| `tasks.expenses` | 조회 기준일 이내 PENDING 은행 출금 건수 |
| `tasks.joinRequests` | 실제 PENDING 주민 가입 신청 수 |
| `tasks.invitationChanges` | 개인 초대의 CHANGE_REQUESTED 정보 수정 요청 수 |
| `tasks.external` | 현재 월 잔고 조회의 누적 외부 부담금 중 정산 제외분을 뺀 양수 미회수 내역 수 |
| `tasks.duplicates` | 같은 통장·날짜·방향·금액의 은행 원본이 있는 미연결 수동 입금·지출 후보 수 |

최초 초안의 모든 요약을 서버에서 새 계산으로 만드는 대신 기존 업무 원장과 검증기를 재사용합니다. 원장을 월별로 6번 전송하지 않습니다. 금액은 원 단위 정수 문자열이고 Client 계산은 BigInt를 사용합니다. 연락처·계좌번호 원문·초대 인증값은 새 필드로 추가하지 않습니다.

## 지표와 집계

2026-11-01 후속 사용자 정정으로 상단은 **선택 월 신규 청구·청구 납부반영액·당월 청구 미수금**을 같은 집합으로 표시합니다. 최초 추천안의 실제 입금 카드와 전월 미수 포함 카드를 대체합니다.

| 지표 | 기준 |
| --- | --- |
| 선택 월 청구액 | 기존 월별 수납 대상의 선택 월 신규 발생액. 기존 미수 인계는 구분하고 0원·음수 원금액은 보존 |
| 청구 납부반영액 | 같은 신규 청구액에서 당월 청구 미수금을 뺀 금액. 이전 선입금에서 충당한 금액 포함 |
| 당월 청구 미수금 | 기존 누적 미수 중 선택 월 신규 양수 청구에 남은 부분. 세대별 `min(신규 양수 부과액, 누적 미수금)`을 합산 |
| 관리대상 부담 지출 | 선택 월 확정 지출의 동 부담액. 내부 이체·외부 부담·미분류 출금 제외 |
| 세대 납부 현황 | 기존 월별 수납 대상·납부 상태. 미부과 선입금 보유 세대는 도넛 분모에서 구분 |
| 선입금 보유 | 월말 잔여 선입금이 있는 세대 수. 납부완료와 겹칠 수 있으므로 도넛에 중복 합산하지 않음 |
| 통장별 잔액 | 상세와 동일한 공통 장부 우선 표시. 계산값 0원 포함, 계산 자료가 없으면 선택 월 이후가 아닌 마지막 확인값·출처·시점 사용. 미확인을 0원으로 대체하지 않음 |
| 최근 거래 | 선택 월 은행 원본·수동 지출과 미연결 수동 입금. 연결·취소 수동 입금 중복 제외. 날짜 내림차순·시각 내림차순·ID 오름차순의 최신 5건 |
| 6개월 추이 | 선택 월을 포함한 6개월의 청구액과 청구 납부반영액. 상단과 같은 계산을 사용하고 선입금 충당 포함 |

신규 청구 100만원에 기존 선납 5만원을 충당하면 상단 납부반영액은 5만원, 당월 청구 미수금은 95만원입니다. 다른 세대의 전월 미납을 당월 신규 청구 미수금에 더하지 않습니다. 누적 이월·미수 원장, 세대별 충당 순서·선입금 잔액은 변경하지 않습니다. 정산 미확정 청구는 납부·미수를 확인 필요로 유지하며 임의로 환급·정산하지 않습니다.

도넛은 청구 대상의 상태별 세대 수입니다. 정산 확인 필요가 있으면 완납 비율을 확정 표시하지 않습니다. 선입금만 보유한 미부과 세대를 자동으로 청구 대상에 포함하지 않습니다.

과거 월도 현재 유효한 원천으로 다시 계산하며 과거 마감 당시의 고정 보고서를 복원하지 않습니다. 취소·삭제·원본 연결은 기존 원천 규칙을 따릅니다. 신규 통계 테이블·Migration·회계·마감 처리는 추가하지 않았습니다.

## 현재 업무와 이동

현재 업무는 선택 월과 독립적으로 조회합니다. 확인 필요 입금·미분류 출금은 기존 처리 상태의 PENDING만 대상으로 하며 보류·취소·이체 연결 대기를 같은 건수에 섞지 않습니다. 중복 후보는 PENDING / ON_HOLD / CONFIRMED 미연결 수동 입금 또는 수동 지출이며 자동 삭제·자동 제외하지 않습니다.

Client는 입금 / 출금 탭과 확인 필요 상태를 명시한 링크, 중복 후보 전용 필터, 외부 미회수 필터로 연결합니다. 실제 거래일로 조회 기간을 잡으며 최솟값 연도를 임의로 표시하지 않습니다. 0건도 클릭 가능하고 해당 조건의 빈 목록으로 연결합니다. 항목별 건수는 겹칠 수 있으므로 상단 총합 배지는 제공하지 않습니다.

가입·정보 수정 요청은 실제 승인 관리로 연결합니다. 초대 발급 수·미연결 주민 명부를 신청 수로 세지 않으며 외부 관리자 승격 요청은 이 건수에 포함하지 않습니다.

## 일관성·오류·재조회

DashboardService는 현재 권한을 먼저 확인하고 원천 Service를 동일한 읽기 전용 REPEATABLE_READ 트랜잭션에서 호출합니다. 선택 월이 과거이면 현재 업무의 외부 미회수 조회만 현재 월로 추가 조회합니다. 현재 신청·초대 목록은 기존 영속 업무 기록이며 인증 토큰·코드 원문을 새로 조회하지 않습니다.

필수 원천 하나가 실패하면 임의의 0원·0건을 섞은 성공 응답을 반환하지 않습니다. 기존 `{code,message}`와 업무 예외 처리기를 사용합니다. 잘못된 UUID·월은 400, 현재 권한 거부는 403, 원천 선행 조건 오류는 기존 409, 저장소 장애는 기존 서버 오류로 처리합니다.

Client는 대상·월·기준일·조회시각·건수와 기존 원천 형식을 검증합니다. 잘못된 응답이나 실패는 빈 월과 구분하고 재시도는 조회만 실행합니다. 캐시는 계정·관리대상·월로 나누고 화면 재진입·창 복귀·1분 주기·업무 상세 닫기에서 다시 조회합니다. 원천 저장을 자동 반복하지 않습니다.
