# 월별 정산 API

상태: 2026-10-24 **구현**. 업무 범위는 [도메인 규칙](domainRules.md#확정된-월별-정산-범위), 화면은 [Client 월별 정산](../client/docs/monthlySettlement.md), 데이터 구조의 적용 범위는 [ERD](erd.md#12-월마감--통장대사)를 따릅니다.

## 조회 요청

`GET /api/properties/{propertyId}/closing/monthly?month=2026-10`

Bearer 인증과 해당 관리대상의 현재 `ADMIN` 권한을 요구합니다. `MANAGER`에게 기존 통장 API보다 넓은 권한을 제공하지 않습니다. 응답은 `Cache-Control: no-store`입니다.

| 입력 | 설명 |
| --- | --- |
| `propertyId` | 관리대상 UUID |
| `month` | 선택. `YYYY-MM` 형식, 연도 1000~9999, 월 01~12. 생략하면 서버 한국시간의 현재 월 |

통장·동 필터는 이번 API에 추가하지 않았습니다. 기존 월별 자료를 전체 범위로 조회합니다.

## 응답

| 필드 | 내용 |
| --- | --- |
| `propertyId` | 요청한 관리대상 ID |
| `month` | 실제 조회한 월 |
| `generatedAt` | 자료를 조회해 응답을 구성한 시각. ISO 8601 오프셋 일시이며 마감 확정일이 아님 |
| `banking` | [통장 Workspace](bankingManagement.md)의 기존 응답 구조. `rows`만 선택 월의 실제 거래로 제한 |
| `balances` | [동별 잔고 응답](bankingManagement.md#동별-잔고외부-회수-api)의 선택 월·전체 통장 조회 결과 |
| `payments` | [입금 관리 Workspace](paymentApi.md)의 누적 원장. 이월·선입금 계산을 위해 이전 월 자료도 유지 |

세 원천 조회는 동일한 읽기 스냅샷으로 묶습니다. 원천 중 하나가 실패하면 부분 응답을 반환하지 않습니다. 금액은 기존 계약대로 정수 문자열을 사용하고 Client 계산과 Excel·PDF에서도 정밀도를 보존합니다. 응답은 기존 Workspace 구조를 재사용하며 주민 연락처·계좌번호 원문을 새 필드로 추가하지 않습니다.

보고서의 수납·미납은 기존 월별 수납 화면의 조회 대상과 계산을 재사용합니다. 실제 입금과 청구 충당, 통장 출금 전액과 동별 부담액, 은행 확인 잔액과 동별 보유금은 별도 지표입니다. 화면·파일에 적용하는 표시와 점검은 [구현 범위](domainRules.md#월별-정산-조회-구현)를 참조합니다.

## 오류와 재조회

기존 업무 API의 오류 응답 `{code,message}`를 재사용합니다.

| 상태 | 주요 코드 | 처리 |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | 잘못된 월·UUID 등 입력 확인 |
| 401 | 기존 인증 오류 | 로그인·세션 복원 처리 |
| 403 | `ACCESS_DENIED`, `ACCOUNT_UNAVAILABLE` | 관리 권한·이용 가능 계정 확인 |
| 409 | `OPENING_BALANCE_REQUIRED` 등 기존 원천 업무 오류 | 관리 시작·원천 자료 확인 |
| 503 | `PAYMENT_SERVICE_UNAVAILABLE` | 저장소 장애 안내와 재시도 |
| 500 | 기존 공통 업무 오류 | 내부 오류 원문 없이 재시도 안내 |

Client는 관리대상·조회 월·자료형·금액을 기존 원천별 검증기로 확인하고, 잘못된 응답을 빈 월이나 0원으로 표시하지 않습니다. 이전 조회 성공 자료가 있어도 새 조회가 실패하면 다운로드를 막습니다.

## 다운로드와 변경 경계

Excel·PDF·이미지(PNG)와 다운로드 미리보기는 화면이 성공적으로 조회한 동일 응답의 `balances.entries`를 사용해 Client에서 생성하는 동별 입금·지출 내역입니다. 한 시트·PDF·이미지의 표시 범위와 정렬은 [Client 설계](../client/docs/monthlySettlement.md#excelpdf-자료-범위)를 따릅니다. 모달의 전체/개별 동·계좌 선택은 동일 스냅샷을 Client에서 제한하며 별도 API 필터는 추가하지 않습니다. 계좌 선택은 기존 월별 통장 표시 정책과 banking.accounts의 기간·사용 이력 메타데이터를 따릅니다. 동별 buildings.accountBalances는 기존 잔고 계산에서 얻은 통장별 기초·월말 잔액입니다. 별도 저장이나 Migration은 추가하지 않습니다. 신규 응답은 다운로드 중 원천 API를 다시 호출하지 않으며, 이 필드가 없는 기존 응답은 계좌 선택 시 기존 GET banking/balances?month&accountId로 해당 계좌 잔액을 확인합니다. 확인 완료 전에는 파일 생성을 막고 선택 범위가 복원된 결과는 사용하지 않습니다. 화면과 파일의 기준 자료는 같지만 다운로드 이후 원천 업무 변경으로 다음 조회 결과가 달라질 수 있습니다.

이번 API는 거래·수납·외부 정산의 상태를 변경하지 않고 마감 이력·확정 보고서를 저장하지 않습니다. 회계기간·전표·마감 테이블이나 새 Migration은 추가하지 않습니다. 별도 마감 확정·잠금·재오픈 API는 후속 범위입니다.
