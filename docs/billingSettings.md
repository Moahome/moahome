# 관리비 전체·동별 기본 부과와 다음 달 임시 부과

기준일: 2026-10-25. 기본 부과와 임시 부과의 전체·동별 선택, 조회·편집·저장과 자동 부과를 구현했습니다. 정책은 [도메인 규칙](domainRules.md#확정-정책-전체동별-부과와-다음-달-한정-변경-2026-10-25)을 따릅니다. 실제 검증 결과는 작업 완료 보고를 기준으로 합니다.

## 1. 두 부과 설정의 관계

기본 부과는 다음 달부터 매월 적용하고, 임시 부과는 항목별로 선택한 이번 달 또는 다음 달에만 추가합니다. **기본 부과와 임시 부과에서 각각 전체 부과 / 동별 부과를 독립적으로 선택합니다.** 기본이 전체여도 임시만 특정 동으로 지정할 수 있습니다.

| 기본 부과 | 임시 부과 | 사용 사례 |
| --- | --- | --- |
| 전체 | 없음 | 모든 동에 동일한 기본 관리비 반복 부과 |
| 동별 | 없음 | 각 동의 독립적인 항목·금액 반복 부과 |
| 전체 | 전체 | 동일한 기본 관리비에 다음 달만 모든 동의 점검비 추가 |
| 전체 | 동별 | 동일한 기본 관리비에 다음 달만 102동의 수선비 추가 |
| 동별 | 전체 | 동마다 다른 기본 관리비에 다음 달만 모든 동의 점검비 추가 |
| 동별 | 동별 | 동마다 다른 기본 관리비에 다음 달만 선택한 동의 수선비 추가 |

각 영역 안에서 전체와 동별을 동시에 선택하지 않습니다. 전체 공통 기본값에 동별 예외를 상속시키지 않으며, 기본·임시 두 영역의 적용 범위를 서로 제한하지 않습니다.

## 2. 102동 다음 달 수선비 예시

아래 기본 관리비는 설명용입니다. 2026년 10월에 설정합니다.

```text
기본 부과: 전체 부과 / 세대당 50,000원 / 다음 달부터 매월
임시 부과: 동별 부과 / 102동 / 수선비 세대당 100,000원 / 2026년 11월만
```

| 구분 | 101동 세대당 금액 | 102동 세대당 금액 | 103동 세대당 금액 |
| --- | ---: | ---: | ---: |
| 11월 기본 관리비 | 50,000원 | 50,000원 | 50,000원 |
| 11월 임시 수선비 | 없음 | 100,000원 | 없음 |
| 11월 합계 | 50,000원 | 150,000원 | 50,000원 |
| 12월 합계 | 50,000원 | 50,000원 | 50,000원 |

다른 반복 설정 변경이 없는 예시입니다. 102동의 부과 대상이 10세대이면 수선비 추가 합계는 1,000,000원입니다. 동 전체 100,000원을 세대로 나누지 않습니다. 공실에는 부과하지 않으며 대상 수가 바뀌어도 세대당 금액은 같습니다.

임시 부과가 끝나도 기본 부과는 전체 방식으로 유지됩니다. 이후에는 그 월에 유효한 반복 설정을 사용하며 이전 금액을 복원하는 별도 저장을 요구하지 않습니다.

## 3. 조회와 편집 구성

현재 적용 중인 설정과 다음 달 적용 예정 설정을 구분합니다. 조회에서는 항목별 적용 현황·금액 범위와 동별 금액을 확인하고, 편집에서는 기본·임시 설정을 각각 조작합니다. 동별 항목의 `모든 동 동일 / 동별 금액 다름`은 조회 결과를 요약하는 문구이며 추가 부과 방식이 아닙니다.

임시 부과에는 각 항목의 적용월 드롭다운에서 이번 달 / 다음 달을 선택하고 대상·항목 종류·세대당 추가 금액·비고를 입력합니다. 기본과 임시는 같은 종류 선택 UI를 사용하고 기타 선택 시에만 항목명을 입력합니다. PC에서도 적용월·대상, 항목·금액, 비고를 여러 줄로 나눕니다. 다음 달 외의 미래 월 달력 선택을 제공하지 않습니다. 다음 달 기본+임시의 세대당 합계와 이번 달에 추가될 금액을 별도 미리보기로 확인합니다.

아코디언, 동 검색·개별 펼침, 방식 전환 시 편집 초기값 복사와 반응형 배치는 구현 설계입니다. 정책의 원본은 위 도메인 규칙이며 상세 화면·입력 상태는 [Client 관리비 설계](../client/docs/managementLayout.md#관리비-부과-2026-10-10)를 참조합니다.

## 4. 수정과 기존 부과 흐름

- 같은 동·월·항목의 예정 내용을 다시 편집하면 기존 예정 설정의 수정입니다. 마지막 저장 내용을 적용하고 변경 버전·사유·수정자를 보존합니다.
- 실제 청구는 기존처럼 매월 1일 자동 생성·확정하고 월말을 납부기한으로 둡니다. 공실 제외·당월 보충·수납 한도 정책을 유지합니다.
- 저장된 임시 항목은 해당 버전의 적용 시작월에만 부과하며 그다음 월의 예정 조회와 실제 생성에서 모두 제외합니다.
- 변경된 기본·임시 설정으로 기존 당월·과거 청구를 다시 계산하지 않습니다. 이번 달 임시 항목은 별도 추가 청구로 기록하고 월별 조회에서 세대별로 합쳐 표시합니다.
- 0원·음수 허용과 수정 사유 필수는 유지하며, 기본 합계와 기본+임시 합계의 금액 범위를 동별로 검증합니다.

## 이번 달 긴급 수선비

각 임시 항목의 적용월에서 이번 달을 선택합니다. 위쪽에 별도의 월 선택 Radio를 두지 않습니다. 이번 달과 다음 달 항목을 함께 작성할 수 있으며, 저장 버튼은 이번 달 항목이 있으면 `이번 달 추가 부과`, 없으면 `다음 달 예약 저장`입니다. 기본 변경은 항상 다음 달부터 적용된다는 설명을 함께 표시합니다.

기본 청구 50,000원을 이미 납부한 세대에 이번 달 수선비 100,000원을 추가하면 기존 청구·납부 50,000원을 유지하고 별도 청구 100,000원을 발행합니다. 선납이 없는 경우 남은 납부액은 100,000원입니다. 납부기한은 이번 달 말일이며, 현재월 항목을 다음 달 예약에 섞지 않습니다. 처리자·사유·원본 항목·요청 ID를 보존하고 응답 유실 재시도에도 추가 부과는 한 번만 생성합니다.

기존 템플릿·항목 ID와 확정 청구를 유지하고 후속 Migration으로 범위·대상 동·임시 여부·비고를 추가합니다. 임시 항목도 원본 템플릿 항목으로 보존해 실제 청구에서 적용 근거를 추적합니다. 개발·운영 DB의 적용 여부는 코드 작성과 별개이며 일회성 DB에서 Migration을 검증합니다.

세대별 개별 예외, 동 전체 총액 분담, 여러 달 기간 지정과 다음 달 외 미래 월 예약은 이번 범위에 없습니다. 확정 청구 정정·재발행과 음수 청구 환급·정산의 기존 후속 정책도 별개입니다.

동별 반복 부과 중 새 동에 기본 설정이 없는 경우 서버는 임의의 금액·빈 청구를 생성하지 않고 설정 없음 오류를 반환합니다. 새 동 등록과 초기 기본 설정을 함께 받는 흐름은 후속 보완 범위입니다.
