# 초기 설정 주민 명부 등록과 전화번호 동의

수정일: 2026-11-06. 상태: **사용자 확정 사항을 로컬 코드·Migration에 구현 / 운영 DB·운영 서버에는 미적용**. 이 문서는 요청 범위와 구현 연결을 정리합니다. 업무 규칙은 [도메인 규칙](../domain/domainRules.md), 저장 구조는 [ERD](../domain/erd.md), 요청·응답은 각 API 계약을 기준으로 합니다.

## 1. 확정 범위

- 동·세대 및 담당자 다음에 주민 단계를 추가해 여섯 단계로 진행합니다.
- 주민 없이 건너뛰는 동작은 제공하지 않습니다. 유효한 거주 관리소장을 포함해 최소 한 명을 준비합니다.
- 거주 관리소장과 세대·이름이 같은 추가 행은 제외합니다. 번호·주민 구분을 자동 병합하지 않습니다.
- 같은 탭의 새로고침에는 주민 초안도 복원하고 취소·이탈·로그아웃·계정 변경에는 폐기합니다.
- 전화번호 보유 기간은 `주민 명부 삭제 또는 동의 철회 시까지`입니다.
- 사용자가 기존 운영 번호의 사전 동의 완료를 확인했습니다. 동의 필드 도입을 이유로 이 번호들에 일괄 재동의를 요구하지 않습니다.
- 삭제한 명부는 직접 선택해 기존 ID·이력을 복구할 수 있습니다. 파기한 번호와 종료된 서비스 권한은 자동 복구하지 않습니다.

정책의 세부 예외는 [초기 주민 단계](../domain/domainRules.md#초기-설정-주민-명부-단계-추가-2026-11-06), [주민 수정](../domain/domainRules.md#확정된-주민-상세수정삭제), [주민 등록](../domain/domainRules.md#확정된-주민-개별-등록)을 따릅니다.

## 2. 단계와 최종 저장

```text
기본 정보 → 동·세대 및 담당자 → 주민 명부 등록 → 관리계좌 및 잔고 → 관리비 설정 → 최종 확인
```

직접 입력과 엑셀은 같은 주민 초안을 편집합니다. 개별 저장이나 업로드 검증에서 명부를 DB에 저장하지 않습니다. 최종 제출의 주민 배열과 담당자 입력을 기존 등록 트랜잭션·재시도 지문에 함께 반영합니다. 새 등록은 주민 배열을 제출해야 하며, 이전 형식으로 이미 성공한 요청은 기존 결과 재조회·재시도를 지원합니다.

공유 계약은 [관리대상 등록 API](../api/propertyRegistrationApi.md), 내부 원자성·HMAC 처리는 [Server 등록](../../server/docs/propertyRegistration.md)을 참조합니다.

## 3. 화면 구현

주민 목록 상단의 추가 버튼에서 공통 모달을 엽니다. 입력은 두 열이며 동 없음은 호수·이름 / 주민 구분·전화번호로 배치합니다. 동의 체크박스는 입력 아래 한 줄입니다. 수정은 초록 연필, 삭제는 쓰레기통 아이콘을 사용합니다. 거주 관리소장도 같은 목록에 표시하며 수정은 이전 담당자 단계로 이동합니다.

페이지 번호는 최대 다섯 개씩 표시하고 화살표로 다섯 페이지 묶음을 이동합니다. 표시 개수 선택은 유지하되 눈에 보이는 `표시 개수` 라벨은 제거했습니다. 엑셀 작성 안내는 운영 주민 업로드와 공통 UI를 사용하며 동 없는 대상에는 호수 기준 설명을 제공합니다. 양식 다운로드는 업로드 영역 아래 가로 전체 너비로 표시합니다.

[Client 등록 설계](../../client/docs/propertyRegistration.md)에 초안 수명·상태 전이·화면 배치를 관리합니다. 개발 전용 `/preview/registration`은 실제 주민 단계 컴포넌트를 표시하며 최종 등록 API를 호출하지 않습니다. 프로덕션에서는 접근할 수 없습니다.

## 4. 엑셀과 명부 복구

초기 설정 미리보기는 저장 전 세대 초안으로 검증합니다. 운영 주민 업로드는 이미 저장된 세대를 대상으로 하므로 경로·임시 보관 방식을 구분합니다. 두 방식 모두 동 유무별 기존 양식과 O/X 동의 판정을 사용합니다. O가 아닌 번호는 보호값·검색값·응답에 남기지 않습니다.

명부 삭제 시 번호가 파기되므로 과거 이름·번호의 일치로 삭제 명부를 자동 선택하지 않습니다. 삭제 명부 직접 선택은 개별 주민 등록의 복구 모드에서 수행하고, 일반 신규·엑셀 등록은 새 기록을 만듭니다. 상세 계약은 [주민 API](../api/residentManagementApi.md), 구현은 [Client 주민 목록](../../client/docs/residentList.md)과 [Server 주민 등록](../../server/docs/residentRegistration.md)을 참조합니다.

## 5. 전화번호 동의와 번호 변경

사용자 후속 정정에 따라 **이미 동의한 동일 주민의 번호 정정에는 동의를 다시 요구하지 않습니다.** 화면과 서버가 현재 동의 상태를 확인하고 기존 출처·기록자·기록 시각·고지 버전을 유지합니다. 최초 번호 수집·동의 미확인·철회 후 재입력만 동의를 확인합니다. 개인 초대의 번호 정정에도 같은 기준을 적용합니다.

관리소장 자기 번호와 가입 신청은 본인 동의 문구, 관리자의 주민 입력은 사전 동의를 받았다는 확인 문구를 사용합니다. 체크박스 옆 도움말 아이콘·팝업은 제거했습니다. 업무 기준을 [주민 수정 정책](../domain/domainRules.md#확정된-주민-상세수정삭제)에 모으며 API의 bool 입력과 DB 동의 기록을 구분합니다.

## 6. 동의 기록·기존 번호 이관

`PhoneConsent`를 주민·가입 신청·개인 초대에 함께 저장합니다. 신규 확인은 SELF / ADMIN / EXCEL 출처, 처리자·시각·고지 버전을 기록합니다. 기존 동의 이관은 LEGACY_IMPORT와 이관 시각으로 구분하고 과거 실제 동의일을 만들어 넣지 않습니다. 번호 없는 행의 동의 기본값은 false입니다.

추가한 Migration은 다음과 같으며 실제 운영 적용은 아직 하지 않았습니다.

- `V20261106131944__record_phone_collection_consent.sql`: 동의 컬럼과 제약 추가, 번호가 있는 기존 저장 행의 동의 완료 이관
- `V20261106132607__purge_deleted_resident_phone_copies.sql`: 이미 삭제된 명부와 확인 연결된 번호 사본 파기, 해당 관리대상 엑셀 임시 검증 폐기

배포 전 점검·실행 순서는 [운영 배포 규칙](../operations/deploymentRules.md)을 따릅니다. 로컬 구현·격리 DB 검사와 실제 운영 적용을 혼동하지 않습니다.
