# 계정과목 설정 저장과 동시성

2026-11-07 구현. [정책](../../docs/domain/domainRules.md#계정과목-설정의-변경사용-중지삭제-2026-11-07-사용자-확정), [ERD](../../docs/domain/erd.md#계정과목-설정-저장-2026-11-07), [API](../../docs/api/accountingAccountsApi.md)를 기준으로 합니다. 정식 전표·마감 구현을 포함하지 않습니다.

`AccountingAccountSettingsService`는 조회 권한을 먼저 검사하고 조회에서 DB를 쓰지 않습니다. 변경은 ADMIN 검사 → 관리대상 행 잠금 → 역할 재검사 → 필요한 기본 과목 저장 → 기존 자동 분류 고정 → 현재 revision·참조·중복 검증 → Entity 상태 변경 순서로 처리합니다. 과목 설정은 부과·회계 프로필 생성과 분리합니다.

기본 여부는 코드 문자열을 업무 키로 사용하지 않고 `default_account`에 보존합니다. 기본 과목은 변경·삭제를 보호하고 비용만 사용 상태 변경을 허용합니다. 추가 과목의 사용 여부는 취소·삭제된 원천도 포함합니다. 계정 ID와 원천 금액은 바꾸지 않으며 이미 사용한 코드를 다른 성격의 과목으로 변경하지 않습니다.

이름·코드 자동 매칭만 있던 지출은 최초 설정 변경 전에 `accounting_expense_account_links`에 ID를 고정합니다. 미분류 NULL도 고정하여 이후 과목 추가·이름 변경으로 과거 미분류가 자동 이동하지 않게 합니다. 신규 지출은 기존 등록 트랜잭션에서 같은 연결을 저장합니다. 최신 명시적 회계 정정 → 최초 명시 선택 → 고정 자동 분류 → 아직 고정하지 않은 과거 원천의 기존 매칭 순서로 조회합니다. 은행 응답의 `expense.accountResolved`는 이미 해석한 미분류를 손익에서 재추측하지 않도록 하는 호환 필드입니다.

중지 과목은 신규 선택에서 제외하지만 과거 연결·손익·원장에는 유지합니다. 기본 비용 목록을 매번 보충하는 경로도 저장된 중지 상태를 우선합니다. 기존 미지급의 후속 지급은 기존 계정 연결이므로 사용 중지와 무관하게 기존 원천 검증을 유지합니다. 새 미지급 발생만 활성 과목을 요구합니다.

`V20261107094145`는 기존 ID를 유지한 컬럼 추가·기본 여부 보정·최초 이력 저장 후 제한된 UPDATE 트리거를 설치합니다. 계정의 물리 삭제와 두 이력 테이블의 UPDATE/DELETE를 막습니다. 신규 업무 연결은 관리대상 잠금을 공유하여 중지·삭제와 경합하지 않게 합니다. 실패하면 원천 분류 고정과 계정 변경 모두 롤백합니다.

Migration 사전 점검은 전체 선행 이력과 새 버전의 순서·기본 과목 보정·기존 참조·잠금 시간을 확인합니다. 빈 PostgreSQL 전체 적용과 기존 스키마에서의 업그레이드는 격리 DB로 검증합니다. 실제 운영 이력 확인·백업·배포는 [운영 배포 규칙](../../docs/operations/deploymentRules.md)의 별도 절차이며 로컬 검사 통과로 운영 적용을 보고하지 않습니다. 복구 시 변경한 표시 정보는 새 정상 변경으로 보정하고 이미 공유한 Migration을 되돌려 편집하지 않습니다.

정책·권한·revision 검사는 `AccountingAccountSettingsServiceTest`, 기존 원천 보존·사용 중지 신규 연결 거부·이력 불변성·업그레이드는 `AccountingAccountSettingsPersistenceTest`에서 확인합니다.
