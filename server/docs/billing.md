# 관리비 저장과 자동 부과

상태: 실제 API·설정 버전·월별 청구 생성과 자동 확정 구현. 정책은 [도메인 규칙](../../docs/domainRules.md#5-관리비-부과--청구), 요청 / 응답 / 오류는 [관리비 API](../../docs/billingApi.md), 컬럼·제약은 [ERD](../../docs/erd.md#7-관리비-부과)를 기준으로 합니다.

## 설정 변경

BillingService는 매 요청 ManagementAccessService로 현재 권한을 확인합니다. 저장 시 세대 관리와 같은 Property 행의 비관적 잠금을 획득한 뒤 최신 revisionId와 서버 기준 다음 달을 검증합니다. 성공하면 기존 템플릿·항목을 변경하지 않고 증가한 revision의 템플릿과 항목을 함께 추가합니다. 사유·변경자·적용월을 보존합니다. 합계는 BigDecimal로 계산하고 numeric(15,0) 범위를 검증합니다.

BillingTemplates는 적용월 이하의 ACTIVE 기본 템플릿 중 최신 revision을 선택합니다. 최초 템플릿의 effective_from과 첫 부과월은 등록한 한국시간 월을 기준으로 합니다. 기존 NULL 날짜는 Migration에서 같은 기준으로 보정합니다. 적용 시작 날짜 추가는 기존 데이터 전체를 UPDATE하므로 배포 전 레코드 수·잠금 시간을 확인합니다. 이전 Migration과 등록 결과 스냅샷은 변경하지 않습니다.

## 실행과 원자성

PropertyRegistrationService는 기본 설정·세대·권한 저장 직후 BillingGenerationService를 호출해 등록월 청구를 바로 생성·확정합니다. 기본 REQUIRED 전파로 등록 트랜잭션에 참여하며 첫 청구 저장이 실패하면 초기 등록·성공 결과도 함께 롤백합니다. 같은 등록 요청의 재시도는 기존 성공 결과를 반환하고 첫 청구를 다시 만들지 않습니다.

BillingScheduler는 Asia/Seoul의 매시 정각(매월 1일 00시 포함)과 ApplicationReadyEvent에서 실행합니다. 활성 관리대상의 첫 부과월부터 현재 월까지 누락을 확인하므로 일시 장애·서버 중단 후 복구합니다. 이전 구현에서 등록월 청구가 없던 기존 대상도 등록월부터 복구하고 이미 확정된 청구는 보존합니다. `moahome.billing.scheduler-enabled=false`로 자동 실행을 끌 수 있습니다. 이 값은 테스트용 속성으로도 사용합니다.

반복 부과의 각 월·관리대상은 별도 BillingGenerationService 트랜잭션입니다. Property 행 잠금으로 여러 서버·재시도와 세대 / 설정 변경을 직렬화합니다. 이미 ISSUED인 기간은 재생성하지 않습니다. 기간 → 청구·항목 스냅샷 → 자동 확정을 하나의 트랜잭션으로 저장하므로 중간 실패 시 모두 롤백합니다. DB의 관리대상·월 UNIQUE와 기간·세대 UNIQUE도 중복을 차단합니다.

실패한 관리대상은 그 달에서 멈추고 다른 관리대상 처리는 계속합니다. 다음 정각이나 재시작에 다시 시도합니다. 로그에는 대상 UUID·월·예외 종류만 기록하며 SQL·개인정보 원문은 기록하지 않습니다. 복구 시점의 현재 세대 목록과 해당 월 적용 템플릿을 사용합니다. 세대별 과거 소속 시점 복원과 수동 초안은 이번 기능에 없습니다.

## 스냅샷과 조회

Charge는 동명·호수·별칭·총액·기한을, ChargeItem은 원본 항목 ID·코드·명칭·금액·순서·계정 연결 값을 보존합니다. 이후 세대 정정 / 삭제나 기본 설정 변경으로 확정 청구를 다시 계산하지 않습니다. 시스템 확정은 기간의 confirmation_source=SCHEDULE로 식별하고 시각을 보존합니다.

실제 기간이 없는 현재·미래 조회는 예정값만 계산하며 GET에서 저장하지 않습니다. 과거 조회에 가상 청구를 생성하지 않습니다. 조회·이력 금액은 BigDecimal 계산 후 문자열로 반환합니다. 수납·환급·전표 생성은 이 트랜잭션에 포함하지 않습니다.

대표 주민 이름은 ResidentListService의 현재 명부 조회를 한 번 재사용해 세대별로 연결합니다. 기존 세대 목록처럼 ADMIN에게만 제공하고 MANAGER에게는 이름을 반환하지 않습니다. 청구 스냅샷에 이름을 추가하거나 금액을 다시 계산하지 않으므로 대표 변경·삭제와 청구 금액 보존은 독립적입니다. 응답 계약은 [관리비 API](../../docs/billingApi.md#월별-응답)를 따릅니다.

## 검증

`./gradlew build`에 아래 검증을 포함합니다.

- BillingDomainTest: 윤년·한국시간 경계, 0원·음수·금액 범위, 상태 전이와 잘못된 입력의 상태 보존.
- BillingControllerTest: 인증·범위 전달·필수 사유·중첩 항목 검증·고정 오류 응답.
- BillingPersistenceTest: 일회성 PostgreSQL에서 최초 부과월, 사용 중 / 공실 대상, 버전·사유 보존, 충돌, 청구 스냅샷, 동시 실행·전체 롤백·재시도·다른 관리대상 FK 차단.
- 기존 등록·주민·사용자 PostgreSQL 테스트: 빈 DB 전체 Migration과 이전 스키마 업그레이드 / 기존 ID 보존.

테스트 인프라 실행 경로와 분리는 [Server AGENTS.md](../AGENTS.md#16-test--build)를 따릅니다. 개발 / 운영 DB에 테스트를 실행하지 않습니다.
