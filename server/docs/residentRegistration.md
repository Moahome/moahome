# Server 주민 등록

개별 등록 API를 구현했습니다. 업무 정책·입력·응답·오류는 [주민 관리 API](../../docs/residentManagementApi.md#주민-등록)와 [도메인 규칙](../../docs/domainRules.md#확정된-개별-주민-등록)을 참조합니다.

## 저장 순서

`ResidentRegistrationService.register`의 단일 트랜잭션에서 현재 관리소장을 확인하고 `PropertyRepository.findForUnitUpdate`로 관리대상 행을 잠급니다. 세대 추가·수정·삭제와 같은 잠금을 공유해 삭제와 주민 연결이 교차하지 않도록 합니다. 첫 잠금 획득 후 저장이 성공한 요청이 최초 등록입니다. 실패하면 잠금과 변경을 롤백하므로 다음 요청이 최초 등록이 될 수 있습니다.

같은 대상의 실제 세대·동을 검증하고 연락처가 있으면 암호화·HMAC·끝 네 자리를 만듭니다. 요청 ID의 기존 결과 확인, 이름·연락처 중복 검사, 해당 세대의 전체 관계 이력 조회 후 주민과 현재 관계를 함께 저장합니다. 과거·삭제 관계가 있는 세대의 대표 부재를 자동 승계로 처리하지 않습니다.

요청 ID는 신규 주민의 PK로 사용합니다. 같은 대상·정규화된 이름·연락처 HMAC·현재 세대·관계가 모두 같으면 기존 결과를 반환합니다. 기존 주민·관계가 삭제·변경되었거나 다른 대상이면 고정 충돌 오류를 반환하며 기존 정보를 덮어쓰지 않습니다. `Resident`의 신규 저장은 `Persistable.isNew`로 `persist`를 선택하므로 서로 다른 대상의 동일 ID가 경합해도 `merge`로 기존 주민을 수정하지 않습니다.

현재 주민 삭제·명시적 복구 API가 없어 재등록은 구현하지 않았습니다. 삭제 기록과 일치하는 새 입력은 충돌 안내로 중단하며 원래 ID 유지 정책을 신규 생성으로 우회하지 않습니다. 연락처 없는 주민의 동일 인물 판정은 이름만으로 수행하지 않습니다.

## 연락처 보안

공통 `PhoneSecurity`를 사용하며 외부 설정은 [개발 환경 가이드](../../docs/developmentGuide.md#server-환경변수)를 따릅니다. Bean을 지연 생성해 기존 로그인·조회와 연락처 없는 등록을 키 준비와 분리합니다. 연락처 포함 저장에서 키 생성이 실패하면 업무 오류로 바꾸며 평문·임의 생성 키로 대체하지 않습니다. 등록 DTO와 암호화 중간값의 `toString`도 원문을 숨깁니다.

## 검증

`ResidentRegistrationControllerTest`에서 인증·입력·개인정보 없는 응답·오류를 검증합니다. 기존 `ResidentDirectoryPersistenceTest`에 실제 PostgreSQL 등록·연락처 암호화·선택 입력·중복·요청 재시도·권한·소속·롤백·동시 대표 지정 검증을 추가했습니다. 변경 스키마는 없고 기존 Migration을 사용합니다.
